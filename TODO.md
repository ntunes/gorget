- **SECURITY: `Dict[K, Callable].get().unwrap().clone()` double-frees the closure env** (surfaced 2026-04-28 right after landing the deep-clone fix). `Dict.get()` returns `Option[V]` (by value), unlike `Vector.get()` which returns `Option[Ref[V]]`. - **C codegen: nested-struct drop emits `memcmp` against the parent struct's size, not the field's** — surfaced 2026-04-27 building gorget-arena. The C backend emits a "skip drop if value is zero" guard like `{ char __dia_z[N] = {0}; if (memcmp(&parent->field, __dia_z, N) != 0) { Type__drop(&parent->field); } }`. `N` is set to `sizeof(parent_struct)` (e.g. 296 bytes for `ShaderDef`), but `&parent->field` only has the field's own size behind it (e.g. 104 bytes for `DeformType`). gcc flags this as `-Wstringop-overread`. In practice the read stays inside the parent struct's allocation so it's not a hard UB (memory is valid), but the comparison may report "non-zero" for unrelated trailing fields and trigger spurious drop calls — which is unsound for non-idempotent drops. Fixture: `cd target/gorget-arena && gg build src/main.gg` produces 18 such warnings across 3 struct shapes (104/224/296). Fix: use `sizeof(field_type)` not `sizeof(parent_type)` when emitting the drop guard. [added: 2026-04-27]

- **Field-level borrow disjointness for the CoW-borrow checker** (surfaced 2026-04-30 auditing gorget-arena warnings). The CoW-borrow analysis in `src/semantic/safety/check_expr.rs` (the `index_borrow_sources` map at line 338-358) tracks borrows at the *receiver* level: `auto sd = gpu.shader_cache.get(i)` registers `sd` as borrowing from `gpu`, and any subsequent mutation of `gpu` triggers a clone — even when the mutation hits a *disjoint sibling field* like `gpu.deform_face_indices.push(fi)` or `gpu.stage_tex_names.push(name)`. The clone is *correct* (preserves safety) but unnecessary in this pattern, and arena's `load_stage_textures` (`backend.gg:421-438`) does it in a hot map-load loop where `sd` is a ~296-byte ShaderDef, with 4 clone sites per stage × N stages × N shaders → thousands of unnecessary clones per BSP load. Fix: when registering an `index_borrow_source`, record both the receiver `def_id` AND the field path that was projected (e.g. `gpu` + field `shader_cache`). At the mutation site, only invalidate borrows whose recorded field path is a prefix of (or equal to) the mutated field's path. `gpu.shader_cache.get` produces a borrow from `gpu.shader_cache`; `gpu.deform_face_indices.push` mutates `gpu.deform_face_indices` — disjoint paths, no clone needed. Pattern is common ("borrow from one collection-field, mutate a sibling") so the win is broader than just arena. Five warnings in arena's startup-time `load_stage_textures` would disappear; the user workaround (snapshot all stages into an intermediate Vector) allocates more than the clones save and doesn't read naturally. [added: 2026-04-30]

- **Borrow checker doesn't model `gorget_closure_clone_to_owned` as ownership-producing** (surfaced 2026-04-28 landing the Callable deep-clone fix). But Pass-5a's borrow-deps tracking still flags `return f` with `cannot return f: borrows from local variable vec which will be dropped`.
