# PASSING ALLOWLIST — `#[ignore]`d known_gaps tests that PASS at HEAD
#
# The durable-repro contract (AGENTS.md "Task Continuity") says a filed bug gets
# a `known_gaps/` fixture plus an `#[ignore]`d test asserting the INTENDED
# behaviour, GRADUATED the round the bug is fixed. Nothing in the suite ever
# runs an ignored test, so the second half was prose — and prose rots. The
# executable half is `scripts/known_gaps_census.sh` (wired into CI as the
# "known_gaps graduation census" step); this file is its committed baseline.
#
# A row here says: "this ignored test PASSES today, and here is why that is NOT
# a graduation." Every row carries a REASON CODE and the evidence for it.
#
#   CELL-BLIND       the assertion is on the RIGHT lane, but THIS CELL's output
#                    is insensitive to the defect, so it cannot go red however
#                    broken the compiler is. Not fixable by rewiring — the row
#                    must name the SIBLING cells that DO pin the class, and the
#                    header must say why this one cannot (Core #12: a fixture
#                    green for a reason unrelated to what it claims to test).
#   BLIND-PERF       the filed gap is a clone/allocation pathology and the body
#                    asserts only stdout, which the pathology does not change.
#                    Fix: assert a clone-stats floor (`gg build --clones=stats`
#                    → the `[clone-stats] array_clone=N` line the binary prints
#                    at exit), then the test can go red.
#   PINS-TODAY       the test asserts CURRENT behaviour while the open item is a
#                    DESIGN question. Neither graduate nor rewire until the
#                    semantics are ratified — it is an owner ask.
#
# ⚠ SHRINK-ONLY and EXACT, enforced by `known_gaps_passing_allowlist_shrink_only`
# in tests/lints.rs (`assert_eq!` on the row count, so a row cannot be swapped
# for another silently) and by `known_gaps_census.sh --check` (set equality
# against the measured PASS set, so neither a new passer nor a stale row slips
# through). Removing a row is the normal outcome — the test graduated, or its
# assertion was rewired so it goes red again. ADDING one means an ignored test
# silently started passing and nobody adjudicated it. A row is NEVER a place to
# park a graduation you did not do.
#
# ⚠ A PASS IS NOT A VERDICT. Telling a blind cell from a real graduation needs
# the MECHANISM, not the exit code — probe the axis the filing names and break
# the cited fix site to watch the test go red (Core #13). Every row below was
# adjudicated that way; the evidence is in the comment.
#
