# SANITIZE CORPUS MANIFEST — which fixture directories the sweep walks.
#
# WHAT THIS REPLACES, and why. `scripts/sanitize_sweep.sh` used to enumerate its
# corpus with `find tests/fixtures -maxdepth 1 -name '*.gg'`. That depth limit
# was DELIBERATE and load-bearing — the gate's own positive controls live in
# `sanitize_selftest/`, one leaks BY DESIGN, and a naive recursive walk ingests
# them as findings and destroys the Core #13 self-test — but it was an ACCIDENT
# OF DEPTH, not a decision. Nothing recorded WHY each directory was unwatched,
# and a new directory joined the unwatched set silently.
#
# This file is that decision, written down. Every first-level directory under
# `tests/fixtures/` carries exactly one row: `IN` (walked recursively, its
# `*.gg` join the corpus) or `OUT` plus the reason it is not swept.
# `sanitize_corpus_manifest_is_declared` (tests/lints.rs) set-equals this census
# against disk, so a NEW directory with no row REDS the cheap lint on the next
# commit, and the sweep itself refuses to report a verdict against an incomplete
# manifest (exit 2 — the instrument is broken, not the tree).
#
# ⛔ DECLARE, DO NOT RELOCATE. The owner offered "move them under /skip" as one
# option; a manifest is better precisely because moving files changes paths and
# breaks citations in `todo/` items, fixture headers and tests.
#
# FORMAT:  <directory> TAB IN|OUT TAB <reason, and what would change it>
# A reason naming a `todo/` item must name one that EXISTS — the lint checks it,
# so a deferral cannot rot into a dangling pointer.
#
# THE POPULATION IS WHAT GIT SEES, NOT WHAT A DISK WALK SEES — and this file
# shipped with the disk walk, which was WRONG in the worst direction a guard can
# be wrong. `tests/fixtures/.gorget/` is a directory of `*.test-results.json`
# files that RUNNING THE FIXTURE SUITE creates, so the census matched in a fresh
# checkout and drifted on every machine that had actually done work. A guard
# green where nothing has happened and red where work does is worse than none.
#
# The census is therefore the directories git considers part of this tree:
#
#   git ls-files --cached --others --exclude-standard tests/fixtures \
#     | awk -F/ 'NF>3 {print $3}' | sort -u | wc -l          # -> 69
#
# `--cached --others --exclude-standard` = TRACKED plus UNTRACKED-BUT-NOT-IGNORED,
# so a directory counts iff it holds at least one file git would consider part of
# this tree. `.gorget` contributes none and vanishes; a STRAY directory of real
# `.gg` fixtures that nobody has `git add`ed still counts, and still reds — which
# is the whole point, and is why tracked-ness alone would have been the wrong fix.
# ⚠ `git check-ignore` would NOT have worked, measured: line 19 of
# `tests/fixtures/.gitignore` is `!*/`, which UN-IGNORES every directory so the
# file rules can match inside them, so `.gorget` the DIRECTORY is not ignored even
# though every file in it is. `scripts/sanitize_sweep.sh` and
# `sanitize_corpus_manifest_is_declared` both run the command above, and the lint
# parses the sweep's spelling of it from SOURCE so the two cannot drift apart.
#
# NO RECURSIVE COUNT IS PRINTED HERE, DELIBERATELY. It was `84 (15 nested)`, and
# it was measured with a bare `find` on a machine that had never run the suite;
# a naive walk now answers 85/15 and git's population answers 83/14. A number
# whose value depends on whether you have run the tests cannot be maintained in
# prose — the same lesson `tests/sanitize/LEAK_ALLOWLIST.txt`'s big-groups table
# records. Run this instead:
#
#   find tests/fixtures -mindepth 1 -type d | wc -l          # incl. artefacts
#
# ⚠ And note the two answers differ for a SECOND reason worth knowing: git's
# population is derived from FILE paths, so an intermediate directory holding
# only other directories (`known_gaps/manifest_malformed/`, whose four tracked
# files live one level deeper) never appears in it. That does not affect this
# manifest, which declares the FIRST level only — but do not use the git command
# above as a general recursive directory census.
#
# The manifest declares the FIRST level; an `IN` directory is walked recursively,
# so a nested directory inherits its parent's row and cannot join the corpus on
# its own.
#
# ⚠ EVERY ROW IS `OUT` TODAY, AND THE WALK IS THEREFORE BYTE-IDENTICAL TO THE
# `-maxdepth 1` IT REPLACES. That is the intended landing state, not an
# oversight: the deliverable is DECLARED, EVIDENCED and CITED membership, and a
# corpus expansion is a separate act with its own measurements and, for
# `security/`, its own owner ruling (`todo/t0956`). `COVERAGE_FLOOR` therefore
# stays where it was — see the note on it in `scripts/sanitize_sweep.sh`.
#
# ⚠ AN `OUT` ROW IS NOT A CLAIM THAT THE DIRECTORY CANNOT LEAK. Read each
# reason: some are STRUCTURAL and permanent (no binary is ever produced, there
# is no standalone program, the directory holds the gate's own controls), and
# some are DEFERRALS of a real corpus candidate, each citing the item that owns
# the work. Flipping a deferred row to `IN` is a future round's job — it will
# surface findings that already exist and are merely unseen, and the count going
# UP before it goes down is the correct outcome.
#
