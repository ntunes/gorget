# `spectests/` — the Gorget conformance suite

The third leg of the Define-Gorget triad (RFC §1): **spec prose** (`spec/prose/`)
+ **`ggdef`** (the definitional interpreter) + **`spectests/`** (this suite, that
every implementation runs). Expectations **flow FROM the definition** — they are
`ggdef`-generated and human-review-diffed, never copied off whichever backend
came first (RFC §4; decisions.md ARCHITECTURE DIRECTION).

> **Phase-0 status:** this is the *skeleton* laid down by Increment C. The
> directory layout (below), the frontmatter schema, the `ggdef -- gen`
> generator, and a handful of seed fixtures in `run/` exist. The bulk migration
> of the ~1,218 literal harness expectation pairs into frontmatter fixtures is
> **phase 1** (RFC §6) — nothing is moved yet.

## Layout (RFC §3)

```
spectests/
  run/            # mode: run — execute; compare stdout + exit code
  static-error/   # mode: static-error — expect a typecheck/elaboration diagnostic
  parse-error/    # mode: parse-error — expect a parser diagnostic
  annexe/         # D1 copy-guarantees: MUST-NOT-ALLOCATE positions, clone/alloc-counted
  staging/        # low-bar tier — NOT gated (incubator for not-yet-ratified fixtures)
```

Increment C seeds `run/` only (the two smith repros, the EMove witness, and two
core-CoW showcases). The other tiers are laid out empty (each has a `README.md`
describing what it will hold) so the structure is pinned from day one.

## Frontmatter schema (RFC §4)

Every fixture is an ordinary `.gg` program that ALSO carries a frontmatter block
in leading `#` comments — invisible to the lexer, so `ggdef run` / `trace` /
`gen` and any implementation's runner all parse the program unchanged. The block
is fenced by `#!spectest` … `#!end`:

```
#!spectest
# mode: run                 # run | static-error | parse-error
# adjudicator: ggdef        # ggdef | production-v1 | prose
# since: spec-v0.1          # spec version the fixture entered at
# features: [cow, move]     # optional tag list (informational in phase 0)
# args: ["--flag"]          # optional argv (phase 1)
# stdin: "..."              # optional program stdin (phase 1)
# files: { "a.txt": "..." } # optional companion files (phase 1)
# nondet: seeds=8           # optional — sweep N seeds for admitted Nondet
# doc: |                    # optional free-text rationale (any number of lines)
#   why this fixture exists / which C-rule or D-decision it ratifies
# expect:                   # GENERATED by `ggdef -- gen`; keep it LAST
#   exit: 0                 #   0=Value 101=Trap 102=IllFormed 103=FuelExhausted
#   stdout: "9\n"           #   JSON-escaped observed stdout (canonical → idempotent)
#!end

void main():
    ...
```

**Schema keys (RFC §4).** `mode`, `expect:` (stdout + exit, or a diagnostic
code for the error tiers), `args:` / `stdin:` / `files:`, `nondet: seeds=N`,
`since:`, `features:`, `adjudicator:`.

- `adjudicator: ggdef` — expectation generated by the definition (the `run/`
  tier and elaboration-owned D4/D5/D6 rejections).
- `adjudicator: production-v1` — a tracked inversion for `static-error/`
  expectations the definition does not yet own; retired at v1.5.
- `adjudicator: prose` — expectation derived from spec prose for a rejection that
  NEITHER `ggdef`-elaboration NOR production implements yet (the §2.3
  invariant-#8 findings live here until the rejection ships).

Trap output is normalised (defined-panic message shape, `file:line` normalised);
the normalisation rule is spec text (landing with the trap-normalization spec).

## The `expect:` block is generated, never hand-written

```
cargo run -p ggdef -- gen spectests/run/<fixture>.gg     # (re)generate in place
```

`gen` RUNS the program and rewrites the `# expect:` sub-block (which MUST be the
last key before `#!end`) from the observed outcome. It is **idempotent**: a
second `gen` is a no-op. This is gated by `spec/ggdef/tests/gen_idempotent.rs`,
which asserts `gen(committed) == committed` for every `run/` seed — so a stale
expectation fails CI. On an intentional semantics change, re-run `gen` and review
the diff; do not hand-edit `expect:`.

## Runners & conformance (phase 1)

Each implementation lane (C backend / LLVM / self-host / `ggdef`) runs the suite
via a thin adapter and prints an always-pass `spec_conformance_<impl>` diagnostic
with monotone floors in `tests/lints.rs` (RFC §4). CI runs `ggdef` over
`spectests/`; nightly runs the full corpus. `ggdef` also joins **smith** as the
verdict lane (tri-state triage: impl bug / spec bug / spec silent).
