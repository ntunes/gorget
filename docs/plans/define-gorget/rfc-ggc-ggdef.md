# RFC: Gorget Core (GGC) and `ggdef` — the executable definition of Gorget

> **STATUS: DRAFT — under sequential fresh-agent review (pass 0). Do not implement from this
> document until it carries a clean SIGN OFF and the status line says APPROVED.**
> Companion: [`decisions.md`](decisions.md) (D1–D6 are normative inputs to this RFC),
> [`scouts/scout-c-prior-art.md`](scouts/scout-c-prior-art.md) (architecture rationale).

## 1. Goals and non-goals

**Goal.** Give Gorget a single, executable source of truth for its dynamic semantics — the
triad, in one repo, merge-gated together (the WebAssembly model):

1. **Spec prose** — `docs/spec/` (grows out of `language-design.md`'s normative parts).
2. **`ggdef`** — a definitional interpreter whose behavior IS the meaning of a Gorget program.
3. **`spectests/`** — a conformance suite every implementation runs, with expectations
   *generated by `ggdef`* and human-review-diffed.

Charter sentence (goes in the crate root, verbatim): **"`ggdef` is written for clarity and
simplicity, not speed. It is a device for nailing down exact semantics, not a runtime."**
Slogan for the model itself: **"CoW is an optimization; value semantics is the meaning"** (D1).

**Non-goals (v1).** Speed (that's `gg`); a second production frontend (we share the existing
lexer+parser); executable static semantics (v1 keeps type/borrow checking as prose +
expected-error-code fixtures; an executable GGC well-formedness checker is v1.5); mechanized
proofs (D3: mechanization-*friendly*, not mechanized — the Lean 4 path via Aeneas stays open);
async/concurrency semantics beyond single-threaded determinism (phase 3, see §8); replacing
`gg sim` as a CLI feature (sim's disposition is a separate owner decision; sim is permanently
disqualified as the *definition* regardless — the Miri trap, it consumes GIR).

## 2. GGC — the core language

GGC is the desugared core that `ggdef` evaluates. Design bar: small enough to hold in one head
(~30 constructs), total enough to mechanize later, faithful enough that every surface program
elaborates into it without semantic invention.

### 2.1 Construct inventory (v1)

Values: `int`/`float`/`bool` scalars (with the checked/wrapping arithmetic split and the
`Fault` trap conditions: Overflow, DivByZero, Bounds); `String` (one value type; view/owned
provenance is NOT in GGC — it is implementation detail under D1); `Vector[T]`, `Dict[K,V]`,
`Set[T]` as the canonical resource collections (Dict/Set iteration order: Dict/Set insertion-
ordered per C6; `HashMap`/`HashSet` order is the one admitted nondeterminism, seed-swept);
structs; enums with payloads (Option/Result included, nothing special about them in GGC);
tuples; closures (capture-by-value per D5; write-through captures carry an explicit
capture-mode tag from elaboration).

Places & bindings: locals; struct fields; collection elements; the three binding/passing modes
as **elaboration-resolved tags** on each use — `Borrow` (bare), `WriteThrough` (`&`),
`Move` (`!`) — GGC does not re-infer them.

Operations: bind, read, write (to a place), call (with per-arg mode tags), method call
(elaborated to plain call + receiver mode), construct (struct/enum/collection literal),
index read/write, field read/write, `match` with bindings, `if`/`while`/`loop`/`for`
(for-loops elaborate to explicit iterator/index loops with the element-binding mode tag),
`return`/`break`/`continue`, explicit `clone`, explicit `drop`-scope markers (scope exit,
reverse declaration order), throw/propagate/catch in the Result-desugared form (throws is
sugar — GGC sees `Result` values and match-on-carrier; fault-catch is a distinct guarded-op
form per the error-model Phase 1 design).

### 2.2 The ownership model in GGC (per D1/D2/D4/D5)

`ggdef` implements **eager value semantics**:

- A **bind** (`T b = a`, bare) conceptually copies the value as-of the bind point. (The
  production compilers implement this with borrows + CoW; `ggdef` just copies. D1 makes the
  difference unobservable; the copy-guarantees annexe (§5.4) polices the performance side
  separately.)
- A **`WriteThrough` place** (`&`) aliases the owner; writes land on it.
- A **`Move`** transfers the value and kills the source (reads of a dead source are a GGC
  well-formedness error — statically rejected upstream; `ggdef` still detects it dynamically
  as UB-class, MiniRust-style, as defense in depth).
- **Ownership boundaries** (collection put, ctor/field init, return, capture) receive the value
  — in eager semantics there is nothing to decide: the value is copied in (or moved when the
  source is a `Move`). Clone-vs-move liveness optimization does not exist in `ggdef`.
- **`self`** is a bare binding (D2): writes in a plain-`self` method land on the method's own
  copy.
- **Drop-purity (D4):** GGC types carry a `drop_tainted` bit from elaboration. Elaboration
  REJECTS implicit-copy positions for tainted types (surfacing the `E_MoveWithoutOperator`
  family); `ggdef` therefore never implicitly copies a tainted value, and drop count is a
  source-level fact. `ggdef` runs custom drops at scope exit in reverse declaration order;
  drop count/order for tainted types is normative and byte-tested.
- **UB-as-detected:** the small set of dynamic conditions `ggdef` checks and reports as
  spec-level errors (use-after-move as defense-in-depth, index OOB → `Fault.Bounds` trap
  semantics, arithmetic faults) — everything else is defined behavior. There is deliberately
  NO undefined behavior in GGC: conditions are either defined, trapped, or statically rejected.

### 2.3 Elaboration (surface AST → GGC)

A NEW, simple, spec-owned pass. It shares the production **lexer + parser only** (declared
trusted; the grammar remains prose-spec'd and conformance-tested via parse-error fixtures).
It must NOT import `src/ir/` or `src/semantic/` — enforced by an import ratchet lint in
`tests/lints.rs` from day one (the ggdef crate's allowed-imports allowlist: lexer, parser, AST,
span/diagnostic plumbing). Elaboration performs: desugaring (throws→Result, for→loop,
comprehensions→loops, method→call, dot-shorthand, `it`-closures), name resolution (its own
tiny resolver — the production resolver lives in `src/semantic/`, off-limits), mode-tag
resolution (bare/&/! from syntax), and the D4 taint computation + carve-out rejection.
v1 elaboration DOES duplicate a thin slice of semantic analysis; that is the price of
definitional independence, and the slice is kept thin by GGC's size. Divergences between
elaboration's judgments and the production typechecker are themselves conformance findings.

### 2.4 The interpreter discipline

- Safe Rust only, no `unsafe`, no dependencies beyond the shared frontend; pure data
  structures; **one fuel-indexed evaluation function** (CakeML-style functional big-step:
  `eval(fuel, state, expr) -> Outcome` where fuel exhaustion is a distinct outcome, making the
  function total and mechanization-ready).
- **`Nondet<T>`** wraps the only admitted nondeterminism (HashMap/HashSet iteration order;
  later: task interleaving), driven by an explicit seed; conformance runs sweep seeds.
- Every ownership-relevant event (bind-copy, move, explicit clone, drop, write) emits a
  **trace event with provenance** — the raw material for `gg explain` (phase 3) and for
  debugging divergences.

## 3. Crate & directory layout

```
spec/                      # the triad lives together
  ggdef/                   # crate: the definitional interpreter
    src/elaborate/         #   AST -> GGC (spec-owned)
    src/ggc.rs             #   the core language definition (data types = the spec's syntax)
    src/eval.rs            #   the fuel-indexed evaluator (the spec's semantics)
    src/trace.rs           #   provenance events
  prose/                   # normative prose, section-per-GGC-construct, cross-citing eval.rs
spectests/
  run/                     # frontmatter: run + expected stdout/exit (ggdef-generated)
  static-error/            # expected E_-code rejections
  parse-error/
  annexe/                  # copy-guarantees tests (§5.4) — implementation-facing, not ggdef-run
  staging/                 # low-bar tier (test262 model): debugging-session fixtures, no gate
```
`ggdef` is a workspace member with its own bin (`cargo run -p ggdef -- run file.gg`,
`-- gen file.gg` to (re)generate expectations, `-- trace file.gg` for provenance dumps).

## 4. Conformance wiring

- **Fixture format:** YAML-ish frontmatter in a leading comment block: `mode: run|static-error|
  parse-error`, `expect:` (stdout + exit, or `E_` code), `nondet: seeds=N`, `since: spec-v0.1`,
  `features: [..]`. Existing `tests/fixtures/*.gg` migrate incrementally (a converter writes
  frontmatter from the integration harness's current expectations, then `ggdef -- gen`
  REGENERATES and the diff is human-reviewed — expectations flow from the definition, never
  from whichever backend was written first; every regeneration diff is a finding).
- **Per-implementation runners:** thin adapters reusing existing machinery — the integration
  harness for C/LLVM (`GG_BACKEND`), the self-host driver lane (smith already re-derived it),
  and `ggdef` itself. Each prints a `spec_conformance_<impl>` diagnostic-always-pass report
  (MATCH/DIVERGE/REJECT counts) with **monotone floors in `tests/lints.rs`** — the existing
  ratchet pattern.
- **smith integration:** `ggdef` joins gorget-smith as the **verdict lane**: any C/LLVM/
  self-host divergence is adjudicated against `ggdef`; "all three agree but differ from ggdef"
  = three implementation bugs OR one spec bug — triaged tri-state (impl bug / spec bug / spec
  silent), never silently spec-patched. Divergence triage rule: a spec change is justified only
  by design INTENT (`language-design.md`, the ledger), never by "matches the implementation"
  (invariant #8, promoted into spec process).
- **Speed budget:** `ggdef` is slow by charter; conformance CI runs it on `spectests/` (small,
  curated), NOT the full 1,700-fixture corpus. A weekly/nightly job runs the full corpus.

## 5. Process

### 5.1 Same-PR gating (semantics-visible changes)
Once the skeleton lands: any change with observable semantics lands as ONE series — prose Δ +
`ggdef` Δ + spectest(s) + all implementations green (or an explicit floor-tracked exemption
with a TODO entry). Enforced socially at first, then by a coverage lint (new AST node or
fixture family ⇒ spec-coverage manifest touched — the arm-count-lint pattern).

### 5.2 Versioning
Spec releases are tagged `spec-v0.x` with a changelog; fixtures carry `since:`. Pre-1.0 the
spec is a living artifact (the SML "final revision" freeze is an explicit anti-pattern);
1.0 is a spec release, not just a compiler release.

### 5.3 Docs write-through (owner directive, standing)
Each landed decision/rule updates `docs/language-design.md`, the book, and the devbook in the
same series. The ledger (`decisions.md`) tracks write-through debt per decision; a decision's
ledger entry is not marked complete until its docs lines are live.

### 5.4 The copy-guarantees annexe (D1's second half)
A short normative list of MUST-NOT-ALLOCATE positions (bare bind, bare read, bare param pass,
borrow field/element read — the README's promises). Tested NOT via `ggdef` (which copies
eagerly by design) but via implementation-facing probes: designated `spectests/annexe/`
programs run under `--clones=stats` / a counting allocator, asserting zero clones on the
guaranteed positions. Conformance = semantics tests (ggdef-adjudicated) + annexe tests
(implementation-probed). The annexe is small and closed; growing it is a spec change.

## 6. Phased delivery

- **Phase 0 — walking skeleton (this round's deliverable 3):** `ggdef` crate + elaboration for
  the GGC subset covering the `cow_*` fixture family shapes (binds, aliases, mutation-severing,
  collections, structs, bare/&/! params, scope drops, prints). Acceptance: (a) runs ≥ the
  cow_* + deadwrite_* fixture families with output matching the already-ratified expectations
  (C1–C10 rules); (b) **adjudicates the two smith bugs** (dead-branch alias bind → `9`;
  `String !p` concat → `ablog`) and (c) **the EMove question** (pre-mutation value — settling
  it as spec, per D1) from the definition, not from the implementations. Import ratchet lint
  lands with the crate.
- **Phase 1 — coverage + conformance floors:** frontmatter migration, per-impl conformance
  reports + floors, ggdef verdict lane in smith, enum/match/closures/error-model coverage,
  D4/D5/D6 rejections in elaboration (+ negative fixtures both compilers).
- **Phase 2 — annexe + static-error fixtures + `gg explain` v0** (trace-backed provenance
  explanations; human + JSON output).
- **Phase 3 — nondet & async model** (seed-swept scheduling), executable well-formedness
  checker (v1.5 static semantics), mechanization prep audit (fuel/Nondet/purity invariants
  verified; Aeneas trial on `eval.rs`).

## 7. Risks and guards (from prior art; wired to existing culture)

Rot → ggdef runs spectests in CI from day 0 (bootstrap-gate pattern). Spec-lags-impl → same-PR
gate + coverage lint. Divergence-by-convenience → ggdef-generated expectations + intent-based
review + sequential fresh-agent passes. Perf creep → charter + sim absorbs speed pressure +
no-unsafe lint. Scope creep → MiniRust scoping (this RFC's non-goals are the fence).
Miri trap → import ratchet keeps ggdef off `src/ir`/`src/semantic`. Freeze → §5.2.
Coverage illusion → smith keeps fuzzing across all lanes; seeds swept.

## 8. Open questions for reviewers (not for silent resolution)

   fault-catch), or missing (meta? — proposed: meta is elaboration-time, never reaches GGC)?
2. Elaboration's thin resolver: acceptable duplication, or should name resolution be declared
   trusted-shared like the parser? (Proposed: own it — resolution affects semantics via
   shadowing/variant scoping.)
3. Does the annexe test mechanism (clone-stats probes) need a spec-side counterpart, or is
   implementation-probing sufficient for v1?
4. Where does D6's rejection live — elaboration (spec-owned) vs production typecheck first?
   (Proposed: both, elaboration is normative.)
5. Phase-0 subset boundary: are strings-with-provenance shapes (W3a-d) in or out of the
   skeleton? (Proposed: in — they're the highest-value adjudications.)
