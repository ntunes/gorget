- **🆕🚨 [HIGH — SILENTLY WRONG VALUES FROM UNINITIALISED MEMORY ON THE **SELF-HOST** LANE, at rc 0, no crash, no sanitizer report. The SELF-HOST sibling of `[[t0021]]`. Found 2026-09-12 by running the CI battery on x86_64.] A comprehension over `String.bytes()` pushes a 1-BYTE element into an 8-BYTE-element accumulator and over-reads the seven bytes that follow it.**
  - **REPRODUCED AT HEAD, deterministically, on linux/amd64.** `Vector[int] v = [b for b in s0.bytes()]` over `"ABC"` prints `3` then `9222246136947933505` where the correct answer is `65`. Regenerate without the harness:
    ```
    tests/fixtures/self_host_lowerer/driver \
      tests/fixtures/known_gaps/sh_comprehension_bytes_narrow_elem_overread.gg lib \
      --emit-c --runtime-dir=src/backend/c/runtime > /tmp/c.c
    cc -O0 -w -o /tmp/c.bin /tmp/c.c -lm -lpthread && /tmp/c.bin
    ```
  - **MECHANISM — the emitted C states it in three lines.**
    ```c
    uint8_t __s14 = 0;                         // the loop element: ONE byte
    __v8 = gorget_array_new(sizeof(int64_t));  // the accumulator: EIGHT bytes
    __v35 = &__s14; gorget_array_push(__v34, __v35);
    ```
    `gorget_array_push` copies the DESTINATION's element width from the address it is handed, so it reads `__s14` plus the seven bytes after it. The value stays inside the allocation, which is why ASan does not report it.
  - ⛔⛔ **THE FIXTURE THAT WAS SUPPOSED TO CATCH THIS WAS ITSELF AN INSTANCE OF WHAT IT GUARDED AGAINST.** Until 2026-09-12 this program was `tests/fixtures/self_host_comprehension/list_bytessrc_narrow_elem.gg` — a LIVE, GREEN cell whose header stated that the self-host lane prints the CORRECT `3` / `65` and that the cell existed **precisely so that a future change could not make both lanes agree on the wrong answer** (Core #8's trap, named in its own text). **That claim was measured on aarch64 and is FALSE on x86_64.** The over-read is identical on both architectures; what differs is what follows the byte on the stack. On AAPCS64 those seven bytes happened to be zero and the value read back as 65. ⇒ **A cell whose expected value depends on uninitialised memory is not an oracle on ANY architecture** — it was nondeterministic by construction and merely stable on the author's box. The cell is now this item's `known_gaps` repro, with the same INTENDED value asserted by an `#[ignore]`d test, and `SELF_HOST_COMPREHENSION_CELL_FLOOR` moved 39 → 38 with the relocation named at the constant.
  - ⚠ **WHAT DISCRIMINATES IT — COMPREHENSION-vs-STATEMENT**, exactly as on the Rust lane. `for b in s0.bytes(): v.push(b)` on identical input prints `65` correctly on the self-host: a DECLARED accumulator coerces the push. **The comprehension's accumulator is DEFERRED-MINTED** (`comp_reserve` / `comp_note_elem` / `comp_close`, `lower_expr.gg`) — the synthesized push lowers BEFORE the accumulator's type is emitted, so there is no declared destination type for a coercion to key on at that moment. ⇒ **this is NOT a one-line widening at the push site**, and that is the whole reason it was filed rather than fixed.
  - ⛔ **DO NOT RE-DERIVE THE ELEMENT TYPE FROM THE SOURCE OR FROM THE BODY.** `lower_expr.gg`'s own comment records that **four successive body/source-derived remedies were each BUILT and each broke a different cell**, and names the live cell that convicts the source-derived shape (`self_host_comprehension/graduated_nested_vector_source.gg`). The element type has to come from the MATERIALISED local, which is what `comp_note_elem` already carries; what is missing is a COERCION to the declared result element when the two differ in width.
  - **DISCRIMINATED from `[[t0021]]`** — that is the RUST lane, same construct, same class, and is separately filed with its own durable repro (`known_gaps/comprehension_over_bytes_narrow_elem_overread.gg`, INTENDED `2` / `65`). **Both lanes are wrong, so neither adjudicates**; the intended value here is derived by hand from the definition (`"ABC"` is three ASCII codepoints, so `.bytes()` yields 65, 66, 67). Fixing either lane leaves the other live. ⊕ `t0021`'s text should no longer be read as implying the self-host is correct on this axis.
