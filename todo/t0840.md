- **🆕🚨💥 [CRITICAL — THE Book-Ch16 "MANY OWNERS" IDIOM SEGFAULTS: `gg check` rc 0, run rc -11 on BOTH real backends; found 2026-08-30 by R47 Track F4a when the new verdict classifier stopped grading signal deaths as `TRAP`]** Seven lines, `tests/fixtures/robustness_map/cells/sh_vector_of_shared.gg`:
  ```
  void main():
      Shared[int] s = Shared[int](42)
      Vector[Shared[int]] all = []
      all.push(s.clone())
      all.push(s.clone())
      all.push(s.clone())
      print(f"{all.len()}")
      print(f"{all.get(1).unwrap().get()}")
  ```
  Expected `3` / `42`. This is the "many owners" case `docs/book/` Ch16 exists to teach.

- **THE MECHANISM: THE ELEMENT SLOT WAS NEVER WRITTEN.** Under `gg build --sanitize`, UBSan fires FIRST and names it:
  ```
  x.c:3687:75: runtime error: load of misaligned address 0xbebebebebebebebe
               for type 'int64_t', which requires 8 byte alignment
  ==N==ERROR: AddressSanitizer: SEGV on unknown address 0x17d7d7e7d7d7d7d7
      #0 Shared__int64_t__get   #1 main
  ```
  **`0xbebebebebebebebe` IS the sanitizer's uninitialised-heap fill pattern**, so the vector element was never stored; `0x17d7…` is that fill after the accessor's pointer arithmetic, one frame later. ⚠ An earlier draft of this item read only the SEGV line, called `0x17d7…` "not a poison pattern", and concluded the push and the read disagreed about LAYOUT. That points at the wrong fix. The committed record already had it right — `MANIFEST.tsv`'s note for this cell reads *"UBSan: misaligned load 0xbebe..."*. **Read the UBSan line before the ASan line: for a sanitized bad load it comes first and it is the one that names the cause.**

- **WHAT TO MEASURE FIRST.** Whether `push` stores nothing at all, or stores into the wrong slot: `all.len()` printing `3` says the length was updated, so the container bookkeeping ran and only the payload write is missing. Compare against a `Vector[Shared[T]]` built by a literal rather than by `push`, and against `Vector[Box[T]]` / `Vector[String]` with the same shape — the element type's clone/drop pair is the obvious suspect axis.
- **DISCRIMINATED from the filed `Shared` work:** `t0612`'s residual is `Shared[Callable[T]].get()()`, an invoke-chain lowering gap whose own text records *"there is NO heap-overflow/UAF/SEGV"*; `t0406` is the `&`-sigil non-identifier-callee class.
