- **[MED — A CAPABILITY GAP IN THE FFI SURFACE, left standing once the fiction that hid it was removed: there is no way to declare a C function that takes or returns a pointer. Found 2026-08-29 by R47 Track C; the documentation half was removed by R47 Track D3b and this entry now carries only what REMAINS.]**
  - **THE DOC-FICTION HALF IS NO LONGER LIVE.** `RawPtr[T]`/`ConstRawPtr[T]` were documented in `docs/book/21-interop.md` (a `## Raw Pointers` section plus a worked example) and `docs/language-design.md` (`### 11.3 Raw Pointers`, a numbered design section) while appearing nowhere in `src/`, `spec/` or `lib/`. Those sections are gone. Regenerate: `grep -rn 'RawPtr\|ConstRawPtr' docs/` → **0**. Do not re-file the doc half; what follows is the part the deletion exposed rather than fixed.
  - **THE REMAINING GAP, and it is a real one.** Removing the fictional type left the FFI examples unable to express the signatures they had. `void free(RawPtr[void] ptr)` and `int read(int fd, RawPtr[void] buf, int count)` had to be dropped from the book rather than rewritten, **because Gorget has no type that marshals to a C pointer**. `docs/language-reference.md` §5.10 enumerates what an `extern "C"` block can say — `String` → `const char*`, `cstr`, and the `extern "Gorget"` resource types — and there is no `void*`. So `malloc`/`free`, buffer I/O, opaque handles, and every callback-taking C API are undeclarable today. The FFI story is honest now; it is also narrower than a systems language needs.
  - **DISPOSITION IS AN OWNER CALL — and D50 changed the frame it must be decided in.** The original framing was *"implement the FFI escape hatch both documents describe"*. `unsafe` no longer exists (D50), so a raw pointer cannot be reintroduced as a construct that suspends the language's guarantees; whatever fills this gap has to be safe by construction or explicitly rejected at the boundary. Coherent options: (a) an **opaque handle type** — a pointer-width value that can be passed to and returned from `extern` functions but never dereferenced in Gorget, which covers `free`, opaque handles and buffer APIs without a deref hole; (b) **typed buffer marshalling** — let `Vector[byte]`/slices pass as `void*` + length at the `extern "C"` boundary, which covers the read/write family and nothing else; (c) **declare the gap intentional** and say so in §5.10, so the next reader stops looking. Not interchangeable: (a) and (b) are type-system work, (c) is a paragraph.
  - **FAMILY.** `t0810` (`Sendable`/`Syncable` documented, absent) and `t0411` (`thread.spawn` documented, absent) are the other two members of the documented-but-absent family in the same stretch of `docs/language-design.md`. `t0038` is the mechanism that let all three type-check under casual probing — an undefined type name is silently accepted in parameter and field positions, which is exactly why `RawPtr[void] ptr` as a *parameter* returned rc 0 while `RawPtr[int] p = 0` returned `E_UndefinedName`.
