- **🆕🚨 [HIGH — MEMORY-UNSAFE FROM ORDINARY SAFE SYNTAX, both backends, `gg check` rc 0 AND `gg build` rc 0; the DEFERRED half of R49 Track S-a2, deferred on an owner ruling rather than overlooked] A BARE INDEX PLACE of single-owner type binds a second owner: two reads DOUBLE-FREE.**
  ```gorget
  Vector[Callable[int()]] v = []
  v.push(mk(40))
  Callable[int()] g  = v[0]   # owner 1
  Callable[int()] g2 = v[0]   # owner 2 — same env
  ```
  → `AddressSanitizer: attempting double-free`. A `Dict[String, Callable]` read twice at the SAME key is the same. Read at the same key once per iteration of a loop and BOUND to a local it is a `heap-use-after-free` instead; the same loop CALL-ONLY, never bound, leaks the env.
  - **WHY IT IS NOT ALREADY CLOSED.** R49 Track S-a2 widened the carve-out's gate from `if let Expr::Identifier(_)` to a structural place test, and the gate keys on the OUTERMOST PROJECTION. `h.f`, `t.1`, `t._1` and even `v[0].f` (a read THROUGH a container) now reject with `E_MoveWithoutOperator`. A BARE index place does not — deliberately.
  - ⚖ **THE OWNER RULED (2026-09-04): THE CALLEE POSITION IS A BORROW POSITION.** A call does not consume its callee: `Callable` borrows, `MutCallable` mutably borrows, `ConsumeCallable` consumes. Under that rule `h = d[k]` used only to CALL binds a borrow — no second owner, no clone, nothing to free. Rejecting index places *before* that rule lands would instead force a per-request closure-env `.clone()` on `lib/xtd/httpserver.gg`'s dispatch path (8 sites, 5 of them call-only), which is the charter breach the ruling exists to remove. **So the sequence is: land the callee-borrow rule, then this closes; do not widen the reject ahead of it.**
  - ⛔ **THE DISCRIMINATOR IS THE ELEMENT-READ COUNT — NOT THE CONTAINER'S SPELLING, AND NOT THE BIND COUNT.** Two earlier readings are recorded here as **measured false**, so that neither comes back: (i) *"each httpserver site binds EXACTLY ONCE"* — a cell that binds exactly once PER ITERATION is a `heap-use-after-free`; and (ii) its replacement, *"a read through a `&` BORROW PARAM is CLEAN; the same loop from a BARE LOCAL is a UAF"* — **both halves false**, because the same same-key loop is a UAF through a `&` param too, and a bare local reading DISTINCT keys is clean. **THE AXIS IS WHETHER THE SAME ELEMENT IS READ MORE THAN ONCE.** Each read binds another owner of that element's one heap value, so the safe property is *"each ELEMENT is bound at most once"*, by any route: read one element twice and it double-frees (straight-line) or use-after-frees (across loop iterations); read it twice call-only, never bound, and it leaks the env instead.
