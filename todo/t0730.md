- **🆕🐛 [MED — TWO of the THREE named residuals of R47 Track D1's primitive-receiver reject; all are lane divergences with a CLEAR correct direction] `reject_no_method_on_primitive` (`self_host_typechecker/typecheck.gg`) is deliberately weaker than its Rust counterpart.** They are named rather than left implicit, because a reader who tightens the first one without fixing its blocker will re-introduce twelve false rejects.
  - ⚠ **THE THIRD RESIDUAL IS THE BIGGEST AND IT IS FILED SEPARATELY AS `todo/t0740`**: the reject fires only for a bare IDENTIFIER receiver, so four of the five cells of the RECEIVER/ROOT-SHAPE axis still miscompile — one of them by inventing `int64_t__to_string` at link time. It is its own item because it has its own repro and its own two-way exit; this item is the two residuals that live inside the admission test itself.

  1. **A String-table name on a NUMERIC receiver is still accepted, and silently miscompiles.** `3.0.len()` compiles, runs, and prints a GARBAGE INTEGER (`281474220167352` on one run) — not a CC-FAIL, a silent wrong answer, which is the worse half of the lower-or-reject class. Rust gg rejects it: `error[E_NoMethodFound]: no method `len` found on type `float``. Repro `tests/fixtures/known_gaps/sh_len_on_float_silently_miscompiles.gg`, wired `#[ignore]`d as `known_gap_sh_len_on_float_silently_miscompiles`, asserting the reject.
     - **BLOCKED ON `todo/t0727`**, and the blocker is the whole point. The reject abstains because it consults `any_prim_method_admitted` — the UNION of every primitive's table — rather than the receiver's own. A per-receiver-kind table closes this cell AND refuses 12 valid corpus programs, because the self-host resolves their receivers to the wrong definition. Fix the resolution, then dispatch per kind, then this graduates.
  2. **The diagnostic CODE diverges for a non-optional `unwrap`.** `x.unwrap()` on an `int` is now rejected on both lanes — an improvement; it used to be accepted and run as a silent no-op — but the self-host reports `E_NoMethodFound` where Rust reports the specialised `E_UnwrapOnNonOptional` ("method `unwrap` requires an `Option` or `Result` receiver, but `int` is neither"). Fixtures: `tests/fixtures/method_resolution_unwrap_on_int.gg`, `method_resolution_unwrap_or_on_int.gg` (both currently pinned on the Rust lane only).
     - The direction is aligned, so this is not urgent — but the codes are the conformance axis a `spectests/run/reject_*.gg` fixture pins, so the first spectest written for this shape would MISMATCH on the self-host lane. Closing it means giving the self-host a `DkUnwrapOnNonOptional` DiagKind and checking it before the generic reject, which is a different fix shape from the reject itself.
