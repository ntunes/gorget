- **🆕🧹 [MED — READINESS CHECKLIST rows should GRADUATE to executable guards and LEAVE the checklist (owner 2026-08-29). Deferred from the capping change that landed the same day.]** The checklist is now capped at five rows by `readiness_checklist_rows_are_capped`, so a new defect class must RETIRE a row or become a guard. That makes growth an explicit act but leaves the standing cost: **every row is a PRE-LAUNCH obligation re-performed by every track, forever.** Core #6 says the durable form of a recurring check is an executable guard, not prose — and three of the five rows are decidable without judgement.

  **The graduation candidates, in the order they pay:**
  - **Row 4 — "the GUARD FAILS when the fix is reverted" is mutation testing spelled as a promise.** A script can revert the diff's `src/` hunks into a scratch worktree (NEVER `git stash` — repo-global, see Multi-agent rule 8), run the round's named guard, and require RED. This is the row most often attested and least often actually performed, because performing it by hand is expensive. Landing it retires the row AND enforces Core #12's RED-verify mechanically.
  - **Row 5 — "every load-bearing figure REGENERATED at current HEAD"** is already half-mechanised by Core #15(a), which requires every load-bearing claim to carry its VERIFICATION COMMAND. A brief-linter can assert that every figure-shaped token in a brief has a regen command within its block; the residual (was the command actually run this session) is what stays human.
  - **Row 3 — `|pinned cells| == |changed cells|`** is a diff-vs-fixture count. Decidable from the diff plus the fixture set, so a script can compute both sides and compare.

  **Rows 1 and 2 are the hard ones and probably stay.** Row 1 (every measurement carries a FIRE COUNT) needs the instrumentation to exist before it can be checked. Row 2 (every enumeration cites an INDEPENDENT witness) is a judgement about what counts as independent — `t0725` is the worked example: the independent witness was `rustc` itself (renaming `FunctionBuilder::call` enumerated 105 × E0599 across 9 files) after three grep-based censuses had each produced a selection and called it an enumeration.

  **Acceptance.** Each graduated row lands as a guard in `tests/lints.rs` or a script wired into the round-close battery, RED-demonstrated on a deliberately broken variant (Core #13), AND is DELETED from the checklist in the same commit — including its inventory probe (`REV-ck3`/`REV-ck4`/`REV-ck5`) and a renumbering of the survivors, which `readiness_checklist_rows_are_capped`'s contiguity assert enforces. A row that gains a guard but stays on the checklist has doubled the cost, not halved it.

  **Why it is filed and not fixed inline.** Distinct CLASS from the capping change (that one stops growth; this one reduces the standing cost), and each row is a real guard to design and RED-verify.
