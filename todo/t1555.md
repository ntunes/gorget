- **🆕📐 [MED — OWNER DECISION REQUESTED. A structural cost R51 created and did not solve. Raised by the orchestrator 2026-09-06 when the owner asked for an assessment of the round.]**

  **The measurement.** `AGENTS.md` is **48,633 bytes** against a ceiling of **49,400** — **767 bytes of headroom**. Regenerate both:

  ```
  wc -c < AGENTS.md
  grep -n 'AGENTS_MD_SIZE_CEILING' tests/lints.rs
  ```

  The ceiling has moved **three times** (`49_000` → `49_200` → `49_400`; the comment at `tests/lints.rs:12448` records the third). R51 alone added roughly **3.4KB** of rules. At that rate the next round has no room, and the *response so far has always been to raise the ceiling.*

  ⭐ **WHY THIS IS NOT BOOKKEEPING.** The file is loaded into the context of **every agent the orchestrator launches** — scouts, brief-reviews, executors, output-reviews. A round with 4 tracks and ~20 passes pays that cost ~25 times. Growth here is not a documentation cost, it is a **per-agent tax that scales with the number of passes the gauntlet runs**, and the gauntlet is the thing we keep making more thorough.

  **THE PROPOSAL (orchestrator's opinion, unratified).** Stop raising the ceiling; start **retiring**. The mechanism already exists in the file's own logic — Core #6 says *"convert a recurring bug class into an executable guard … prose rots, guards don't."* Where a rule now has a **lint or validator enforcing it**, the prose can shrink to a pointer at the guard, because the guard is what actually binds. Candidates are exactly the rules that earned a `tests/lints.rs` entry this round and last.

  ⚠ **THE COUNTER-ARGUMENT, STATED HONESTLY.** A rule's prose does work a guard cannot: it says *why*, and it reaches an agent **before** the agent writes the code, whereas a lint only fires **after**. Shrinking a rule to a pointer may trade a cheap up-front correction for an expensive late one. So the retirement test is **not** "does a guard exist" but **"would an agent that never read this prose still do the right thing, because the guard makes the wrong thing impossible rather than merely detected?"** Rules whose guards *detect* must keep their prose; rules whose guards *prevent* can shrink.

  **WHAT IS BEING ASKED.** A direction, not a specific edit: (a) raise the ceiling again, (b) retire under the prevent-vs-detect test above, or (c) split the file so agents load only the section that binds them (`AGENTS.md` already declares *"Read the part that binds you"* — but every agent still receives all of it, so the declaration is currently advisory only).

  ⊕ **Option (c) is the one no round has costed**, and it is plausibly the largest win: the § Multi-agent orchestration, § Review and § Round lifecycle sections bind **the orchestrator alone** and are shipped to every executor regardless. Measuring what fraction of the file that is would be the first step, and it is a `wc -c` away.
