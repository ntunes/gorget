- **🆕🐛 [MED — SELF-HOST lane; the surviving POSITION of a four-arm class whose other position closed] A closure LITERAL at a BUILTIN-METHOD ARGUMENT is emitted `int64_t`-returning whatever it actually returns:** `error: incompatible types when returning type 'Str' but 'int64_t' {aka 'long int'} was expected`.
  - **⭐ THE SUBJECT IS THE POSITION, NOT THE BODY SHAPE.** `compute_closure_sig` prefers the AMBIENT expected type: where the destination is declared `Callable[R(...)]` the declaration already names the return type and the body is not re-derived. Whether that fires is decided entirely by WHERE the closure sits:
    | position | what `ctx.expected_type` holds | peel | verdict |
    |---|---|---|---|
    | declared `Callable[R(..)]` local | the local's own declared type | reads `GtFnPtr` | **works** |
    | direct free-call argument | the CALLEE's declared param type | reads `GtFnPtr` | **works** |
    | **builtin-method arg, `or`/`and_then`/`flat_map`/`or_else`** | a peeled `Option`/`Result` **WRAPPER** | no `GtFnPtr` — declines | **THE GAP** |
    | **builtin-method arg, `unwrap_or_else`** | the receiver's **PAYLOAD** (`ok_type`) | declines *only if the payload is not callable* | **THE GAP — and see `t1303`** |
    ⚠ **THIS TABLE IS A SELECTION, NOT AN ENUMERATION** (Six Questions #3). `grep -rn 'ctx\.expected_type = ' tests/fixtures/self_host_lowerer/*.gg` shows ~25 non-restore writers, several reachable by a closure literal — struct-literal field, dict value, list element, tuple element, return, index-assign, field write. Every one of them lands in the "works" bucket (the destination's declared type IS the callable), so the VERDICT generalises; the table still cannot show you what it omits, and a new writer is not covered by having read this row.
    Regenerate the writers: `grep -n 'int prev_expected_arg = ctx.expected_type' tests/fixtures/self_host_lowerer/lower_expr.gg` (the `-1` beside it is an initial clear, **immediately overwritten** with the peeled param type — an earlier version of this item said call arguments simply carry `-1`, and that was false) and `grep -n '_combinator_et' tests/fixtures/self_host_lowerer/lower_expr.gg`.
    ⚠ **`_combinator_et` IS NOT ONE THING, and an earlier version of this row said it was.** `or`/`and_then`/`flat_map`/`or_else` take `peel_ptr_tid(..)` of an Option/Result **wrapper**; `unwrap_or_else` takes `enum_category.ok_type`, the **payload** — that site's own comment reads *"uoe returns the PAYLOAD (Some_0 / Ok_0), not the wrapper"*. So *"the receiver's own Option/Result"* is true of the first group and FALSE of the second, which is the one this item's own repro exercises.
    ⊕ And the earlier erratum here had the coincidence **INVERTED**. At `unwrap_or_else` `_combinator_et` **IS** exactly the closure's return type (the closure must produce the payload). At `and_then`/`or_else` it is the WRAPPER, which coincides with the closure's return type only in the same-type case. The operative fact that holds everywhere is narrower than either: **for the types the corpus actually puts here, it is not a `GtFnPtr`, so the peel declines.** ⛔ That is CONTINGENT, not structural — `todo/t1303` is the payload that breaks it.
  - **⭐ THE BODY SHAPES ARE NOT THE DISCRIMINATOR, MEASURED.** The *same* bare-parameter body compiles at a direct-call argument and fails at a builtin-method argument; the repro holds the body fixed across the two positions to say exactly that. **⇒ No widening of a body-shape rule reaches this cell** — its subject does not exist in that taxonomy.
  - **THE FOUR BODY SHAPES that have no arm** (`tests/fixtures/self_host_lowerer/lower_closures.gg::guess_return_type`), all of which survive at this position: **(a)** an `Ok(..)` / `Error(..)` body — the `Some(x)` sibling arm MINTS `Option__U` from the payload, but the Result constructors are gated on `expected_type` being a Result. **(b)** a bare closure PARAMETER identifier and **(c)** a bare outer LOCAL identifier — one arm, one miss: the `EIdentifier` arm consults `gmod.fn_sigs` and nothing else, so it is INERT (not absent) for any bare identifier `fn_sigs` misses. **(d)** a METHOD-CHAIN body — the `EMethodCall` arm does not carry a collection's element type back out.
  - **WHAT CLOSING IT NEEDS, and Rust gg is the shape.** Rust carries BOTH halves: it registers the closure's params as locals immediately BEFORE running its body inference ("Tier 1c"), and then lets the ambient type override the result (`grep -n 'ambient' src/ir/lowering/closures.rs`). The self-host now carries only the override. The fallback is three ports: Tier-1c param registration, a `lookup_local` beside the `EIdentifier` arm's `fn_sigs` read, and element-type propagation through `EMethodCall`. ⊕ A fourth rides along: `resolve_builtin_method_return_type` replacing `guess_return_type`'s hardcoded method-name lists (`if mname == "upper" or mname == "lower" …` deciding a TYPE) — a live Core #2 / "no name matching" violation.
  - **⚠ AN INERT ARM AND AN ABSENT ARM EMIT THE SAME C.** An earlier erratum on this item asserted `guess_return_type` had *"NO `EIdentifier` arm at all"*; the arm exists (`grep -n 'case EIdentifier(name):' tests/fixtures/self_host_lowerer/lower_closures.gg` — the first hit is the one inside it) and merely misses. **Recorded because the REMEDY differs:** widening the arm to consult local types is the fix; *"add the missing arm"* would have been written beside the one already there. *"The symptom is identical"* is not evidence about the mechanism.
  - **⚠ DISCRIMINATE FROM `t0230` (b)**, the SAME helper's other fall-through: a closure whose body's last statement is `SMatch`/`SIf` returns UNIT, not I64. The ambient override does not rescue it either (`snag51_closure_block_tail_value` SEGVs identically with and without it) — same helper, different arms, different wrong answer, and they want fixing together.
  - **NOT `t0770`** (fixed): that class is about reading an ERASED `Callable` PARAMETER's declared return type, and its self-host reader (`combinator_closure_ret_type`) now peels the callable local's `GtFnPtr`. Here nothing is erased.
