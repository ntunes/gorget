- **🆕🛡 [MED — THE THIRD VARIANT OF A VACUOUS GATE IN ONE CLASS, AND THIS ONE IS INSIDE THE FIX FOR THE FIRST TWO. Found 2026-09-06 by R51 Track A's output-review; re-measured by its executor at the shipped ledger size.]**

  `run_box_receiver_guards` prints `[box-receiver] subject=N decl=D val=V`, and `scripts/box_receiver_burndown.sh` reds a `CLEAN` row whose `subject` has fallen to 0. That is what stops a `CLEAN` row going vacuous — **for the DECLARATION guard.** ⛔ **It does not do the same job for the VALUE guard**, because `subject` counts externs carrying ANY `box_wrapper_arm` while `validate_box_get_ptr_result_consumed` returns an empty vec unless a `GetPtr` extern exists.

  **Measured at the shipped ledger** (regenerate per row: `GG_BOX_RECEIVER_GUARD=count target/debug/gg build <row> --emit-lir` for `subject=`, and `grep -cE '^declare .*Box__[A-Za-z0-9_]+__get_ptr\\(' ` on the same dump):

  | CLEAN rows | `subject=` | `get_ptr` externs | value guard |
  |---|---|---|---|
  | the 4 `box_d36_*_method` cells | 1 | **1** | live |
  | the 8 `box_receiver_*_get` cells | 1 | **0** | **inert** |
  | `box_heap.gg` | 2 | **0** | **inert** |
  | `drop_raii.gg` | 1 | **0** | **inert** |

  ⇒ **10 of 14 CLEAN rows are positive controls for one guard and decoration for the other, while the census reports them identically.**

  ⛔ **THE CONSTRUCTIVE PROOF, which is what makes this a defect and not a nitpick:** rewrite `box_d36_field_of_temp_method.gg`'s read from `make().b.val()` to `make().b.get()`. Its `get_ptr` extern count goes to 0, the census still says `subject=1`, `run_gg` still passes, and the burn-down gate still reports OK — **the value guard's positive controls can be removed one at a time with every gate staying green.**

  ⚠ **THIS CLASS HAS NOW SHIPPED A VACUOUS GATE THREE TIMES**: *"0 fires over 72 fixtures"*, *"141 rows, no false positives"*, and now a census invented specifically to retire those two, which retires them for only one of the two guards it serves. **An aggregate subject count cannot adjudicate a per-guard question** — the same shape as `todo/t1538`'s iteration-domain finding, one layer up.

  **INTENDED:** the census reports `decl_subj=` and `val_subj=` separately; each `CLEAN` row declares which guard it is a control for and is reconciled against THAT guard's subject count; and the ledger carries a per-guard `CLEAN` floor so the value guard's controls cannot be emptied while the declaration guard's stay full.
