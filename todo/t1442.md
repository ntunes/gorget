- **🆕🚨 [HIGH — THE SAME UNDEFINED BEHAVIOUR, IN THE LANE THAT IS MEANT TO BECOME THE PRIMARY REFERENCE. Found 2026-09-05 by R50 Track L's brief-review pass 2.]**

  `tests/fixtures/self_host_lowerer/lir_codegen.gg` has its **own C emitter** with the **same three-arm shape** as `src/backend/c_lir/mod.rs` (regenerate: `grep -n 'case IAdd(dst, ty, lhs, rhs, overflow)' tests/fixtures/self_host_lowerer/lir_codegen.gg`). The non-`OVF_TRAP` fall-through emits **plain signed C arithmetic** — exactly the `Overflow::Wrap` cell `todo/t1410` fixes on the Rust lane. Same at `ISub` and `IMul`.

  ⛔ **AND TWO SITES ARE WORSE THAN THE RUST LANE:**
  - **`INeg`** emits `-(int64_t)(intptr_t)` — **UB at `INT64_MIN`.**
  - **`IShl`** emits a bare `<<` with **NEITHER a count trap NOR an unsigned companion.** The Rust lane traps the count at `>= sizeof(ct)*8`; the self-host does not.

  ⛔⛔ **AND NOTHING WATCHES IT.** `grep -n 'self_host_lowerer' tests/sanitize/CORPUS_MANIFEST.txt` → **`OUT`**. The lane has no UBSan gate, so the defect is invisible by construction.

  ⭐ **WHY THIS IS NOT A FOOTNOTE.** The succession plan makes the self-host the intended **primary reference** at parity. A reference lane that emits UB where the current reference does not is the *"reference lags the self-host"* finding inverted — and Core #4 says fix the **class**, not the lane that happens to be in front of you.

  **INTENDED:** the self-host's emitter performs wrapping arithmetic in an unsigned type of rank ≥ `int`, traps its shift counts, and handles `INeg` at `INT64_MIN` — matching whatever `t1410` lands on the Rust lane. The mirror is roughly six lines.
