ROOT CAUSE (No-name-matching violation, Layering rule 2): `src/lir/lower/insts.rs:616`/`:730` rewrite `gorget_abs`→`gorget_fabs` for float operands, but the RUNTIME_MATH include gate at `src/backend/c_lir/emit_types.rs:2363-2374` tests `starts_with("gorget_abs")` / `== "gorget_min"` — `gorget_fabs`/`gorget_fmin`/`gorget_fmax` match nothing, so the header is never emitted. **The class**: float `min`/`max` in the same position fail identically (`gorget_fmin`/`gorget_fmax`, probe-verified). **Second defect underneath (accept/reject asymmetry)**: outside an f-string the same call REJECTS (`E_TypeMismatch: expected int, found float` — `lib/std/math.gg:19` declares `int abs(int x)`); inside an f-string it is ACCEPTED and miscompiled — the f-string path bypasses the typecheck that the plain path applies, so the C failure is the SYMPTOM of an accept that should not happen (or, if float `abs` is intended, the plain path should accept too — owner/design call on which).
