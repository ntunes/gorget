- **[MED — owner-approved 2026-08-30, R48 candidate] ONE GENERIC FIGURES DB — for ratchets, limits,
  benchmarks and any other pinned number.**
  ⛔ **GENERIC BY REQUIREMENT (owner):** *"make sure the db is generic and not specific to any track.
  Should be reusable by other systems, ratchets, limits, etc."* **Do not build a clone-meter feature.**
  - **The scale, measured 2026-08-30:** `grep -rhoE "\b[A-Z][A-Z0-9_]*(CEILING|FLOOR|LIMIT|BUDGET|BASELINE)\b"
    tests/ src/ scripts/ | sort -u | wc -l` → **54** distinct identifiers, spanning at least four unrelated
    systems — parity (`*_MATCH_FLOOR`), the spec's own ratchets (`AGENTS_MD_SIZE_CEILING`,
    `AGENTS_MD_MAX_RUNS_OVER_100`, `AGENTS_MD_RULE_FLOOR`), self-host coverage
    (`SELF_HOST_COMPREHENSION_CELL_FLOOR`), formatter shape (`SHAPE_MAX_DEPTH`, `FILL_PACK_MAX_WIDTH`),
    plus the four clone meters and the leak allowlist. **Any schema that only fits one of these is wrong.**
  - **THE GENERALISING AXIS IS POLARITY, NOT SUBJECT.** A row is `shrink-only` (ratchet) · `grow-only`
    (floor) · `exact-pin` (the clone meters under the 2026-08-30 owner ruling) · `informational`
    (benchmarks, census counts, coverage shares). **Polarity is what a checker needs; the subject is
    just a name.** Get this field right and the schema serves everything above.
  - **Per row:** `id` · `value` · `polarity` · `regen` (the command that reproduces it) · `instrument` ·
    `measured_at` (commit) · `caveat` (e.g. *"attributes ~3.5% of clone volume; leaf calls, not events"*).
    ⚠ **`regen` is mandatory** — a figure with no command is a hope (Core #15a).
  - **⛔ THE VALUE IS THE GUARD, NOT THE FILE.** A figures file with no lint forbidding bare literals of
    covered figures in prose is a *sixth spelling with better manners*. R47 shipped five spellings of one
    census figure, ten `todo/` items instructing a retired tool, and `208` surviving **in the doc comment
    of the lint that enforces the rule**. Those die only when something FAILS on a duplicate (Core #6).
  - **THE PRECEDENT EXISTS AND IS PROVEN — GENERALISE IT, DO NOT RESTART.** `scripts/clone_meter.spec`
    (R47 F5a) is one declaration read by **three** instruments — `clone_meter_get` (awk,
    `scripts/clone_meter.sh`), `clone_meter_spec_get` (`tests/integration.rs`), `clone_meter_spec_values`
    (`tests/lints.rs`) — with `tests/lints.rs::clone_meter_instruments_read_the_declared_spec` failing when
    an instrument spells the invocation itself. ⚠ **Its own header records the gap to close: the DATA is
    single-source but the THREE READERS have no agreement guard.**
  - **⛔ NOT YAML — and the reason is in the precedent's header.** The format is deliberately restricted
    (`key = value`, whole-line `#` only, no trailing whitespace) because **awk strips only the leading
    run while Rust `trim()`s both ends**, so a trailing space would reach the shell intact and break the
    build. One reader is awk. `toml 0.8` is already a dependency (`Cargo.toml:25`) if rows genuinely need
    nesting — reach for it only then.
  - **⚖ THE LEDGER KEEPS ITS DATED MEASUREMENTS.** ⛔ Do NOT strip figures out of
    `docs/define-gorget/decisions.md`. A dated measurement inside a ratified entry is **evidence for the
    ruling at the time it was made**; replacing it with a pointer to a live value changes what the entry
    asserts, and a reader could no longer tell whether a ruling still rests on its original grounds.
    ⇒ **The ledger records what was measured THEN; the DB records what is true NOW.** A ledger entry gains
    a pointer to the live row; it loses nothing. (Owner 2026-08-30, and see the ledger-edit rule in
    AGENTS.md § Documentation.)
  - **The strongest version, and the difference between a filing cabinet and a guard:** round close RUNS
    each row's `regen` and diffs the values as a reviewed change. Then a stale figure is impossible rather
    than discouraged. Sequence it after the cheap half if the cost is real — measure it, do not assume it.
