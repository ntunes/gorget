- **🆕🧹 [MEDIUM — a live Layering-rule-2 smell and the natural migration point for the indirect-dispatch chokepoint; raised by the R47 Track B scout and by two brief-review passes before being filed] `FunctionBuilder::call_indirect` (`src/ir/builder.rs`) has ZERO callers.**
  - **VERIFIED at `f3feea79`:** `grep -rn '\.call_indirect(' src/` → empty; the rustc-rename witness (rename the definition line, count `E0599`s) yields **0** sites. Meanwhile `Instruction::CallIndirect` is fully plumbed — constructed in `src/ir/transforms/shared_async.rs`, and lowered in `src/lir/lower/insts.rs` — through liveness, validate and the printer.
  - **THE SMELL.** The IR already has a typed representation for "the callee is a runtime value", and the lowering does not use it: all nine indirect-dispatch arms manufacture a mangled NAME (`__callable_N`, `__gorget_closure_call_N`, `__Closure_N__call`) and emit a plain `Call`, leaving the backend to recognise the spelling. That is a runtime-resolved callee crossing a layer boundary as a name — devbook/24 rule 2, the exact shape the "No name matching" section forbids.
  - **THE MIGRATION POINT NOW EXISTS.** R47 Track B routed all nine arms through `LoweringContext::call_indirect_tracked` (`src/ir/lowering/context.rs`), so the change of representation is now a single-function edit plus the LIR/BIR/backend work behind it, rather than nine scattered ones. Whoever takes this should start there and check what `insts.rs` promotes by name today.
  - ⭐ **R49 TRACK A1-IDENTITY CONFIRMS THIS IS THE CLASS-RETIRING FORM, AND MEASURED WHY NOTHING SHORT OF IT IS.** A1-IDENTITY closed a live miscompile at `src/lir/lower/insts.rs` — `!func.contains("__call")`, a SUBSTRING test against a MANGLED USER METHOD NAME, so `equip Runner: int call(self, Callable[int(int)] f, ...)` left its closure argument unpacked: exit 139 on a capture-less closure and SILENT WRONG OUTPUT (`7028` where ggdef says `7063`, rc 0, ASan AND UBSan silent) on a capturing one. Three typed carriers landed (`TypeMetadata::closure_call_fn`, `StructDef::closure_call_fn`, `ir::Function::takes_env`). **They did NOT retire the class**: with the carriers in place, an `assert_eq!` probe comparing `func.contains("__call")` against the typed answer still COMPILES and still FIRES, and a one-line `const CALL_MARK: &str = concat!("__", "call");` hoist restores the miscompile with `cargo test --test lints` fully green. **A carrier ADDS a typed route; it does not make the old fact UNAVAILABLE.** Only carrying the callee's identity ON THE INSTRUCTION does that — which is this item.
  - **THE BACKSTOPS THAT DO EXIST, so whoever takes this knows what is already held:** the behavioural fixture family `tests/fixtures/closure_arg_user_method_named_call*.gg` (asserts STDOUT, red under the const-hoist evasion) and the bookkeeping ratchets `no_growth_in_closure_identity_name_matching` / `..._self_host_...` in `tests/lints.rs`, which are labelled as bookkeeping precisely because of the measurement above.
