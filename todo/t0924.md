- **🆕🚧 [HIGH — A GATE THAT NO-OPS IN THE PROFILE EXECUTORS RUN, demonstrated by a live breach it let through 2026-08-31] `RUNTIME_DIFF_NONMATCH_CEILING` is never evaluated by `cargo test --test integration self_host`.** The assert sits behind `if cfg!(debug_assertions) { eprintln!("… ceiling skipped …") } else if parity_floor_active(..) { assert!(..) }` (`tests/integration.rs`, locate by the constant). `cargo test` is a DEBUG build. So the branch every track's own gauntlet takes prints a note and moves on.
- **THE BREACH THAT PROVED IT.** R48 Track C added nine top-level `tests/fixtures/*.gg`. Two of them do NOT match on the self-host lane (`todo/t0922` CC-FAIL, `todo/t0923` wrong output) and would have pushed non-MATCH past the FROZEN ceiling of 151 — which Core #9 ⊕ forbids for a round's own inflow, with no exemption. The track's `self_host` family run was **green**. The breach was found by a human output review running `self_host_emit_cc_run` by hand over the nine fixtures. **Core #13: a gate that has never been seen to fail is not evidence — and this one cannot fail where it is run.**
- **Why the skip exists, and why that reason does not justify the current shape.** The comment cites "the same timeout-flip sensitivity as the MATCH floor": under a loaded debug build, self-host fixtures time out and read as non-MATCH, so the ceiling would flap. That is a real hazard for the *count*. It is not a reason for the gate to be SILENTLY VACUOUS — a flappy gate and an absent gate look identical from inside a green run.
- **Three candidate fixes, cheapest first.**
  1. **Make the skip loud and make the obligation explicit** (landed 2026-08-31 as a stop-gap): the note now says `THIS IS A NO-OP, NOT A PASS` and names the adder's obligation. Prose, so it rots — this item stays open.
  2. **An add-time membership check that does not need the corpus.** The expensive part is running 2000+ fixtures through the self-host lane; deciding whether a round ADDED a top-level fixture is `git diff --name-only <round-open>..HEAD -- tests/fixtures/*.gg`. A lint that fails when a NEW top-level fixture has no corresponding self-host verdict recorded would catch this class at the same cost as any other lint. This is R48 Track E-B3's declared-membership idea applied to the parity corpus rather than to ggdef's.
  3. **Arm the ceiling in debug behind an env gate** (`GG_PARITY_CEILING=1`) and run it once per round, so the flap risk is opted into rather than the gate being opted out of.
- **⊕⊕ THE CENSUS ASKED FOR BELOW IS DONE, AND THE ANSWER IS WORSE THAN THIS ITEM STATES (measured 2026-09-02, R48 round-close battery). ALL SIX assertions in `self_host_runtime_diff` are `cfg!(debug_assertions)`-skipped, so in a debug sweep the test adjudicates NOTHING.** Enumerated at HEAD by reading the function body: `tests/integration.rs:38962` (new-NONDETERMINISTIC set) · `:39120` `GGDEF_ADJUDICATED_FLOOR` · `:39190` (two asserts) · `:39399` `RUNTIME_DIFF_MATCH_FLOOR` · `:39538` `RUNTIME_DIFF_NONMATCH_CEILING` · `:39596` no-new-hangs. Every one takes a skip branch under `cargo test --test integration`.
- **⛔ AND THE TEST WAS MADE DEFAULT-ON *FOR THE ROUND-CLOSE BATTERY* — its own header says so.** `tests/integration.rs:38646`: the gate was flipped opt-OUT (owner 2026-08-22) because "AGENTS.md never named `GG_RUNTIME_DIFF`, so the round-close battery could be GREEN on every listed target while this ceiling assert never executed at all", and "the round-close battery is where this is meant to bite". It does not bite there: **AGENTS.md § Round lifecycle step 4 runs the C sweep in DEBUG**, so the round-close battery pays the test's full cost and evaluates none of its assertions. Only the separate documented `--release` invocation arms any of them. The default-on change fixed the *named* silencer and left a second one in place.
- **⊕ COMPOUNDED BY A DOCUMENTED-PROCEDURE CONFLICT, also measured this round.** Step 4 mandates the C sweep with `GG_TEST_TIMEOUT_SECS=600`. The parity harness's own regen note (`tests/integration.rs:39258`) says the opposite in as many words: *"leave `GG_TEST_TIMEOUT_SECS` at its default — 600 makes each hang-class fixture stall a worker 20x longer for identical counts."* `EXPECTED_HANGS = {async_select}` (`:39590`), and at R48 close its child `async_select_diff` sat idle for the full 600s where the default would have cost 30s. So the battery's own recipe makes its longest leg ~20x slower on the hang class to produce numbers nothing evaluates. **Fix BOTH halves together: either step 4 stops setting the per-test knob, or the parity test reads its own deadline — and the assertions need to be armable in the profile the battery actually runs (candidate 3 above).**
- **⊕ The same shape is worth auditing elsewhere.** `parity_floor_active` and the `cfg!(debug_assertions)` pattern guard more than one number in `tests/integration.rs`; census them and say for each whether the gate can fail in the profile a track runs. A gate that can only fail in a profile nobody runs before integrating is a comment, not a guard (Core #6).
