- **🆕🐛 [MED — A CASE WITH NO SUBJECT (SIX-Q #4): the rule that would fix it never gets to run. Found 2026-09-05 by R50 Track A2's brief-review pass 4, MEASURED by its executor.]**

  ```gorget
  newtype Set(String)     # print(s.0) -> prints `hi`, rc 0 ... and the emitted C
  newtype Dict(int)       # print(d.0) -> prints `7`,  rc 0     warns about GorgetMap
  ```

  **MECHANISM.** `rewrite_expr` opens its constructor-rewrite block with

      const COLLECTION_TYPES: &[&str] = &["Vector", "Deque", "Dict", "HashMap", "Set", "HashSet",
          "Box", "Channel", "Arena", "TrackingAllocator", "PoolAllocator", "TlsfAllocator",
          "FixedBufferAllocator", "FallbackAllocator"];
      if COLLECTION_TYPES.contains(&cname.as_str()) { return; }

  — a **STRING COMPARISON standing in for a typed question** ("is this callee a runtime-backed collection?"), and it fires **before** the `def.kind` gate. So a user `newtype`/`struct` named `Set`, `Dict`, `Box`, `Arena`… never reaches the gate at all. ⛔ **NO WIDENING OF THE `DefKind` GATE FIXES THIS — there is no subject for the rule to apply to.** The typed axis already exists and is already used elsewhere for exactly this question: `TypeMetadata::collection_kind`, whose own doc says it *"replaces name-prefix matching"*.

  **MEASURED at R50 Track A2's tip, not inferred** — both programs build rc 0 and print the RIGHT answer, and both are **accidentally correct** (SIX-Q #6):

      GG_VALIDATE_CTOR_LOWERING=1 ./target/debug/gg build <f>.gg 2>&1 | grep -E 'ctor-lowering|NOT-INIT'
      newtype Set(String)  ->  NOT-INIT @main bb0 i0 -> Set  (TypeDef kind Struct)
      newtype Dict(int)    ->  NOT-INIT @main bb0 i0 -> Dict (TypeDef kind Struct)

  ⛔ **AND THE `Set` CASE IS ALREADY LEAKING INTO THE RUNTIME TYPE.** Its emitted C carries `warning: missing initializer for field 'entries_keys' of 'GorgetMap'` — the user's `Set` is being conflated with the runtime map struct at the C-emit layer. It prints `hi` because a `String` payload survives the punning, not because the lowering is right. **That is one field-layout change away from a silent wrong value, and nothing in the corpus tests any of it** (zero fixtures declare a type whose name collides with a `COLLECTION_TYPES` entry).

  ⭐ **A2's `GG_VALIDATE_CTOR_LOWERING` census SEES this class** (`src/ir/validate.rs::validate_ctor_lowering`) — it is the same "a construction that never became an init instruction" defect, reported from typed state. It is the fix-verifier: when the early-return is keyed on `collection_kind` instead of the name list, these two programs go to `not_init=0`.

  ⚠ **DISCRIMINATOR vs `t1375` (closed by A2):** that was the `DefKind` gate REJECTING newtypes it should have admitted. This is a name-list early-return that stops the gate from ever being consulted. Same downstream damage, different reason, and A2's fix does not touch it.

  ⚠ **DISCRIMINATOR vs `t0691`:** that one is the f-string wrapper changing the lowering of an inline constructor. Same census, same class, different cause — do not merge them.

  **INTENDED:** the early-return asks the typed question (`collection_kind.is_some()` on the resolved def), so a user type that merely shares a builtin's spelling is rewritten like any other constructor. Owes a `known_gaps` repro per collision family once the direction is settled.
