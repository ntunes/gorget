- **🆕🐛 [MED — LEAK, `gg check` clean and stdout CORRECT; found 2026-08-29 by R47 Track E2's brief-review pass 1, re-measured by the executor at the same HEAD] A droppable TEMP minted inside a LOOP CONDITION leaks once per iteration.** `while vs.iter().all(is_long) and guard < 1:` — the condition block is RE-EVALUATED every iteration and `Vector__GorgetString__iter` deep-clones the backing array each time, but drop elaboration emits a single drop at function exit, so every evaluation but the last drops its iterator on the floor. Measured: `detect_leaks=1` (`LSAN_OPTIONS=use_stacks=0`) reports **75 byte(s) in 3 allocations, 3/3 runs**, frames `gorget_array_clone` ← `Vector__GorgetString__iter` ← `main`; `detect_leaks=0` exits 0 and stdout is correct.
  - **⚠ DISTINCT CLASS from R47 Track E2's for-loop producer sites, which is why it was filed rather than folded into that track.** Different file and pass (`src/lir/drop_elab.rs` — LIR drop *elaboration*, not GIR for-loop lowering), different subject (a compiler temp of ANY droppable type in ANY re-evaluated header block, not an iterator-protocol binding), and a different fix shape (the temp's slot is re-stored each iteration — nothing about it is "decide ownership + register at the producer"). Track E2's fix landed and this shape still leaks at the same byte count, which is the confirmation that the two are independent.
  - **NO EXISTING ITEM'S SUBJECT IS THIS CELL.** `drop_loop_reinit` appears in `t0725` and `t0599` only as a *blocker mention* on the producer-side validator's fatal stage, never as the subject; `t0392`'s RV-H is a `while`-condition **use-after-move** accept, a checker defect on a different axis. `src/lir/drop_elab.rs`'s own comment says *"the loop-reinit pattern (iter N moves slot, iter N+1 re-stores) is handled by step 3's SlotStore arm — see `drop_loop_reinit.gg`"*, and that fixture samples the loop **BODY** cell; the **CONDITION** cell had no fixture in the tree until this filing.
