- **🆕🛡 [LOW — PRE-EXISTING DEGENERATE CASE IN THE LEAK ADJUDICATOR'S TWO-FILE `awk`. Filed 2026-09-06 by R51 Track J's executor; found by that track's fourth brief-review pass, NOT introduced by it.]** `adjudicate_leaks` partitions its two input files with the classic `FNR==NR` idiom. That idiom is **wrong for an empty first file**: with a zero-length allowlist, `FNR==NR` is true for the first records of `verdicts.tsv` as well, so verdict rows are ingested as allowlist rows.

  **Unreachable today**, and the guard that keeps it so is not in this script: `tests/lints.rs`'s `LEAK_CEILING` is an `assert_eq!(251)` on the allowlist's row count, so an empty `tests/sanitize/LEAK_ALLOWLIST.txt` reds the suite before any sweep runs. A `LEAK_LIST=` override pointed at an empty file would reach it.

  ⊕ **`todo/t1360`'s fix made the degenerate outcome SAFER, not worse.** Under the old adjudicator the mis-partitioned rows landed in `fixed_leak` and printed delete advice; they now land in `absent`/`unmeasured` and the gate exits 1. That is why this is LOW and not a blocker — the failure mode is a confusing red, not a silent instruction to discard evidence.

  **The fix is the standard one:** partition on `ARGIND == 1` (gawk) or on an explicit `-v` sentinel set between the two files, rather than on `FNR == NR`.
