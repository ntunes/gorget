- **🆕🚨 [HIGH — THE SINGLE-OWNER CARVE-OUT HAS A HOLE THE SIZE OF EVERY GENERIC ADAPTER. Found 2026-09-05 by R50 Track E's brief-review pass 2, which measured the two halves side by side.]**

  ```
  concrete `Callable[int(int)]` param -> struct field init   ->  E_MoveWithoutOperator  (REJECTS)
  generic `F`           param -> the same position           ->  silently ACCEPTED
  ```

  **Same position, same ownership boundary, opposite answers — and the difference is only whether the type was spelled concretely.** `needs_explicit_move`'s `ResolvedType::Generic` arm matches a fixed list of concrete names, so **a generic parameter bound to a single-owner type is invisible to the check** (regenerate: `grep -n 'fn needs_explicit_move' -A25 src/semantic/safety/type_utils.rs`).

  ⭐ **THIS IS THE WRITE SITE BEHIND `todo/t1349`** — the six `lib/std/iter.gg` adapters store a borrowed `Callable` into a returned struct with no clone precisely because their parameter is a generic `F`. **Fixing this closes that class at the source rather than at six call sites** (Core #1, Core #4).

  ⛔ **IT IS A NEW REJECTION ⇒ Core #9 BINDS ALL THREE LANES** (ggdef, Rust gg C+LLVM, self-host) in the same round, with a NEG fixture per rejected position. **Sequence it deliberately:** until it lands, a fix that frees closure-argument temps at the plain-call site **turns a leak into a use-after-free** for any program that retains a borrowed `Callable`.

  ⚠ **NOT AN OWNER ASK.** The deciding rule is ratified and `AGENTS.md` already states plain-call `Callable` params *"are simply borrowed"*; what is missing is the compiler's ability to see a generic parameter, not a ruling.
