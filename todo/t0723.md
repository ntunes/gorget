- **🆕🚨 [HIGH — A GATE THAT CAN NEVER GO RED: `--sanitize` is a SILENT NO-OP on the LLVM backend, which makes every "ASan-clean on LLVM" claim in this project's history VACUOUS. Found 2026-08-29 by the R46 Track C brief-review pass 1, orchestrator-verified at HEAD.]**
  - **VERIFIED AT HEAD.** `fn compile_llvm_pipeline(ll_path, exe_path, _ll_code, concat_source, lir_module, release)` (`src/main.rs:1393`) **takes no `sanitize` parameter**, and `-fsanitize` occurs **0 times** in its body (`:1393-1679`) against **4** occurrences on the C path. Measured by pass 1: an LLVM `--sanitize` binary has **zero ASan symbols and does not link `libasan`**, while its C twin has 16 and links `libasan.so.8`.
    ```
    grep -n 'fn compile_llvm_pipeline' src/main.rs
    sed -n '1393,1679p' src/main.rs | grep -c fsanitize     # 0
    grep -c fsanitize src/main.rs                            # 4 (the C path)
    ```
  - **WHY THIS IS WORSE THAN A MISSING FEATURE.** The flag does not error, warn, or decline — it hands back a binary that looks sanitized and is not. Any leak or UAF probe run as `--sanitize --backend=llvm` comes back **clean regardless of the defect**, so a reviewer reasonably reads it as lane parity. Pass 1 measured three known-leaking repros as clean on LLVM at HEAD, *before any fix*. **A gate that cannot go red is not evidence** (Core #13), and this one has been silently green for an unknown period.
  - **IMMEDIATE CONSEQUENCE FOR IN-FLIGHT WORK.** Any acceptance bar reading "zero sanitizer residual on **both lanes**" is unsatisfiable-as-intended: the LLVM half is free. `tests/security.rs` never passes `--backend`, so `--test security` is a **C-only** gate today — its name implies a coverage it does not have.
  - **DISPOSITION — two defects, both owed.** (a) Wire `-fsanitize` through the LLVM pipeline so the flag means what it says; (b) until then, `--sanitize --backend=llvm` must **fail loudly** rather than silently succeed (Core #10: never silently drop what the user asked for). Then re-examine any historical claim of LLVM ASan cleanliness — they are not evidence.
  - **GUARD (the deliverable, not just the fix).** A positive control: a fixture with a known leak, built `--sanitize --backend=llvm`, must be observed to FAIL. A sanitizer gate that has never been seen to go red on the lane it claims to cover is exactly the class this item exists to retire.
