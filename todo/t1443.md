- **⚖🆕 [HIGH — AN UNRATIFIED SEMANTICS QUESTION, AND THE FIX FOR `t1410` WOULD HAVE RATIFIED IT BY FIXTURE. Found 2026-09-05 by R50 Track L's brief-review pass 4, which refused an instruction in the brief telling it the direction was settled.]**

  **Measured at HEAD, same program, same overflow:**
  ```
  0 - INT64_MIN   ->  trap[T_Overflow]: integer overflow
  -INT64_MIN      ->  -9223372036854775808     (silent wrap, NO trap)
  ```

  **THE ASYMMETRY IS STRUCTURAL.** `GirBinOp::Sub` lowers to `Inst::Sub { …, overflow: default_overflow }`; `GirUnOp::Neg` lowers to `Inst::Neg { dst, ty, operand }` — and `Inst::Neg` **carries no `Overflow` field** (regenerate: `grep -n 'Neg {' src/lir/mod.rs`). ⇒ **it has no policy at all**, which is why nobody chose this behaviour.

  ## ⚖ WHY THE RECORD DOES NOT SETTLE IT

  - **`D30` lists the fix's own choice among its REJECTED alternatives** — *"defined-wrap (**silent corruption + inconsistent with int's trap**)"*. Making `Neg` defined-wrapping adopts exactly that.
  - ⛔ **AND `D30`'s PREMISE IS INCOMPLETE, WHICH IS WHY THE HOLE WENT UNNOTICED.** It rests on *"64-bit `int` overflow already trapped `T_Overflow`"*. **Unary negation IS a 64-bit `int` overflow that does NOT trap** — the counter-example to its own premise.
  - ⛔ **BUT `D30`'s SUBJECT IS THE NARROW PATHS**, and `-INT64_MIN` is not narrow ⇒ **SIX-Q #4: a case with no subject.** No widening of D30 reaches it.
  - **Unary negation's OVERFLOW semantics appear NOWHERE in the ledger.** `grep -in 'negation\|unary minus' docs/define-gorget/decisions.md` → 3 hits, all about `**` precedence (`-2**2 = -4`), none about overflow.

  ⛔ **AND Core #8 APPLIES DIRECTLY: BOTH BACKENDS AGREE ON THE WRAP.** *"Both backends agree"* is **necessary, not sufficient** — if the agreed-on behaviour is wrong, both compilers change.

  ## ⚖ THE QUESTION

  **Does `-INT64_MIN` trap `T_Overflow` (consistent with `0 - INT64_MIN`, and with D30's stated reason for rejecting defined-wrap), or is it defined to wrap?**

  ⚠ **DO NOT PIN THE CURRENT VALUE IN A TOP-LEVEL FIXTURE UNTIL THIS IS RULED** — a top-level fixture auto-enters `runtime_parity_corpus` and the sanitize sweep, so pinning `neg64=-9223372036854775808` **ratifies by fixture**. `known_gaps/` is where a value that may flip belongs.
