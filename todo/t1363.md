- **[LOW — LAYERING RULE 3 ("one source of truth per axis") vs. a MEASURED cost. Not a behavioural defect: no known program is wrong because of it.]** CoW borrow provenance lives in two stores that the two severance mechanisms read separately. Regenerate the counts uncapped:

  ```
  grep -rn "set_cow_borrow_source(builder" src/ --include='*.rs'   # writers, sidecar
  grep -rn "\.cow_borrow_source(" src/ --include='*.rs'            # 8 LIVE READERS (lazy rescue)
  grep -rn "set_collection_ref(" src/ --include='*.rs'             # writers, typed origin
  ```

  ⛔ **DO NOT "FIX" THIS BY DELETING THE SIDECAR.** An earlier note in the record claimed it "is never read"; that is true only of `cow_collection_refs_for_id` (which matches on `l.ownership` alone) and **false generally** — the readers above are live and serve the lazy-rescue mechanism. An executor told the sidecar is unread would delete working code.

  ⛔ **AND THE OBVIOUS UNIFICATION WAS MEASURED AND IS A LOSS.** Unioning the sidecar into `cow_collection_refs_for_id` is **behaviourally green** (222/222 `cow_` integration tests) but costs **`array_clone` +22.6%**, `total_allocs` **+6.9%**, wall **+14%**, peak RSS **+1.6%** — real cost, **zero measured behavioural gain**. Anyone re-deriving that number is repeating work already done; the point of this item is that the cheap version of the unification is the expensive one. A genuine fix has to make the eager walk see the sidecar's borrows *without* widening what it materializes, which is a design question, not a refactor.

  ⊕ **The DOCSTRING half of this was fixed in R50 Track F1r** and is not part of the remaining work: `BorrowOrigin::CowBorrowPending` in `src/ir/mod.rs` used to claim a later `set_cow_borrow_source` *"upgrades the entry to CollectionElement / FieldPath"*, which contradicted both the setter's own docstring and its body (Core #14 rot). It now states the actual contract.
