- **🆕⚖ [HIGH — `D41`'s ENFORCEMENT HAS AN IN-TREE CASUALTY AND NOBODY HAS RECORDED IT; found 2026-09-05 by the orchestrator answering an owner question about prior use of user-writable `Ref[T]`]** `D41` (owner 2026-07-22, ledgered 2026-08-04) ratifies **"NO STORED BORROWS, NO USER-VISIBLE `Ref[T]`"** and its own ledger entry says **STATUS: partly shipped … the accept/reject change is UNBUILT** and *"owes all lanes per Core #9 when it lands."* **When it lands, it makes the shipped stdlib illegal.**
- **THE TWO ROLES `Ref[T]` PLAYS IN `lib/std/iter.gg`, and only one is a problem.**
  - **PERMITTED — `extern` PARAMETERS (10 sites).** `Ref[Dict[K,V]]` / `Ref[Set[T]]` on `__dict_iter_*`, `__set_iter_*`, `__*_drain_entry`. This is *"views internal to builtins"*, exactly what `D41` allows. The file's own note: *"`Ref[…]` (not `… &`) matches the iter accessor convention."* **Leave these alone.**
  - ⛔ **THE CONFLICT — STORED BORROW FIELDS (4 sites).** `SetIter[T].source: Ref[Set[T]]`, `DictIter[K,V].source: Ref[Dict[K,V]]`, and two more. Deliberate and documented: *"walking the underlying `GorgetMap` bucket array in place via a `Ref[Set[T]]` borrow field — no `.items()` materialisation."*
  - **REGENERATE:** `grep -nE "^\s+Ref\[" lib/std/iter.gg` (fields) vs `grep -nE "extern .*Ref\[" lib/std/iter.gg` (permitted).
- ⛔⛔ **OWNER 2026-09-05 — DO NOT FIX THIS NOW, AND PERFORMANCE IS A HARD CONSTRAINT ON ANY FIX.** Verbatim:
  *"although possibly illegal, it is working **very** well. It is **FAST**. I do not want to replace the
  illegal stored borrows with something that deteriorates its current performance. Whatever we replace it
  with, must be equally fast. So let's design this right. We need to find a solution."*
  ⇒ **This item is a DESIGN problem, not a cleanup.** The stored borrow is not sloppiness — **it is the
  fast path, and it is load-bearing.** ⛔ **A track that swaps the field and ships is a REGRESSION even if it
  is legal.** ⚠ **The "fix" below is a SKETCH, NOT A PRESCRIPTION — it is unmeasured, and the owner's
  constraint is exactly that it must be MEASURED before it is believed.**
  ⭐ **THE BAR: equal speed, measured — not "should be free under CoW". Any candidate ships a benchmark against
  the stored-borrow baseline on Dict and Set iteration** (`iterator_lazy_chain`, `iterator_adapters` and the
  `tensor_*` / `dataframe_*` HOF corpus are the live workloads), **with peak RSS alongside wall-clock per
  Solution Quality.** If it is slower, it is not the answer.
- ⭐ **THE ASYMMETRY IS THE WHOLE FINDING — AND A CANDIDATE SHAPE IS ALREADY IN THE FILE (UNMEASURED).** `VectorIter[T].source` is **`Vector[T]`**, not a `Ref`: an owned/CoW-aliased value walked by index. **Vector iteration already obeys `D41`; Dict and Set do not.** ⇒ **Hold `Dict[K,V]` / `Set[T]` in the field and pass `&self.source` at each extern call.** The externs keep their `Ref[...]` parameters (permitted role), the stored borrow disappears, `D41` holds with **no exception**, and the iterator inherits CoW's own invalidation rules instead of needing a lifetime system.
- 🚨 **WHY IT WAS NOT WRITTEN THAT WAY, AND WHY THIS BLOCKS ON THE COST AXIS.** The comment says *"no `.items()` materialisation"* — they were avoiding a copy. Under CoW default-borrow a `Dict` field is an **alias**, not a copy — **unless the constructor's ownership boundary forces a clone**, which is precisely the unanswered question in `docs/internals/cow-cost-contract.md`. **The iterators stored a borrow because the cost model did not yet promise them a free alias.** ⇒ **Ratify the cost contract and the legality violation MAY dissolve; ship `D41`'s enforcement first and the stdlib breaks.** The ORDER matters and it is the opposite of the obvious one. ⚠ **"May" is deliberate: a free alias is what the cost contract would PROMISE, and the owner's constraint says the promise has to be MEASURED on this workload before anyone relies on it.**
- ⊖ **A `SelfRef[T]` "view-of-self" type does NOT reach this case.** These iterators borrow a **foreign** collection, not their own storage, so an intrusive self-reference type is the wrong shape. Read as *"a borrow whose provenance is pinned to a named owner"* it is a lifetime system in miniature — the exact machinery the ledger's own `*boxed` argument says Gorget declines to import (*"the ergonomic shape but not the type-system machinery that keeps it honest"*). ⊕ **Where it WOULD be sound is narrower and worth naming separately:** a struct holding a view into **its own** allocation, where the lifetime is *structurally* guaranteed because view and owner are one object. That is a real checkable property and it is **not** what the iterators need.
