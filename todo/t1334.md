- **🆕🧹 [LOW — LAYERING RESIDUAL, no known user-visible misbehaviour; surfaced 2026-09-05 by the R50 Track C2 brief-review gauntlet while closing `t0045`]** `IndexLoad`'s element handling in `src/lir/lower/insts.rs` derives the element type NAME by string surgery on the monomorphized collection name:

  ```rust
  let elem_type_name = base_type_name
      .strip_prefix("Vector__")
      .or_else(|| base_type_name.strip_prefix("Deque__"))
      .or_else(|| { /* Dict__K__V → everything past the second "__" */ })
      .unwrap_or("");
  ```

  That reconstructed string is then the KEY for `clone_fn_for_collection_element`, `infer_drop_strategy`, `is_refcount_clone_type_name` and — as of `t0045` — the `TypeMetadata::borrow_view_fn` lookup.

  ⚖ **SCOPE THE CLAIM HONESTLY, WHICH IS WHY THIS IS LOW AND NOT A BUG FILING.** `t0045` fixed the Core #2 violation at the **DECISION**: which borrow primitive to emit is now read from a typed axis instead of matched against a runtime symbol's spelling. It did **not** fix the **KEY**: the type IDENTITY that axis is looked up by is still name-reconstructed. This is pre-existing — `clone_fn_for_collection_element` and the drop-strategy inference have always keyed off it — and `t0045` neither introduced nor widened it. It is filed so the residual is recorded rather than silently inherited by the next reader of that (now typed-looking) lookup.

  ⚠ **THE SILENT-WRONG-ANSWER SHAPE TO WATCH:** the fallback is `unwrap_or("")`, so a base name that matches none of the four prefixes yields an EMPTY key rather than an error — every downstream lookup then misses and takes its default. A `_ => default` on a type-identity decision is the Core #10 shape (lower-or-reject) one layer down.

  **INTENDED:** the element type identity crosses into LIR as typed metadata on the collection's type definition — resolved once, upstream, where the monomorphization actually knows the element type — and the LIR reads it through one accessor (devbook/24 rules 2 and 4: typed metadata, not name-matching; resolve once, write through). The litmus test in that doc names this exact shape: *"if a downstream pass reconstructs information from names … the boundary upstream was drawn wrong."*
