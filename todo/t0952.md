- **🆕🐛 [MED — a LEAK *and* an O(n) deep copy per iteration step, from ordinary safe syntax, BOTH backends, `gg check` clean; found 2026-09-03 by R48 Track T-a1 while ASan-attributing the three rows that round admitted to `tests/sanitize/LEAK_ALLOWLIST.txt`] `DictIter[K, V].next()` deep-clones the WHOLE Dict four times per call and frees none of the copies.**
  ```gorget
  Dict[String, int] m = {"x": 1, "y": 2, "z": 3}
  int total = 0
  for k, v in m.iter():
      total = total + v
  print(f"{total}")           # prints 6, leaks 10062 bytes in 78 allocations
  ```
  **WHAT THE EMITTED C SHOWS.** `lib/std/iter.gg:863-878` declares `struct DictIter[K, V]: Ref[Dict[K, V]] source` — a BORROW — and its `next()` reads that field four times, once for each of `__dict_iter_order_len` / `__dict_iter_order` / `__dict_iter_key` / `__dict_iter_value`, every one of them an `extern` whose FIRST parameter is *also* declared `Ref[Dict[K, V]] m` (`lib/std/iter.gg:49-52`). Correct answer at all four positions: PASS THE POINTER THROUGH. Emitted instead, four times over:
  ```c
  __v4 = *(void**)(&self->source);   /* the Ref's pointer */
  __v6 = gorget_map_clone(__v4);     /* a full deep copy of the map */
  __s4 = __v6;
  __v8 = gorget_map_iter_order_len(&__s4);   /* …to read a length */
  ```
  No `gorget_map_free` is emitted for any of the four.
  **THE WRITE SITE.** `auto_clone_if_ptr` (`src/ir/lowering/context.rs:3098`, the `match self.ptr_materialization_kind(inner)` at `:3142` and its `PtrMaterialization::Clone` arm, `ImplicitCloneReason::CallArg`). Confirmed by instrument, not by reading: `gg build --clones=all` on the minimal cell reports exactly one implicit clone, `Dict[String, int] call argument … gorget_map_clone`. That helper asks `ptr_materialization_kind(inner)` and **never asks what slot the value is going into** — the file's own comment at `:2786-2795` says the `Ref[T] → T` question "is handled at the sites that know their target", and a call whose PARAMETER is declared `Ref[T]` is exactly such a site and does not ask. There is already a precedent for asking: the `is_string_type(inner)` early return immediately above (`:3139`), whose comment admits it is *"a type-identity test standing in for typed metadata"*.
  ⚠ **THE ARM DOES CALL `register_local(cloned, …)`, so "the temp is unregistered" is NOT the whole story** — something downstream loses the obligation (the callee takes a borrow and does not consume it, so a `mark_moved` on the argument temp would delete the only drop). Re-measure before acting; the CLONE ITSELF is the primary defect and removing it retires the leak with it.

The 2-vs-3-entry row proves the RECORD count is `4 clone sites × 3 allocations inside gorget_map_clone` and is independent of the Dict's size — only the BYTES scale.   **THE SIBLING SET (Core #4).** `lib/std/iter.gg`'s own comment says `DictKeysIter` / `DictValuesIter` *"borrow the source via `Ref[Dict[K, V]]` — identical plumbing to `DictIter`"*, and their `next()` bodies (`:906`, `:921`, `:982`) read `self.source` the same way. They are not reachable from surface syntax today (`m.keys_iter()` → `E_NoMethodFound`), so they are UNMEASURED, not proven clean. Fix the class at `auto_clone_if_ptr`, not the `DictIter` instance.
  ⚡ **PERFORMANCE, not only memory.** Four whole-Dict deep copies per `next()` makes iterating a Dict O(n²) in time and allocation, on top of the leak. `--clones=stats` on the repro is the instrument.
