- **🆕✨ [MED — RATIFIED 2026-08-11 (owner, live session; ledger `docs/define-gorget/decisions.md`), not built] The PARENTHESIZED IMPORT FORM: `from x import (a, b, c)`.** Parens suspend newline-significance inside the name list exactly as in expression context (Python-identical; PEP 8's preferred wrap). WHY: the `from x import a, b, c` name list is the language's ONE undelimited list, so in indentation-based syntax it cannot wrap — a bare name on a fresh line re-parses as a new statement (the rationale comment at `src/formatter/mod.rs`'s `format_import` says exactly this) — while every peer language ships a bracketed form. Consequences, in order: **(1) ACCEPT-SURFACE CHANGE ⇒ Core #9 cross-lane** — the Rust parser plus the three self-host parser copies, with POS/NEG conformance fixtures encoding the intended final state and a ggdef subset note (in-subset or filed as a subset gap). Backslash continuation stays REJECTED; the split-into-repeated-`from` statements workaround stops being needed. **(2) THEN `gg fmt` fill-packs import name lists at 120** through the existing `surround_fill` machinery — the grouped `import a.{X, Y}` path already does this, so the from-import path is the same call with the new delimiters, and the `format_import` no-wrap rationale comment RETIRES with it. **(3) THEN delete the width exemption** documented in `docs/book/appendix-formatting.md` §"Line width and wrapping" and in `docs/devbook/05-formatter.md`'s third-budget-escape clause, both of which currently state the exemption and point at the ratified form as its retirement. Its own small track, NOT R41's. ⚠ NOT ratified alongside it: fmt-merging adjacent same-module imports (the isort precedent) — a separate knob if ever wanted.
