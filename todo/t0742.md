- **🆕🐛 [MED — BOTH LANES AGREE ON THE WRONG ANSWER, which is a red flag and not a pass (Core #8); found R47 Track D1 while mirroring the primitive method table into the self-host] `hash()` on a primitive receiver link-errors.** `hash` is one of the four AUTO-DERIVABLE methods — every type has one — and `src/semantic/typecheck.rs::builtin_method_type`'s numeric/bool arm accepts it and types it `int`. The LOWERING has no `hash` for a primitive receiver, so both compilers emit a call to a user-method mangling nothing defines:

  ```
  RUST gg   : undefined reference to `int64_t__hash'
  SELF-HOST : undefined reference to `int64_t__hash'
  ```

  - This is a Core #10 lower-or-reject violation on the ACCEPT side, twice over: the oracle promises a method the backend cannot produce. The fix belongs in the LOWERING (give primitives a real `hash`), not in the oracle — rejecting `hash` would contradict its auto-derivable status and would break `Dict`/`Set` key hashing reasoning.
  - Repro `tests/fixtures/known_gaps/hash_on_primitive_undefined_symbol.gg`, wired `#[ignore]`d as `known_gap_hash_on_primitive_undefined_symbol`, asserting the INTENDED behaviour: it compiles and `x.hash() == x.hash()` prints `true`. (The equality rather than a literal digest keeps the pin independent of which hash function is chosen.)
  - R47 Track D1's `reject_no_method_on_primitive` deliberately ADMITS `hash` — rejecting it would diverge from the oracle in the other direction — so this repro is what says the remaining half is unfinished.
