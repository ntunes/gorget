- **🆕🐛 [CRITICAL — `gg check` passes, the binary SEGVs on BOTH backends, and `E_MoveWithoutOperator` actively steers users into it by advising `.clone()`] `.clone()` on a value-form `Callable` lowers to `Constant::Unit`.**
  ```
  Callable[int(int)] h = (int x): x + 1
  Callable[int(int)] g = h.clone()        # rc 139
  print(g(1))
  ```
  `gg check` → `OK: no semantic errors`. Emitted C: `__v4 = (int32_t)0LL;` then `memcpy(&__s3, (void*)__v4, sizeof(GorgetClosure))` — a 16-byte read from a null/unit slot. At GIR level the whole call is `_3 = const unit`.
  **ROOT CAUSE (measured, fire count 0):** the `.clone()` arm at `src/ir/lowering/exprs/methods.rs:1958` **never executes** for this shape. It sits inside `if let Some(type_name) = type_name` at `:1731`, and `infer_type_name_from_operand_full` (`:4901`) returns **`None`** for a `GirType::FnPtr` receiver, skipping the entire block.
  ⭐ **AND THAT FUNCTION ALREADY DOCUMENTS THIS FAILURE CLASS FOR A PREVIOUSLY-FIXED SIBLING** (`:4954-4956`): *"Without this, a receiver with type `I64_TYPE` gets `type_name=None` and the call site falls through to `Constant::Unit`."* The primitive arms exist because this exact bug was fixed once for `int`; `FnPtr` never got its arm. **Core #4 sibling drift, with the war story in the same function.**
  ⭐ **ggdef ADJUDICATES THIS AND GETS IT RIGHT — the oracle already knows both compilers are wrong (Core #13, Core #8).** `./target/debug/ggdef run` on this exact repro prints **`2`**, the intended answer, while Rust gg and the self-host both SEGV. `Callable` is squarely in ggdef's model (`grep -rc Callable spec/ggdef/src/` → 88 mentions; `.clone()` elaborates generically to `Expr::Clone(recv)` at `elaborate/mod.rs:2737-2741`). ⚠ An earlier revision of this item claimed ggdef abstains here; that was pasted from the D53 track, where the relevant grep was `Mutex|RWLock`.
