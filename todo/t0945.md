- **🆕🐛 [MED — Core #8 BOTH LANES AGREE ON THE WRONG ANSWER, over-rejection with a FALSE diagnostic] `c[i]` on a user generic is typed as the receiver's LAST type argument, so an unrelated type parameter decides the verdict.**
  ```
  struct Pair[K, V]:
      Vector[K] keys
      Vector[V] vals
  equip Pair[K, V] with Index[int, K]:
      K get(self, int key): return self.keys[key]

  Pair[int, Mutex[int]] p = ...
  v.push(p[0])          # p[0] is an `int`. No lock VALUE appears in this expression.
  ```
  → `error[E_MoveWithoutOperator]: cannot copy \`p\`: \`p\` is a unique lock`. **`p` is a `Pair`, and `p[0]` is an `int`.**
  **THE DISCRIMINATING EXPERIMENT, and it settles that the heuristic is wrong rather than the program:** change the UNRELATED parameter `V` from `Mutex[int]` to `String` and the byte-identical rest of the program compiles and RUNS. A verdict that moves when you edit a type the rejected expression never mentions is not a judgement about the program.
  Measured at HEAD, all three lanes: Rust `gg check` rc=1; self-host driver rc=1 (see the honesty note below); with `V = String` all lanes rc=0 and the program runs.
