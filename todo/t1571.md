- **🆕📐 [MED — THE SELF-HOST COUNTERPART OF `t1505`, AT THE SAME LAYER AND WITH A LOUDER SYMPTOM. Measured 2026-09-06 by R51 Track H's executor, four probes, with a positive control.]**

  The self-host lane **has** real `Ref` machinery and it works — `tests/fixtures/self_host_lowerer/lower_types.gg:502-511` lowers `RTRef(inner)` to `register_ptr(…)` (`GtPtr`), Rust parity. **It is not reached from a declared PARAMETER position.** There the type resolves through the mangled-name arm at `:348-357` (`return "Ref__" + resolved_to_c_name(inner_rtid, &gmod)`), and the emitted C declares an opaque nominal struct.

  **MEASURED**, self-host driver built from `tests/fixtures/self_host_lowerer/driver.gg`, invoked as `driver <probe.gg> lib --emit-c --runtime-dir=src/backend/c/runtime`, then `cc -O0 -w -o bin out.c -lm -lpthread`:

  | probe | shape | self-host verdict |
  |---|---|---|
  | `int ref_len(Ref[Dict[String,int]] m): return m.len()` | free fn | **cc error**: `incompatible type for argument 1 of 'ref_len'` |
  | `int ref_x(Ref[Point] p): return p.x` | free fn, struct pointee | **cc error** at `ref_x` |
  | `int ref_sum(Ref[Vector[int]] v)` | free fn, for-loop subject | **cc error** at `ref_sum` |
  | `int via_ref(&self, Ref[Dict] m)` + `int mutref_len(MutRef[Dict] m)` | equip method + `MutRef` | **cc error** at `Counter__via_ref` |

  The emitted C says it exactly:
  ```c
  int64_t ref_len(__gg_Ref__Dict__GorgetString__int64_t __p0);
  …
  __v46 = ref_len(__v45);   /* __v45 is a GorgetMap, by value */
  ```
  and cc: `expected '__gg_Ref__Dict__GorgetString__int64_t' but argument is of type 'GorgetMap'`. `MutRef` is symmetric — `struct __gg_MutRef__Dict__GorgetString__int64_t` at the same position.

  ⭐ **POSITIVE CONTROL, so this is not a broken harness (Core #13).** The same driver, same harness, compiles and runs `tests/fixtures/borrow_field_basic.gg` → `99|42` and `borrow_field_nongeneric.gg` → `99`, both **`Ref[T]` FIELD** fixtures, both correct; and `tests/fixtures/stdlib_iter_dict.gg` → full correct output. ⇒ the `RTRef → GtPtr` machinery is LIVE, and the failure is **specific to the declared-parameter position**.

  ⭐ **HOW IT DIFFERS FROM THE RUST LANE'S DEFECT (`t1505`).** Same layer — the parameter position does not reach the borrow-aware mapper — but the Rust lane degraded the type to `UNIT_TYPE` and **silently printed the wrong answer at rc 0**, while the self-host mints a distinct nominal type and **fails loudly at `cc`**. A loud failure is the better of the two, which is why this is MED and `t1505` was CRITICAL.

  ⛔ **NOT A CORE #9 BREACH BY R51 TRACK H, and here is the check.** That track changed a **GIR TypeId at Rust-lane declared-param sites**. Measured: the self-host driver's own emitted C is **byte-identical before and after** (`gg build --emit-c-lir tests/fixtures/self_host_lowerer/driver.gg | sort`, 1 320 540 lines each, `cmp` rc 0 — a real emission on both sides, ~82 s, not a timeout), and every probe above gives the identical verdict under a HEAD-built and a fix-built driver. The lane was already in this state and the change does not move it.

  ⊕ **AND THE SHAPE IS D41-ILLEGAL EITHER WAY.** `docs/define-gorget/decisions.md` ratifies *"`Ref` never appears in user source"*, so no conformant program can reach this. That is why it is filed rather than fixed, and why no fixture pins it: a fixture would pin a shape the ledger ratified away.

  **INTENDED:** the declared-parameter position resolves through the same `RTRef → GtPtr` path the field position already uses, so the emitted C declares the parameter a pointer — or the self-host **rejects** the spelling at check time, matching whatever reject the Rust lane lands (`todo/t1506`, gated on `todo/t1307`'s owner ask). Either answer is reference-grade; silently emitting C that cannot compile is not.
