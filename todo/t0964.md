- **🆕 [MEDIUM — DERIVED DATA WITH NO PROVENANCE; found 2026-09-03 by the R48 round-close C sweep] The 1377 `runtime_snapshots/*.out` files cannot say what they were derived from, so the lock-in net reports STALE and REGRESSED identically.**
  - **MECHANISM.** `self_host_runtime` (`tests/integration.rs:37845-37848`) compares the self-host's run output against the committed `tests/fixtures/runtime_snapshots/<stem>.out`. The snapshot stores the OUTPUT only. When a fixture's own source changes — new `print`s, widened assertions — the snapshot is stale by construction, but the net has no way to know the input moved, so it emits `<stem>: WRONG-OUTPUT (L1: oracle="…" self="…")` and panics with *"N fixture(s) regressed against committed snapshots"*.
  - **MEASURED INSTANCE.** At R48 close, `closure_mixed_implicit_explicit_wiring` reported `L1: oracle="6" self="2"`. It read as a Track U miscompile and is not one: Track U widened the fixture (`d7ce0d4ed`, `900745e10`) to print the mapped values, and the snapshot dates from Round XXXIV (`3a5808438`) when the fixture printed only two lines. **Three independent artifacts had to be cross-read by hand to establish that** — the harness's wired expectation (`tests/integration.rs:48666` = `"3\n2\n4\n6\n6"`), the fixture's own green integration test in the same sweep, and the fixture's absence from every non-MATCH bucket of the parity run.
  - **⚠ THE DANGER IS THE REMEDY THE PANIC ITSELF SUGGESTS.** The message ends *"(If the change is intended, re-seed with GG_REGEN_RUNTIME_SNAPSHOT=1.)"* — and under time pressure that is indistinguishable from laundering a real miscompile into a committed snapshot. The regen path is in fact SAFE (`:37851` writes a snapshot only for a fixture that is a STABLE MATCH — self-host twice + oracle twice, identical — so a miscompiled fixture gets no snapshot), but **nothing in the failure message says so**, and the safety is a property of the regen path, not of the diagnosis.
  - **INTENDED:** the snapshot records the content hash of the fixture it was derived from, and the net splits the two cases mechanically:
    - fixture hash MATCHES + output differs → **REGRESSION**, build-breaking, exactly as today;
    - fixture hash DIFFERS + output differs → **STALE SNAPSHOT**, named, with a per-fixture re-seed instruction.
    This is the `PINNED-BY: <sha> VALUE: <n>` pattern the clone meters already use (`tests/integration.rs:31905` and the `clone_meter_pins_carry_their_provenance` lint) — **bind a derived value to its provenance and guard the binding** — applied to the one large family of derived data that lacks it.
  - **⊕ SCOPE NOTE.** 1377 snapshot files; the hash can live in a single side manifest rather than in each `.out`, so the diff need not touch all of them. A whole-corpus `GG_REGEN_RUNTIME_SNAPSHOT=1` rewrite is the wide, low-information diff to avoid — seed the manifest once, then let it move per-fixture.
  - **⊕ SIBLINGS ALREADY FIXED, so this is the remaining member of the class.** The same disease in `tests/spec_conformance.rs` — corpus-derived literals with `>=` guards blind to corpus GROWTH — was closed at R48 close: `MIN_FIXTURES` became an exact pin and the prose relation between the four constants became three `const` asserts that fail at COMPILE time. Both were RED-verified. This item is the third instance and the only one still open.
