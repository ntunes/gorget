- **🆕📋 [LOW — OPEN DESIGN QUESTION, filed 2026-08-19 by R43 Track G because its code comment asserted a filing that did not exist] Should the AUTHOR'S ROW GROUPING be typed metadata on the AST rather than a source re-read?** `Formatter::author_line_break_between` (`src/formatter/mod.rs`) answers "did the author write a line break between these two elements" by scanning the SOURCE between their spans, exactly as its ratified sibling `author_trailing_comma` does. The alternative is for the parser to record the grouping — a `rows: Vec<usize>`, or a per-element `starts_row` flag, on the spanned nodes — and for the formatter to read typed metadata instead. **Arguments both ways, because this is genuinely undecided and not a filed defect:** FOR — Layering discipline rule 2 prefers typed metadata over re-derivation, and a source scan is where the ANCHOR bug of this round lived (a `#` inside an author grouping paren falls on the wrong side of `advance_past_author_parens`, so the probe needs two different windows; a typed field would have no windows at all). AGAINST — it pushes a FORMATTER-ONLY concern into the shared AST, which every other consumer then carries and must not disturb, and it is not one change but four: the Rust parser plus the three self-host `parser.gg` copies, each of which would need the field, the write site and its own arm-count guard. **Nobody has made the FOR argument in a design record**, which is why the shipped code comment now points here rather than claiming the question is settled. ⚠ Note what does NOT decide it: the magic comma reads source too (`author_trailing_comma`), so "the formatter re-reads source" is the ratified status quo for this class, not a novel departure. If taken up: own scout, and the deliverable is a decision in `docs/define-gorget/decisions.md`, not a refactor. No repro fixture — a design question has no failing program.
