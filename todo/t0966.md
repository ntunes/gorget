- **🆕 [MED — A GUARD THAT CANNOT CATCH ITS OWN CLASS; found 2026-09-03 by R48 Track T-a2, whose own
  diff widened it] `scripts/figures.db`'s `mirror` field is OPTIONAL WITH NO ESCAPE VALUE, so a row
  that omits it is silently never mirror-checked — and the backstop that was supposed to notice is a
  `>=` floor.**
  - **MECHANISM, in two halves.**
    1. `scripts/figures.py`'s `MULTI = ("mirror", "waiver", "input")` makes `mirror` repeatable and
       optional. `input` is separately forced to be present (`missing mandatory field `input` (write
       `input = none`)`) precisely so that "no quantified input" is a claim someone made rather than a
       field someone forgot. **`mirror` gets no such treatment**, so "this figure has no code literal"
       and "somebody deleted the mirror line" are indistinguishable.
    2. `tests/lints.rs::figures_db_mirrors_agree` ends with `assert!(checked >= 12, "…a row lost its
       `mirror` field and this lint quietly stopped guarding it.")`. That message names EXACTLY this
       failure — and a `>=` floor cannot see it once the population grows past the floor, because
       adding rows makes the assert MORE true.
  - **MEASURED at `dc0b0024b` + T-a2's diff** (regenerate by parsing the DB, not by grep — several
    rows declare two mirrors and five declare `mirror = none`):

        python3 -c "import sys; sys.path.insert(0,'scripts'); import figures as F; o,db=F.parse(); print(sum(1 for r in F.rows(db) for m in db.get(r+'.mirror',[]) if m!='none'), 'mirrors;', [r for r in F.rows(db) if not db.get(r+'.mirror')], 'have no mirror field')"

    **32 mirrors are checked against a floor of 12** — twenty rows of headroom. Four rows carry no
    `mirror` field at all (`todo.pending_items`, `clone.waste.attributed_site_hits`,
    `done_md.round_close.anchor_age_matched`, `done_md.round_close.roundish_headlines`); all four are
    legitimately DB-native, which is the point: their legitimacy is currently indistinguishable from
    an omission.
  - **⚠ THIS IS R48's OWN SIBLING DEBT, and the round already fixed two instances of it.**
    `MIN_FIXTURES` (`tests/spec_conformance.rs`) and `SELF_HOST_COMPREHENSION_CELL_FLOOR`
    (`tests/integration.rs`) were both converted from `>=` to `assert_eq!` at R48 close, each with the
    same finding written on it: *a floor catches only the DELETION half, because adding a cell makes
    `len() >= FLOOR` MORE true.* `checked >= 12` is the third site in that class (Core #4: one fix,
    all siblings — ask what stops the next site). T-a2 was fenced out of this assert and filed rather
    than edited it.
  - **THE FIX IS THE SECOND HALF, NOT THE FIRST.** Bumping `12` to the current count buys a number to
    maintain on every adoption and still cannot see a row that never had a `mirror` line. The
    reference-grade shape is to make `mirror` **required with an escape value**, exactly as `input`,
    `caveat` and `cost_secs` already are:
    - `scripts/figures.py`: reject a row with no `mirror` declaration, message in the established form
      — *"missing mandatory field `mirror` (write `mirror = none` for a DB-native figure)"*;
    - `scripts/figures.db`: add `mirror = none` to the four DB-native rows above, each already
      carrying a `home` that says it is DB-native, so the escape is a restatement and not a decision;
    - `tests/lints.rs`: the `checked >= 12` backstop then becomes redundant against THIS class and can
      either go or become an `assert_eq!` — with the schema clause in place, the count no longer
      carries the guarantee alone.
  - **RED-VERIFY IT BOTH WAYS (Core #13), and the harness for it already exists**:
    `figures_db_rows_are_wellformed` writes seven deliberately-broken declarations to a temp file and
    points `FIGURES_DB` at each on every run. Add an eighth (`figures_db_edit_line(&t,
    "fmt.max_width.mirror = ", None)` → expect *"missing mandatory field `mirror`"*). ⚠ Use the
    `figures_db_edit_line` helper, which ASSERTS its target matched — a `str::replace` on a missing
    target silently no-ops and the RED demonstration would run against an unbroken file.
  - **Sibling:** [[t0926]] owns the remaining figures-DB adoption; this is a schema defect that every
    future adopter inherits, so it is worth fixing BEFORE the next batch of rows lands rather than
    after.
