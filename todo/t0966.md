- **🆕🧹 [MED — UNBOUNDED DISK LEAK IN THE SHIPPED DRIVER, one leaked directory per `gg run`; measured 2026-09-03 at R49 open, where the accumulated residue was **161,898 directories / ~37 GB** in `/tmp`] `gg run` never deletes its build scratch directory, because `tempfile::TempDir`'s cleanup is a destructor and the command exits via `process::exit`.**
  - **MECHANISM, read at HEAD.** `src/main.rs:2596` opens the run command's scratch with
    `let tmp_dir = tempfile::tempdir()`. `TempDir` is an RAII guard: it removes the directory in its
    `Drop` impl and nowhere else. The `run` arm then terminates through `std::process::exit`
    (`src/main.rs:3081` on the success path, `:3095` on the signal path, `:3097` on the failure path,
    and ~30 earlier error exits between `:2598` and `:3097`). `process::exit` terminates the process
    **without unwinding and without running destructors** — so `tmp_dir`'s `Drop` never executes on
    ANY path through the command, success or failure. The directory, the emitted `<stem>.c` and the
    linked `<stem>` binary all survive the process.
  - ⚠ **`gg build` is NOT affected and the contrast is the discriminator.** `build` writes its
    artifact to the user's chosen output path and its tempdir is dropped normally; DONE.md's `t0840`
    entry records the consequence from the other side — *"`gg build` deletes its tempdir"* is why that
    round needed a `CC=` shim to capture the generated C. Only `run` leaks, and it leaks on every
    invocation.
  - **RED-VERIFIED 2026-09-03**, on a `/tmp` swept to zero `.tmp*` entries first:
    ```
    $ printf 'void main():\n    print("hi")\n' > /tmp/leakprobe.gg
    $ ls -A /tmp | grep -c '^\.tmp'          # 0
    $ ./target/debug/gg run /tmp/leakprobe.gg # prints: hi
    $ ls -A /tmp | grep -c '^\.tmp'          # 1
    $ ls /tmp/.tmpa9K76s                      # leakprobe  leakprobe.c
    ```
    One run, one leaked directory, holding both the emitted C and the linked executable.
  - **WHY IT MATTERS BEYOND TIDINESS — it is an operational hazard the project has already paid for.**
    The residue scales with the round-close battery, which invokes the run path across a ~2,200-fixture
    corpus on five lanes, repeatedly, every round. At R49 open the accumulation measured **161,898
    directories totalling ~37 GB**, against ~2.9 GB of all other `/tmp` content combined — i.e. the
    leak was **93%** of the scratch volume. `TODO.md`'s own handover records the cost of the same
    class in a different guise: *"crashes = disk accumulation"*, and R48 lost the F3 scout's worktree
    to a disk crash. A gate that fills the disk is a gate that eventually fails for a reason unrelated
    to the code under test.
  - **INTENDED:** `gg run` removes its scratch directory on every exit path, including the error and
    signal paths. **THE FIX SHAPE IS THE STANDARD ONE and it is a Core #1 write-site fix, not a
    read-site sweep:** do not add a reaper that scans `$TMPDIR` for orphans (that is the read side, it
    cannot distinguish this driver's dirs from another process's live ones, and it races). Confine the
    destructor-bearing scope instead — hoist the body into a function returning the exit code so
    `tmp_dir` drops at its end, and call `process::exit(code)` only after it has returned. The ~30
    intermediate `process::exit` calls inside that scope are the sibling set (Core #4): each one is a
    separate leaking path, so the fix must be the scope, not a `drop(tmp_dir)` added before each exit.
  - **GUARD (Core #6).** The class is executable-checkable: a test that snapshots the `$TMPDIR` entry
    count, shells out to `gg run` on a trivial fixture, and asserts the count is unchanged. It fails
    today and passes after, and — unlike a prose note — it also catches the next `process::exit` added
    inside the guarded scope, which is the sibling that would otherwise reintroduce the class.
  - ⊕ **CHECK THE SIBLINGS BEFORE CLOSING.** `src/main.rs:3288` and `:3510` open tempdirs in two other
    command arms; both must be shown either to drop normally or to carry the same defect, and the item
    closes only when all three are stated with a disposition (Core #15b).
