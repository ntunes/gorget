- **[LOW — the sanitize sweep covers ONE lane and ONE directory level; extending it to the LLVM lane is now possible for the first time. Filed 2026-08-29 out of R47 Track C, which deliberately scoped it out.]**
  - **THE TWO LIMITS, verified at HEAD.** `scripts/sanitize_sweep.sh` builds with `"$GG" build --sanitize "$d/$stem.gg"` and passes **no `--backend`**, so it is the default lane; and it enumerates `find tests/fixtures -maxdepth 1 -name '*.gg'`, so it never descends into `tests/fixtures/security/`, `known_gaps/`, or any other subdirectory. `CORRUPTION_CEILING` and `LEAK_CEILING` (`tests/lints.rs`) are therefore **C-lane, top-level-fixture** counts. Both facts are now stated in the ratchet comment; this item is the extension itself.
  - **WHY IT IS ONLY NOW POSSIBLE.** Before R47 Track C, an LLVM sweep would have measured nothing: `--sanitize` was silently dropped under `--backend=llvm` (t0723), so every fixture would have come back clean for free. The flag works now, which is what makes a second lane a real measurement rather than a second copy of the first.
  - **⚠ DO NOT ASSUME THE CEILINGS TRANSFER.** LLVM instruments only the runtime, not generated user code (t0727), so an LLVM sweep sees a strictly different defect set — complete leak coverage, but no user-code UAF/overflow. A second lane needs its OWN ceilings, established by measurement, not the C numbers copied across. Adding a lane to a ratchet whose numbers were derived on a different lane would be the same false-equivalence this whole area has just been cleaned of.
  - **EVIDENCE THE SECOND LIMIT COSTS SOMETHING REAL:** `t0732` is an 8-byte leak that lives in a shipped fixture under `tests/fixtures/security/`, leaks on both lanes deterministically, and is seen by **no gate in this tree** — the sweep's `-maxdepth 1` is one of the three reasons. Widening the directory scope may be the cheaper half of this item and worth doing first.
  - **SCOPE.** A new gate with an unmeasured radius. Expect to burn down whatever the first LLVM run reports before making it fatal (Core #6: env-gate → burn down → fatal), and to do the same for any new directory level.
