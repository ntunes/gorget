- **🚨 [HIGH — SILENT WRONG OUTPUT at exit 0, no diagnostic; found 2026-09-03 by the R49 Track K brief-review gauntlet, executor-verified at HEAD] `for c in s:` reads a TORN string when `s` is reassigned inside the loop.**
  - **MEASURED:** `for c in "abc": seen = seen + c; if n == 0: s = "ZZZ…"` prints **`aZZ` / `3`** on Rust gg (C). **ggdef prints `abc` / `3`** and adjudicates definitively (Core #8) — `aZZ` is not the answer under any semantics.
  - **THE MECHANISM.** `lower_for_string_with` snapshots the byte length ONCE before the header, but builds `iter_local` as an `emit_borrow` Ptr to `s`'s own slot and re-reads `->data` every iteration. Reassignment swaps the buffer while the loop keeps walking to the OLD length: length and buffer disagree.
  - **⚠ THE CASE HAS NO SUBJECT (SIX Q#4) — this is not a rule that needs widening.** `E_MutationWhileBorrowed` DOES guard this class for collections, via `self.for_loop_iterables.contains(&recv_def_id)` in `src/semantic/safety/check_expr.rs` — confirmed firing. But it lives in the mutating-METHOD-CALL arm only, and a plain REASSIGNMENT is the only way to mutate a String, so it reaches no rule at all. The guard exists and covers exactly the axis that does not need it (`for x in v: v = [9, …]` prints correctly).
  - **SECOND-ORDER, SAME FILING — a heap OOB READ, and it is TWO helpers, not one.** Shrink the source instead of growing it and the stale length walks off the end of the new buffer: `String s = "abcdefghijklmnopqrst"` with `s = "x"` at iteration 0 prints **`a` / `20`** (ggdef: the full string / `20`) — twenty iterations indexing a ONE-BYTE allocation.
    - `src/backend/c_lir/emit_types.rs` DEFINES `gorget_str_codepoint_at` with a `byte_pos` bounds check AND a `cplen` clamp, and `gorget_utf8_codepoint_len_at` with a bounds check. **Both definitions are dead.** `src/backend/c_lir/emit_call_extern.rs` emits BOTH calls INLINE with NEITHER guard, and the inline form is what the loop body uses.
    - Read off the emitted C for the probe above: the guarded definitions sit at the top of the file and the loop body calls `gorget_str_view_region((const char*)((Str*)s)->data + pos, (size_t)gorget_utf8_codepoint_len(((const unsigned char*)((Str*)s)->data)[pos]))` — raw, unguarded, twice.
    - **One behaviour, two emitters, no shared source of truth** (Layering rule 3). Fixing the torn read closes the trigger; the missing guards are the second, independent half.
  - **⚠ ASan IS BLIND** (custom `__gorget_current_alloc` pool). stdout is the instrument.
  - **NOT the `t0871` view-tag class** (which landed R49): unchanged by that tag, measured. Discriminators from `t0692`/`t0693`: String source not dict · REASSIGN not method-call · silent wrong output not ICE.
  - **INTENDED:** the loop iterates the string it started on — `abc` / `3` — or the check site rejects the reassign the way `E_MutationWhileBorrowed` rejects the collection sibling. Which of the two is the right answer is a semantics call worth an owner ask; ggdef already implements "iterate what you started on".
