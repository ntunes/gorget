- **[MED — Core #4 sibling of the awk attribution fix] `tests/lints.rs` `known_gaps_passing_allowlist_shrink_only` enumerator (`tests/lints.rs` ~22035-22056) has the same unanchored scanner `scripts/known_gaps_census.sh` had.** On `#[ignore` it sets `ign = true` and `continue`s; on `fn` it commits `cur_is_ign`; any later line containing `known_gaps/` while `cur_is_ign` is still the *previous* function is inserted into `ignored_kg` under that previous name. A `known_gaps/` string in (a) the next test's doc comment or (b) continuation lines of the next `#[ignore]` is therefore attributed to `cur`. The awk half was fixed (smoking gun: `dict_swap_remove_vector_value` inherited `dict_swap_remove_nested_resource`); this Rust mirror was out of zone for that track (`tests/lints.rs` forbidden). The lint only stores a *set of names*, so the fixture-identity collision is weaker than the awk's, but a previous ignored test that does **not** cite `known_gaps/` in its own body can still be enrolled from the next item's header. Fix: close `cur` / `cur_is_ign` when a new item starts (`#[ignore`, `#[test`, item-level `///` / column-0 `//`), matching `scripts/known_gaps_census.sh` `enumerate()`. Do not widen `enumerate()` as a substitute.
