- **🆕🧹 [LOW — a sibling-site gap the A2-α change made VISIBLE rather than created. Found 2026-09-04 by R49 Track A2-α] The two ABI-driven validator walkers have no `Instruction::CallIndirect` arm.**
  - **THE SHAPE.** `validate_resource_sites_all`'s read-site walker (`src/ir/validate.rs`, the `ReadSiteClass::CallArg` arm) and the consume-site walker (`ConsumeSiteClass::CallByValueArg`) both classify each call argument from the callee's declared `ParamABI` — `ByValue` is a shallow-copy / consuming position, `ByPtr` / `ByMutPtr` are borrow-shaped. Each has an arm for `Call` and one for `CallExtern`. `CallIndirect` falls into the `_ => {}` catch-all, so an argument passed through a `Callable[T]` slot or an escaped closure is classified by neither walker.
  - **WHY IT WAS INVISIBLE UNTIL NOW.** Before A2-α, `Instruction::CallIndirect` was never constructed — its own doc said *"reserved for future dynamic dispatch"* — and indirect dispatch was spelled as an `Instruction::Call` to a manufactured name. Those DID reach the arms, and looked the name up in `module.fn_param_abis`, where it was normally absent → skip. ⚠ **Except when the manufactured name collided with a real user function, in which case the walkers read the USER's ABI and classified the closure's arguments by it** — one more consequence of that shared namespace, now gone. So today's behaviour ("indirect calls are not classified") matches the non-colliding behaviour exactly; nothing regressed, and one wrong-classification path closed.
  - **WHY IT IS WORTH CLOSING.** The fact is now available and typed: `Instruction::CallIndirect { arg_abis, .. }` carries the callee's declared per-argument ABI, written at the one place the signature is still in scope. Both walkers could read it directly and stop skipping the class — which is the same `resolve once, write through` move A2-α made for the LIR side.
  - ⚠ **NOT A FREE CHANGE, WHICH IS WHY IT IS FILED AND NOT INLINED.** These walkers EMIT diagnostics (`validate_consume` → move/clone findings). Turning classification on for a previously-skipped instruction class can surface new findings across the corpus, so it needs a measured sweep and a disposition per new row, not a one-line arm. Size it before briefing.
  - **VERIFICATION:** `grep -n 'ReadSiteClass::CallArg\|ConsumeSiteClass::CallByValueArg' src/ir/validate.rs` and read the enclosing `match` — the absent `CallIndirect` arm is the finding. `arg_abis` is empty for the arms whose signature was never spelled (a container-element callable, an `auto`-bound one), so the fix must treat empty as UNKNOWN, not as "no borrows".
