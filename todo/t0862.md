- **[MED — owner-directed 2026-08-31, R48 candidate] `slice` MATERIALIZES AT THE READ SITE ON BOTH RECEIVERS.
  One defect, two spellings.** Owner: *"is there a legitimate reason for the Vector version to return an
  owned (materialized) value? … I would assume `.clone()` should be used by the caller if an owned value
  was required."* ⇒ **There is no semantic reason. This is a missing flag and a missing lowering, not a
  representation gap.**
  - **The contract this violates is already ratified** (`AGENTS.md` § Ownership at Consuming Positions):
    *"CoW's default everywhere is borrow… Clones happen ONLY at ownership boundaries, where the destination
    must own."* **A slice is a READ. It is not an ownership boundary.** If the caller must own, the boundary
    materializes it, or the caller writes `.clone()` and means it. Materializing eagerly on the read side is
    Core #1's signature — a fix at the read site standing in for a missing invariant one layer up.
  - **⚠ STRING — flagged a view, materializes anyway.** `src/ir/lowering/builtins.rs:854` declares
    `String.slice` with **`returns_view: true`** and callee `gorget_str_slice`; `substring` (`:853`) is
    **byte-identical apart from the name**, and `byte_slice` (`:862`) is the codepoint-vs-byte sibling.
    ⊕ **`s[a:b]` lowers to THE SAME CALLEE** — `src/lir/lower/insts.rs:1022`: *"Str[range] →
    gorget_str_slice(str, start, end)"* — yet R47 measured **1,002 clones over 1,000 `.slice()` calls
    against 2 for the identical `s[a:b]`, same results.** Same runtime function, same declared view flag,
    1000× the clones. ⇒ **The delta is in the METHOD-CALL lowering path, not the callee. FIND THAT SITE
    FIRST — it decides whether this is one producer fix or per-method metadata.** (Unlocated as of filing;
    do not scope the work before it is pinned.)
  - **⚠ VECTOR — not flagged at all, but the representation is READY.**
    `src/ir/lowering/builtins.rs:383` declares `Vector.slice` with `runtime_callee: None`,
    **`returns_view: false`**, `return_type: ret_self` — lowered structurally as a fresh collection.
    **But `GorgetArray` (`src/backend/c/runtime/runtime_preamble.c`, struct ending `:354`) already carries
    `size_t cap; // offset +8: generic view discriminator (0 = view)` — the SAME `cap==0` convention the
    String view path uses — plus `__gorget_drop_fn elem_materialize; // CoW materialize: view→owned only`.**
    And the IR state is general: `RuntimeView(LocalId)` (`src/ir/mod.rs:~635`) is typed on a plain local, not
    on strings. ⊕ Census: **zero Vector methods carry `returns_view: true`** today.
  - **⚠ THE ONE THING THAT SEPARATES "FLIP A FLAG" FROM REAL WORK — SCOUT IT BEFORE SCOPING.** A String view
    aliases an IMMUTABLE buffer; a Vector view aliases a MUTABLE one. The String decl's comment promises the
    compiler *"tracks ViewOf(receiver) and auto-materializes on source mutation"* — **it is NOT verified that
    this path fires for arrays.** If it does not, that machinery is the work, not the flag.
  - **Sequencing note:** D22 defers *step*/stride for a stated reason — *"a stride breaks the future
    offset+len CoW-share repr"*. Plain slices are unaffected; do not widen scope to strides.

    cost-contract campaign), [[t0468]] (retire sidecars), [[t0860]]/[[t0861]] (the audit and the figures DB
