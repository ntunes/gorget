- **🆕🔧 [MED — FOUR ROWS THAT CACHE A NUMBER THEIR OWN REGEN COMPUTES, AND NO ONE ENFORCEMENT SHAPE COVERS ALL FOUR. Split out of the `--bless` track after Jobs 1/2/4 landed; the mechanism they need is filed here rather than forced, because the fourth row is a different question from the other three.]**

  `scripts/figures.db` carries four rows keyed to the tree's one declared round-open anchor, the `ROUND-OPENED-BY:` line in `tests/integration.rs`: `sanitize.leak.rows.round_open`, `sanitize.leak.records.round_open`, `sanitize.leak.class_pairs.round_open` and `sanitize.leak.debt.trend`. The DB's own note on the last of them states the coupling and the gap in one sentence — regenerate it:

  ```
  grep -n 'the four move as one' scripts/figures.db
  ```

  > *"re-seed this value at round open, together with the three `.round_open` anchors; **the four move as one and nothing enforces that**"*

  **MEASURED 2026-09-09 — all four are stale, and only three of them can say so.** Regenerate each, rc off the **bare** command:

  ```
  for r in sanitize.leak.rows.round_open sanitize.leak.records.round_open \
           sanitize.leak.class_pairs.round_open sanitize.leak.debt.trend; do
    python3 scripts/figures.py check $r; echo "rc=$?"
  done
  grep -m1 -oE 'ROUND-OPENED-BY: [0-9a-f]+' tests/integration.rs
  ```

  The three `.round_open` rows each report **FAIL — measured ≠ pin**, every one against the anchor the tree declares *today*. Their `regen` reads the anchor rather than hard-coding it, which is what makes the staleness detectable at all; but `mirror = none` on all three means **no gate in the battery evaluates them**, and `figures.py check` is run by nothing (`[[t1630]]`).

  ⛔ **AND THE FOURTH ROW IS STALE IN A WAY ITS OWN CHECK CANNOT REPORT — DO NOT DROP IT FOR LOOKING GREEN.** `sanitize.leak.debt.trend` returns **rc 0** and its census is correct for HEAD, because `polarity = informational` never reds. What is stale is its stored `value`, which its `authority` declares to be a copy of `sanitize.leak.records.round_open`'s value and which `check` uses as the delta's `prev`. So the row prints a **wrong delta** every time it is read, while reporting success. An executor who checks it, sees green and drops it from the set has been misled by the instrument.

  ⭐ **THE SHAPE, AND WHY IT IS NOT ONE FIELD.** All four `value`s are a cached copy of a number computable from a declared source — Layering rule 3 (one source of truth per axis) violated four times. But the source differs:

  | row | the invariant that would hold it |
  |---|---|
  | the three `.round_open` rows | `value == regen(anchor)` — its OWN regen, already written and already reading the anchor |
  | `sanitize.leak.debt.trend` | `value == sanitize.leak.records.round_open.value` — ANOTHER ROW's value; its own regen deliberately reads HEAD, because that is the `now` half of an informational delta |

  ⇒ **A single `reseed = anchor-derived` classifier plus a "value equals its regen" lint covers three of the four and is WRONG for the fourth** — asserting `value == regen` on the trend row asserts that `prev` equals `now`, which is the one thing a trend row must not do.

  **THE DESIGN CALL THIS ITEM CARRIES.** Two candidate shapes, and the second is the one Layering rule 3 actually asks for:

  1. **A typed classifier plus a typed row-link.** Add `reseed = anchor-derived` for the three, and a second typed field naming the row a cached `prev` is copied from (the `band_anchor` precedent already stores a row id as a typed field). The lint then asserts `value == regen` for the first kind and `value == <named row>.value` for the second. Cheap; still stores a copy.
  2. **Stop caching `prev` at all.** Give the informational row a typed `prev_from = <row>` and have `figures.py check`'s informational branch READ that row's value instead of the row's own `value`. Then the fourth row has no number to go stale, and the invariant it needed disappears rather than being enforced. This is a change to `check`'s informational branch and to the schema, which is why it is a design call and not a port.

  ⊕ **CHEAP TO DISCHARGE ONCE DECIDED:** these are **baselines, not pins**, so unlike Core #6's LOWER-ONLY pin write-back a baseline's write-back is **BIDIRECTIONAL** — recording a rise is required, not forbidden, because refusing to record one makes the next round's delta a lie. And all four rows carry `scan = none`, so re-seeding them moves no spelling and needs no waiver (verify with `python3 scripts/figures.py scan`, rc off the bare command).

  ⚠ **WHAT THIS ITEM IS NOT.** It is not the missing round-open TRIGGER. Nothing re-seeds these rows *at round open*, and the clone band's equivalent guard only detects, writes nothing, and its own doc records it matching a small minority of round closes — hitching these four to it inherits a broken trigger. That trigger is `[[t0851]]` / `[[t0860]]`. A lint of the shape above makes a **moved anchor go RED immediately**, which is a different and independently useful property: it does not claim the anchor is current, only that the four numbers agree with whatever anchor the tree declares.

  ⚠ **ORDERING.** The typed-classifier MECHANISM this needs already exists — `CLASSIFIERS` in `scripts/figures.py`, with its family derivation, its completeness check in `validate`, and its three RED demonstrations in `tests/lints.rs::figures_db_rows_are_wellformed`. It is parameterised by field name precisely so a second axis is an entry rather than a second selector. **Do not build a second one.** ⊕ `[[t1630]]`'s CI-wiring cut is the third consumer of that same mechanism and is still open.
