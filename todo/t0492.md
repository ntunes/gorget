- **🐛 UPSTREAM GAP — `enum_category` NOT registered for Result with a USER error enum** (`Result[float, ParseError]`/`Result[int, ParseError]`). At the unwrap site (`methods.rs`) `enum_category` was `None` for `Result__double__ParseError` → fell to `else { I64_TYPE }` → mis-typed Ok payload (`double` read as `int64_t`, bogus `+8` arith → `dataframe_csv` printed `0`). Worked around with a name-prefix fallback (`tn.starts_with("Result__")`). REAL fix = find why these user-error Result types are registered WITHOUT going through `make_result_type_def` (`types.rs:1186`, which sets `enum_category: Result`) — likely a mono/generic-instantiation path building the TypeDef directly. Then the name-prefix fallback becomes redundant.
