- **🆕🚨 [HIGH — TWO SILENT WRONG-ANSWER PATHS ON THE SAME TEN LINES, `gg check` CLEAN, BOTH BACKENDS; found
  2026-09-03 by the R49 Track C v2 brief-review while falsifying the track's own fire-count evidence,
  orchestrator-verified] A user type that defines `is_ok` / `is_some` / `is_none` / `is_error` never gets
  called, and a user struct merely NAMED `Option…`/`Result…` is read as an enum.**
  - **PATH 1 — the predicate is swallowed before dispatch.** `src/ir/lowering/exprs/methods.rs:1647` is
    `if matches!(method_name, "is_some" | "is_none" | "is_ok" | "is_error")`, and it intercepts **before**
    the generic dispatch block at **`:1779`** (orchestrator-verified). A non-Option/Result receiver then
    falls to `:1653`'s `return Operand::Constant(Constant::Bool(false))` and **the user's method body is
    never invoked**:
    ```gorget
    struct MyOpt: int v
    equip MyOpt:
        bool has_value(&self): return self.v > 0
        bool is_ok(&self):     return self.v > 0
    MyOpt m = MyOpt(7)
    print(m.has_value())   # true   ← dispatches correctly
    print(m.is_ok())       # false  ← WRONG: the user method is never called
    ```
    `gg check` reports no errors. ⭐ **`has_value` is the negative control that makes it provable** — it
    proves dispatch works for every name *except* the four intercepted ones.
    ⚠ **THE CLASS IS PARTLY SELF-CAMOUFLAGING:** `is_none`/`is_error` on the same object print `false`, and
    `false` is the *correct* answer there — so half the axis is **accidentally correct** (SIX QUESTIONS #6).
    Any fixture set that samples only those two cells reads as green.
  - **PATH 2 — a name-match sends a struct into the enum tag-check.** The same block reads
    `n.starts_with("Option") || n.starts_with("Result")` (`:1651`), so a user struct whose name merely
    *begins* with either string is routed into `build_enum_recv_ptr`, **which reads its first field as a
    discriminant**:
    ```gorget
    struct OptionalConfig: int a, int b, int c      # a = 0
    equip OptionalConfig: bool is_some(&self): return self.a == 999
    print(o.is_some())    # true   ← WRONG; the correct answer is false
    ```
    Two *distinct* wrong paths, discriminated by an instrumented probe: `NAMEMATCH_ONLY` for
    `OptionalConfig` versus `FALLTHROUGH` for an identically-shaped `PlainConfig`.
    ⇒ This is **CLAUDE.md § "No name matching" verbatim** — a name prefix deciding *meaning* — and it is a
    live type-confusion miscompile, **not the tidy-up a Core #2 cleanup would be.**
  - ⭐ **WHY THIS WAS INVISIBLE, and the lesson generalises.** R49 Track C measured this site's whole-corpus
    fire count as **exactly 1 in 4348 fixtures** and concluded it *"fires on every cell of the class and on
    none of the correct ones."* **That measured the CORPUS, not the LANGUAGE**: no fixture happens to define
    a user type carrying one of the four names. A fire count over a corpus is evidence about that corpus
