- **🆕🐛 [HIGH — a stdout-invisible leak on EVERY combinator call over a named receiver with a heap payload; 6 B / 1 allocation, 3/3 runs at `f3feea79`, unchanged by R47 Track B; found R47 Track B as the residual on its own probes]** `Option[String] o = Some(mk("hel","lo"))` then `o.map(...)` leaks `o`'s payload.
  - **MECHANISM, from the GIR — not inferred.** The adapter borrows the receiver, CLONES it, works on the clone, and then its *move-if-dead* prologue unregisters BOTH the scrutinee and the receiver's own local from drop tracking, before the branch — unconditionally, without checking whether the receiver was actually consumed:
    ```
    _6  = call @mk(...)                                   ; payload, heap-forced
    _7  = enum_init Option::Some { copy _6 }
    [Mv] _1 = copy _7                                     ; `o`
    _10 = borrow _1
    _11 = call @Option__GorgetString__clone(copy _10)     ; RECEIVER IS CLONED
    [Mv] _9 = copy _11
    ...
    (no drop_if_alive _1 anywhere)
    ```
    Unregistering is correct when the receiver was genuinely moved in. Here it was cloned one line earlier, so the original still owns a payload nobody frees.
  - **⚠ DIRECTION — this is the MIRROR of the class R47 Track B fixed, which is why it is filed and not folded.** Track B fixed UNDER-registration at a producer (a call result nobody registered). This is OVER-unregistration at a consumer (an owner whose registration is removed although nothing consumed it). Same helper, same axis, **opposite direction and a different fix shape**: the fix here is to make the prologue's unregister conditional on the receiver actually being consumed (it is not, when `clone_resource_args_for_init`-style cloning has already happened), not to add a registration anywhere.
  - **BLAST RADIUS: every** `.map` / `.and_then` / `.flat_map` / `.filter` / `.or_else` / `.unwrap_or_else` / `.map_err` on a named Option/Result receiver holding a String or collection payload — i.e. every combinator chain in user code. It is invisible to the whole integration suite because those are stdout comparisons.
  - **⚠ WHY R47 TRACK B'S OWN FIXTURE NET AVOIDS `.map()` ON A NAMED RECEIVER:** those cells would carry this residual and an output-review would read it as an incomplete fix. Track B's adapter cells use `unwrap_or_else` on a `None()` receiver instead.
