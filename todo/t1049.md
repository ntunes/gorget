- **🚨 [HIGH — `for i, c in s.enumerate()` TRAPS on any multibyte String, and is ACCIDENTALLY CORRECT on every ASCII one; found 2026-09-03 by the R49 Track K brief-review gauntlet, executor-verified at HEAD] The enumerate loop counts BYTES and indexes CODEPOINTS.**
  - **MEASURED:** `for i, c in "héllo".enumerate(): print(i); print(c)` prints the five correct pairs and then **`trap[T_Bounds]: str index out of bounds`, rc 101**. "héllo" is 5 codepoints in 6 bytes; `lower_for_enumerate` reads the iterator's `.len` via `Projection::Field(2)` — the BYTE length for a String — so the loop runs a sixth time and asks for codepoint 5.
  - **⚠ WHY NOBODY SAW IT (SIX Q#6):** byte length equals codepoint count for every ASCII string, so the entire ASCII `.enumerate()` corpus is green and proves nothing about the multibyte cell. The plain `for c in s:` form walks codepoints correctly and is unaffected.
  - **SIBLING SHAPE, SAME ROOT:** binding the element (`for (i, c) in s.enumerate(): held = c`) ICEs at `src/ir/lowering/mod.rs` with a Tier 2a *"AssignIntoOwnedSlot — untracked source consumed"* consume-site violation. `infer_collection_element_type` strips `Vector__`/`Deque__`/`Set__`… and has no String arm, so a String receiver falls through to `I64_TYPE` and `is_string_type(elem_type)` is false for the whole enumerate path. Not separately filed — it is this defect seen from the other side. ⚠ The R49 Track K view tag does NOT reach it and does NOT close the ICE; measured with the fix applied.
  - **REFERENCE LAGS THE SELF-HOST (fix Rust as oracle hygiene, never dumb the SH down):** `self_host_lowerer/lower_loops.gg`'s `lower_for_string(… is_enumerate …)` handles enumerate on the STRING path with its own codepoint-ordinal counter and gets it right.
