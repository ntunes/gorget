- **🆕⚡ [MED — a CoW charter breach with a USER-OBSERVABLE signature: `flat_map` runs the result element's `Drop` body TWICE per element; found 2026-09-04 by R49 Track N2, whose own fix introduced the second half of it] `flat_map` deep-clones every element it appends and then frees the source, where the reference-grade shape is an append-MOVE.**
  ```gorget
  Vector[Cust] r = src.flat_map((s): [Cust(s)])   # two elements in, four `drop` bodies run
  ```
  **MEASURED**, `tests/fixtures/vector_hof_result_element_drop.gg`, a two-element source whose element type has an `equip Cust with Drop` body that prints:

  | producer | lane | `drop` bodies run for 2 result elements |
  |---|---|---|
  | `push` (control) | Rust | **2** |
  | `map` | Rust | **2** |
  | `flat_map` | Rust | **4** |
  | `flat_map` | **self-host** | **2** ⭐ |

  ⭐⭐ **THE SELF-HOST ALREADY DOES IT RIGHT, AND THAT IS THE STRONGEST PART OF THIS FILING.** Measured 2026-09-04 through `assert_self_host_stdout` on the same program: the self-host desugars `flat_map` into a NESTED LOOP that publishes the inner loop variable directly, so each element is MOVED into the accumulator and there is no drained husk to free — two `drop` bodies, matching `map` and the `push` control. The Rust lane's extend-then-free runs four. **This is a "reference lags the self-host" finding in the sense the succession plan means it: the reference-grade shape is not hypothetical, it is running in the tree, and the fix direction is to bring Rust up rather than to accept the clone.** ⚠ It is also why `tests/fixtures/vector_hof_result_element_drop.gg` has no `flat_map` cell — pinning either count would pin the divergence.

  ⭐ **IT IS NOT A BUG IN THE SENSE OF UNSOUNDNESS — every value is dropped exactly once.** The extend deep-clones the callee's elements into the accumulator, so there are genuinely four `Cust` values over the program's life. But two of them exist only to be copied and destroyed, and a user who writes a `Drop` body with a side effect sees it fire twice per element with no `.clone()` anywhere in their source.
  ⛔ **`feedback-cow-charter-optimal-clones` is explicit that implicit clones must be AS GOOD AS the best hand-written equivalent.** A hand-written `flat_map` drains the callee's vector by MOVING each element and then frees the empty husk; no clone is required, because the husk is dead at that point and the elements are owned by construction. The clone here is a consequence of the runtime primitive available, not of the ownership state.
  ⚠ **THE CLONE IS LOAD-BEARING TODAY — DO NOT SIMPLY DELETE IT.** `gorget_array_extend` gates its deep clone on the DESTINATION's `elem_clone`; that clone is exactly what makes freeing the drained husk safe rather than a use-after-free, because without it the accumulator holds aliases into the husk's buffer. Removing the clone and keeping the free reintroduces a measured UAF. The fix is a new append-MOVE runtime primitive that transfers the elements and leaves the husk genuinely empty, plus the expander calling it instead of extend-then-free — and it owes its own order-coupling analysis, because the safety argument for the husk free changes with it.
