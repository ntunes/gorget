- **🐛 ESCAPING SLICE (`int[]`) silently MISCOMPILES — reject it at `check`.** Returning a slice of a *local* is rejected (`DanglingReturn`, `check_stmt.rs:667`), but a slice escaping backed by a *parameter*'s storage is accept-and-wrong: `int[] f(int[] s): return s` compiles + prints `0` (should be `3`) with a `void*`-from-`int` warning (ptr/len isn't carried across the return ABI). No general slice runtime representation (only the `cap==0` String view). TASK: make `int[]` in a return/escape position a clean `check`-time error — extend `DanglingReturn`/return-origin to reject ANY non-`String` slice that escapes (incl. `Ref[T]`/`MutRef[T]` lazy-iterator returns). (Alternative, bigger: a real slice fat-pointer.) ZERO integration fixtures return a slice.
