- **🆕🚨 [HIGH — the self-host lane SEGVs on a program Rust gg runs correctly on BOTH backends; the emitted C COMPILES CLEANLY, so no gate short of running it can see this. LIVE and un-`#[ignore]`d since 2026-09-04 (`030d4d2d7`), red on x86_64 the whole time.] The self-host declares an indirect-call ABI channel and never writes to it, so the call site types its parameters from the ARGUMENT and the callee from its own DECLARATION.**
  - **REPRODUCED AT HEAD, deterministically, on linux/amd64.** Regenerate without the harness:
    ```
    tests/fixtures/self_host_lowerer/driver \
      tests/fixtures/closure_literal_ambient_return_at_call_arg.gg lib \
      --emit-c --runtime-dir=src/backend/c/runtime > /tmp/sh.c
    cc -O0 -w -o /tmp/sh.bin /tmp/sh.c -lm -lpthread    # rc 0 — it COMPILES
    /tmp/sh.bin; echo rc=$?                             # rc 139
    ```
    Rust gg runs the same fixture correctly on C and LLVM (`closure_literal_ambient_return_at_call_arg`, live and green).
  - **MECHANISM — the emitted C states it in two lines.** The `apply(Callable[String(String)] f, String arg): return f(arg)` cell:
    ```c
    Str apply(void* __p0, void* __p1) { ...
        __v4 = ((Str(*)(void*, void*))(((void**)__v0)[0]))(((void**)__v0)[1], __v1);
    Str __Closure_2__call(void* __p0, Str __p1) { ... }
    ```
    The caller casts parameter 1 to `void*` and passes the pointer it is holding; the callee declares that parameter as a 32-byte `Str` BY VALUE. **The two sides of one call disagree about the ABI.**
  - ⚠ **ARCHITECTURE IS THE DISCRIMINATOR, AND IT IS WHY THIS SAT UNSEEN THROUGH THE ROUND THAT LANDED IT.** SysV x86_64 classes a 32-byte composite as MEMORY and passes it on the STACK, so the callee reads a stack slot nothing wrote. AAPCS64 passes a >16-byte composite **BY REFERENCE to a caller-made copy**, so the callee receives exactly the pointer the caller passed and the cell is correct BY ACCIDENT. A dev box that is not x86_64 cannot see this class at all. ⊕ Same blindness as `[[t0969]]`, and as the two Rust-side defects closed 2026-09-11 (`DONE.md`, `t1652` / `t1653`).
  - ⭐ **THE WRITE SITE, LOCATED, AND IT IS AN UNPOPULATED CHANNEL RATHER THAN A WRONG VALUE (Core #1).**
    ```
    grep -n 'ICallClosure(cl_dst' tests/fixtures/self_host_lowerer/lir_lower.gg
    ```
    ```gorget
    Vector[int] cl_abis = []
    # kind=0 means CallableParam (void*[2] protocol)
    lir_push_inst(&f, bb, ICallClosure(cl_dst, 0, cl_closure, cl_call_args, cl_abis, cl_ret))
    ```
    `cl_abis` is constructed EMPTY at the only site that builds the instruction, and `lir.gg:208` declares the field (`arg_abis`) as part of the shape. The reader then has nothing to read:
    ```
    grep -n 'case ICallClosure(dst2, kind, closure, cl_args, cl_abis, ret_ty)' tests/fixtures/self_host_lowerer/lir_codegen.gg
    ```
    binds `cl_abis` and **never mentions it again**, typing each parameter from `val_types.get(cl_arg_id)` — the ARGUMENT's own type. **A field that is declared, threaded through SSA substitution, bound at the reader and used by nobody is Core #14's case exactly: the shape asserts an invariant that nothing enforces.**
  - ⊕ **THE REFERENCE IMPLEMENTATION OF BOTH HALVES ALREADY EXISTS ON THE RUST SIDE**, and the succession plan says to bring the self-host UP to it rather than dumb the fixture down. Producer: `declared_indirect_abis` at the three indirect-call arms in `src/ir/lowering/exprs/calls.rs` (the sidecar/`FnPtr`-type read, see `t1653`). Consumer: the `needs_deref` decision in `Inst::CallClosure` at `src/backend/c_lir/mod.rs`, which reads `arg_abis` per index and emits `*(T*)arg` or the pointer accordingly. Pinned there by `indirect_call_abi_decision_sites` (`tests/lints.rs`), which is worth mirroring once the channel carries data.
  - ⛔ **DO NOT "FIX" IT BY LOADING EVERY POINTER ARGUMENT AT THE EMIT SITE.** That is green on this fixture and wrong by construction: a callee whose parameter is genuinely by-reference (a `&` sigil) must keep receiving the pointer, and the emit site cannot tell the two apart without the channel. The whole defect is that the DECLARED ABI is not in scope at the call site; a rule inferred from the argument's shape is the same mistake in the other direction.
  - **WHAT DISCRIMINATES IT FROM ITS NEIGHBOURS.** `[[t0969]]` is the same fixture family but a different failure: a `Callable[String(String)]` STRUCT FIELD, self-host only, and its `int(int)` siblings MATCH. This one needs no struct field — a plain `Callable` PARAMETER called directly is enough — and its Rust-lane twin is green. `t1653` (closed) is the RUST-side mirror of this exact channel gap, at the producer rather than the consumer; fixing either lane leaves the other live.
  - **INTENDED:** the self-host lane prints `hello?`, `bad!`, `world` and exits 0, matching Rust gg. Asserted by the `#[ignore]`d `closure_literal_ambient_return_at_call_arg_self_host`. **This item closes when that test passes un-ignored.**
