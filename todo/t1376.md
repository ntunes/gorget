- **🆕🐛 [MED — A ONE-FIELD `newtype` ACCEPTS ANY ARITY AT CHECK TIME. Found 2026-09-05 by R50 Track A2's brief-review pass 4; PRE-EXISTING, and A2 deliberately did not change it.]**

  ```gorget
  newtype UserId(int)
  UserId u = UserId(1, 2)   # accepted by `gg check`, before and after R50 Track A2
  ```

  **MECHANISM.** `typecheck.rs`'s `Expr::StructLiteral` arm validates arity only inside `else if let Some(sfi) = self.struct_fields.get(&def_id)`. A newtype def_id has no `struct_fields` entry, so the `Some` branch never runs and `WrongFieldCount` is never raised. Nothing downstream re-checks it.

  ⚠ **A2 MEASURED THIS AND LEFT IT DELIBERATELY.** Adding a `struct_fields` entry for newtype def_ids would have made the arity check fire — but that is an **ACCEPT→REJECT semantic change**, which under Core #9 must land on every lane in the same round with its own conformance fixture, and it is not what A2 was briefed to do. Skipping the check is **exactly the pre-A2 behaviour**: measured identical before and after (3/3 newtype integration tests, both robustness cells byte-identical, and the NEG cell still emits its byte-identical `E_TypeMismatch`). Filing it is the honest disposition; silently widening the gate would not have been.

  ⚠ **DISCRIMINATOR vs `t1375`:** that item is about newtype construction never becoming a `StructInit` at all (closed by A2). This is about the arity CHECK that the `StructInit` arm skips for want of a field table. A2 routed newtypes INTO that arm; it did not give them a field table.

  **INTENDED:** `UserId(1, 2)` is rejected at check time with `WrongFieldCount { expected: 1, found: 2 }`. **Accept→reject ⇒ needs the ggdef + self-host lanes and a conformance fixture for the final state (Core #9), so it is a track of its own, not a one-line widening.**
