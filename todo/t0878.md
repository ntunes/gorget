- **🆕🐛 [HIGH — `Vector[T].map(f)` / `.flat_map(f)` with `f` a `Callable[U(T)]` PARAMETER links against nothing; found R48 Track A, whose `t0770` reader-3 fix would otherwise have un-gated it into a SILENT LLVM MISCOMPILE]**
  - **MECHANISM, read at HEAD.** The typechecker elaborates the call's result type fine. The BODY of `Vector__T__map` is emitted only if `ir::lowering::generics::discover_method_instances` registered the instance while walking the AST with a `LocalTypeEnv` — and a `Callable[U(T)]` parameter, whose type is erased, is not in that env. So: `undefined reference to 'Vector__GorgetString__map'`.
  - **⭐ WHY IT IS CURRENTLY A REJECTION, AND WHAT MUST NOT BE UNDONE.** Widening `extract_fn_return_type` to see through the `CallableTrait` wrapper (reader 3 of `t0770`) un-gates this shape from a clean check-time rejection into that un-minted monomorph. MEASURED: C gives the `undefined reference` above; **LLVM gives rc 0 printing `281470681743361` where `5` is correct** — a silent miscompile where the compiler previously rejected, which is strictly worse (Core #8, Core #10). So the two `Vector` arms in `src/semantic/typecheck.rs` decline a non-`Function` closure operand via `is_monomorphizable_closure_operand`, restoring the rejection. **Deleting that gate without minting the monomorph re-opens the LLVM miscompile — the gate and the fix must land together.**
  - **⚠ THE CURRENT DIAGNOSTIC IS ALSO WRONG.** `error[E_TypeMismatch]: type mismatch: expected 'int', found 'String'` reports the FALLBACK type, not anything the user wrote. The reference-grade end state is that the program COMPILES AND RUNS; a better-worded rejection is the interim, not the destination. The fix owes both halves.
  - **SCOPE IS THE `Vector` COLLECTION HOFs ONLY, measured, not assumed:** `Iterator.map` with a `Callable` PARAM needs no gate.
