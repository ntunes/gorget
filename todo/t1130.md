- **🆕🚨 [HIGH — LANE DIVERGENCE ON ACCEPTED, CORRECT, DOCUMENTED CODE: ggdef's `==` NEVER DISPATCHES a user `equip T with Equatable` implementation. Found 2026-09-04 by R49 Track F-G. This is the truth axis, so ggdef being the one that differs is the worst direction for it to differ in.]**
  - **MEASURED, with a marker-printing body so the dispatch itself is observable.**
    ```
    struct P: int a
    equip P with Equatable:
        bool eq(self, P other):
            print("MARKER:user-eq-ran")
            return true
    ...  P a = P(1); P b = P(2); if a == b: print("equal") else: print("NOT-equal")
    ```
    **C gg** prints `MARKER:user-eq-ran` then `equal`. **ggdef** prints `NOT-equal` and **no marker at all** — it answered structurally (`P(1)` vs `P(2)`) and never entered the user's body.
  - **CONTROL, and it is what makes this the `==` OPERATOR's defect and not a dispatch defect in general:** the same impl called explicitly as `a.eq(b)` DOES dispatch on ggdef. `elaborate_method` consults `equip_methods`; the `ast::Expr::BinaryOp` arm does not, and `eval` reaches `(BinOp::Eq, _, _) => Ok(Value::Bool(values_eq(&lv, &rv)))` (`spec/ggdef/src/eval.rs`), a structural compare that shadows any impl.
  - **DISCRIMINATED FROM ITS FAMILY.** `t0013` (closed by D46) was the MISSING-impl path — no `Equatable` anywhere, all lanes accepted, and the answer was address identity. This is the **PRESENT-impl-IGNORED** path: the impl exists, production honours it, ggdef ignores it. Different sites, different remedy, and this one is **ggdef-only**, measured on each production lane: **C** prints the marker and `equal`; **LLVM** (`--backend=llvm`) prints the marker and `equal`; the **self-host** driver's emitted C contains three references to `P__eq`, so it dispatches the impl too.
  - **WHY IT SURVIVED.** No committed spectest uses `equip … with Equatable` (measured: zero hits across `spectests/run/*.gg`), so nothing on the conformance lane exercises it. `@derive(Equatable)` is not affected — ggdef deliberately keeps `values_eq` as its OWN definition of derived equality, field by field, matching `docs/book/appendix-traits.md`; the derive path and the user-impl path are different obligations.
  - **FIX SHAPE.** In the `ast::Expr::BinaryOp` arm (`spec/ggdef/src/elaborate/mod.rs`), when the operand type is `Ty::Named(n)` and `equip_methods` holds `(n, "eq")`, elaborate to that method's `Expr::Call` instead of `Expr::Binary(BinOp::Eq, …)` — and wrap it in `Expr::Unary(UnOp::Not, …)` for `!=`. The operand type is already inferred there for D46's gate. Land a cross-lane seed with a marker body in the same commit, which is what would have caught it.
  - **INTENDED:** `a == b` on a type with a user `equip … with Equatable` runs the user's `eq` on every lane, ggdef included.
