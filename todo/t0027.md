- **🆕🧹 [MEDIUM — Layering rule 2 debt exposed by R43 M1; NOT a live miscompile] `override_is_trait_box` (`src/ir/lowering/exprs/collections.rs`) is a NAME MATCH that is the load-bearing semantic gate of the array literal's slot decision.** It strips a `Box__` prefix and probes for a `{inner}_TraitObj` type-def to decide whether the destination's declared element type wins over the materialized operand's. It is kept deliberately, for behaviour preservation, and is PINNED in both directions (`box_trait_vector_lit.gg` dies without it; `sound_amp_v_i_tuple_field_writethrough.gg` and `sound_tuple_getchain_writethrough.gg` die if it is widened to a blanket) — but a track whose thesis is that name-matched semantics are the disease should not ship a name match as its discriminator. Owed: a typed `TypeMetadata` flag (`is_trait_box` or equivalent) set once at Box-type registration and read through an accessor, replacing the prefix+probe. ⊕ Related and also filed by the same measurement: `infer_collection_element_type` (`src/ir/lowering/exprs/methods.rs`) recovers an element type by mangled-name strip with a bare `I64_TYPE` fallback, which is why the array literal must pass `SlotType::FromOperand` rather than its 'expected' type — the destination does not actually know its slot. A typed element-type field on the collection TypeDef would retire both.
