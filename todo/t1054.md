- **🆕🧹 [MED — a live Layering-rule-2 site with ~50 arms, IDENTICAL IN SHAPE to the R49 A1-IDENTITY miscompile, and the source of a user-visible defect; found 2026-09-03 by the A1-IDENTITY brief-review passes 1–3, re-measured 2026-09-04] `src/backend/llvm/mod.rs`'s collection-constructor gate is ~50 `!name.contains("__method")` predicates against mangled `{Type}__{method}` names, and the `elem_size` immediately below it is a second name derivation.**
  - **THE SHAPE.** `is_collection_ctor` at `src/backend/llvm/mod.rs:4744-4763` reads `module.struct_aliases.contains_key(name) && !name.contains("__map") && !name.contains("__filter") && !name.contains("__get") && … && args.len() <= 1` — around fifty `contains("__X")` arms, one per collection method. **This is the same `contains("__X")` against a mangled name that produced R49's stack-buffer-overflow / silent-wrong-output miscompile at `contains("__call")`, at fifty times the arm count.**
  - ⚠ **NOT CURRENTLY REACHABLE, AND THE HONEST CLAIM IS THAT THE ~50 PREDICATES ARE DEAD WEIGHT WHOSE REMOVAL IS THE FIX** — not "no exploit demonstrated". `module.struct_aliases` has exactly ONE insertion site (`src/lir/lower/mod.rs:970`) and it inserts `def.name.clone()` of a GIR type definition, so the keys are TYPE-ALIAS names and never method names ⇒ `contains_key` alone already discriminates. An instrumented probe found the only callee reaching that site with `alias = true` is `Vector__int64_t`.
  - ⚠ **BUT IT IS AN ACCIDENT, NOT A GUARANTEE.** A user-struct element *would* produce `Vector__setting`, which contains `__set`; it never arrives only because the callee is rewritten upstream. Nothing enforces that.
  - ⛔ **THE `elem_size` ARM DIRECTLY CAUSES `todo/t1052`.** Immediately below, `src/backend/llvm/mod.rs:4766-4772` computes `let elem_size: i64 = if name.contains("int64_t") || name.contains("double") || name.contains("GorgetString") { 8 } else if name.contains("int32_t") { 4 } else if name.contains("bool") { 1 } else { 8 };` — same shape, and `else { 8 }` is the arm that sends `Vector[UserStruct](capacity)` to a wrong default. `t1052` is the user-visible defect this produces; **fixing it is the likely fix for `t1052`, and fixing `t1052` alone would not retire this item.**
  - **THE REFERENCE-GRADE FIX.** The element's size and the "is this a constructor" question are both typed facts the LIR already holds: `StructDef.computed_c_size` for the element, and the callee's own LIR declaration for constructor-vs-method. Read those; delete the predicate chain.
  - **A MECHANICALLY-DERIVED CENSUS EXISTS AND IS BIGGER THAN THIS SITE.** Deriving the name alphabet from the `format!` mints in `src/` (rather than a hand list) yields **100 `__`-prefixed tokens**, essentially the whole `{Type}__{method}` mangling family. R49's closure-identity ratchet deliberately scopes itself narrower and says so; this item is where that wider family lives.
  - **VERIFICATION:** `sed -n '4744,4772p' src/backend/llvm/mod.rs` for the chain; `grep -n "struct_aliases.insert" src/` for the single writer; `gg build --backend=llvm tests/fixtures/known_gaps/vector_user_struct_capacity_ctor.gg` for the reachable consequence.
