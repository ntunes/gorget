Found by R50 Track J's scout, then correctly de-escalated by its pass-1 review.]** The registry declares `gorget_heap_push` and **no C definition exists anywhere in the tree**. The scout read that as a latent link failure — `Heap.push` would fail to link — and flagged it as reachable-but-unmeasured.

  **Measured, and it is neither:**

  ```
  Heap[int] h = Heap[int]()
  -> E_UndefinedName: undefined name 'Heap'; did you mean 'Weak'?
  ```

  `HEAP` (`grep -n 'HEAP' src/ir/lowering/builtins.rs`) is a **dead protocol**: no surface spelling reaches it, so the dangling row can never be linked against. **Not a CRITICAL, not a latent failure — dead weight in a table that is supposed to be the authoritative witness for runtime element operations.**

  ⛔ **THE REASON IT MATTERS IS THE WITNESS, NOT THE ROW.** Track J's pass-1 review found the same registry is **not total** over the runtime's element-writing surface — `gorget_shared_array_set` is string-emitted from `src/backend/c_lir/helpers.rs` and appears in no registry row at all. A table with dangling rows *and* missing rows is a witness that can neither be trusted for presence nor for absence. Retire the dead row and the dead protocol together, or record why they stay.
