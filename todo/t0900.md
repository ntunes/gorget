- **⚠ THE FILED MECHANISM WAS WRONG, AND THE CORRECTION IS THE USEFUL PART. Re-measured 2026-08-30 at `05f72286`.** This item said *"the harness does not reap its child, so a hung fixture is left spinning every time that gate runs"*, and its own addendum escalated that to *"the ordinary path leaves an orphan every time that gate runs."* **Neither is supported by the code.** Every deadline and overflow path group-kills before it reports: the runner spawns with `process_group(0)` and signals the NEGATIVE pgid, so the kill reaches grandchildren. The corrected mechanism: **orphans are born when the HARNESS ITSELF dies — because `process_group(0)`, which is exactly what makes the tree kill work, is also what makes the child immune to the harness's own group dying.** The two facts have one cause, and so do the leftovers: the same SIGKILL that orphans the child also skips `TmpRootGuard::drop`, so **an orphan implies a surviving scratch root**. That invariant is what the ownership predicate is built on. Interrupted runs are routine here, so the class is real — it is just not "every run".

- **⚠⚠ AND `PPID == 1` IS NOT THE ORPHAN CONDITION.** Re-measured on this box 2026-08-30: `ps -eo pid,ppid | awk '$2==1'` is **EMPTY**, and session leaders show **PPID 0** — the box is PID-namespaced (`readlink /proc/self/ns/pid` → `pid:[4026532557]`, pid 1 is a `bash`). So a parentage predicate is **blind** here; and when it does match, it matches live work — a reparented `cargo test` was observed at `ppid == 1` during the R47 scout. Both directions wrong. The predicate must be **OWNERSHIP**: an executable under a scratch root whose owning run is dead, which puts a live executor's `target/release/deps/integration-<hash>` OUTSIDE the domain rather than excluded from it by a list. That is Core #3 applied to processes, and it is the only shape that structurally cannot repeat the `pkill -f 'integration-[0-9a-f]'` incident that killed a live executor's run mid-gate.

- **WHAT REMAINS — PHASE 2: THE RUN LEDGER, because the tag-based domain has a measured hole.** `scripts/reap_orphans.py` decides ownership by parsing the pid out of the scratch root's NAME (`gg_runtime_diff_<pid>_<millis>`, `gg_sh_<tag>_<pid>`, …), which the harness writes at creation. That covers the families that carry a tag and nothing else:
  - **95,557 untagged `/tmp/.tmpXXXXXX` directories** on this box right now (regenerate: `ls -A /tmp | grep -c '^\.tmp'`), from `tempfile::TempDir` / `mkdtemp`, which encode **no owner at all** — no glob can recover one. Producers: `grep -c 'temp_dir()' tests/integration.rs` → 60; `grep -rn 'TempDir::new()\|tempfile::tempdir()' tests/ src/ | wc -l` → 23.
  - `/proc/<pid>/exe` unreadable (different uid, or the process exiting under the scan) — reported as UNDECIDABLE.
  - processes outside this PID namespace — invisible, and named as such.
  ⇒ **The reference-grade fix is to register ownership at the value's birth**: one helper writes `/tmp/gg_runs/<pid>_<starttime>/` recording the owner's identity and the pgids it spawned, and unlinks it on clean exit; the reaper reads it through one accessor and needs no name parsing whatsoever. Pair it with an **arm-count lint forbidding raw `env::temp_dir()` / `TempDir::new()` in test targets**, so the next scratch family cannot be born untagged. The leak class and the orphan class are the same invariant, which is a pleasing thing for this compiler to be caught not applying to itself.

- **AND THE PRE-FLIGHT'S REACH IS 2 OF 9.** `scripts/reap_orphans.py --preflight` is wired into `scripts/run_integration.sh` (so both the C and the LLVM sweep) and `scripts/sanitize_sweep.sh`. **Uncovered, named rather than implied:** `cargo test --lib`, `--test lints`, `--test security`, `--test spec_conformance`, `-p ggdef`, and `python3 scripts/robustness_map.py`. Each starts on an unchecked box. Widening means either a wrapper every gate calls or a `#[ctor]`-style check inside the Rust targets; pick one deliberately.
