- **🆕🚨 [HIGH — AN ORPHANED TEST BINARY BURNED A FULL CORE FOR 40 HOURS AND SKEWED THE ROUND'S MEASUREMENTS. Found 2026-08-29 by the R47 Track E2 executor, orchestrator-verified and reaped.]** `async_select_diff` from `/tmp/gg_runtime_diff_1621_*` was measured at **elapsed 1d16h, CPU 1d15h, state `R` (running, not blocked), 11 threads, RSS 1 MB** — i.e. a **spin**, not a deadlock. Started 2026-08-28; found still running 2026-08-29.
  - **⚠ THE HANG ITSELF IS NOT THE DEFECT — IT IS ALREADY KNOWN AND ALLOWLISTED.** `tests/integration.rs` carries `EXPECTED_HANGS = {async_select}` (see the NO-NEW-HANGS guard). Do **not** re-file the hang.
  - **THE DEFECT IS THAT THE HARNESS DOES NOT REAP IT.** In the E2 executor's words: *"a killed wrapper doesn't always kill the binary — check `ps aux | grep '[i]ntegration-f'`."* When the wrapper is killed or times out, the child survives and keeps spinning. Nothing notices, because nothing looks.
  - **WHY THIS IS WORSE THAN WASTED CPU — IT SILENTLY CORRUPTS LATER EVIDENCE.** `scripts/run_integration.sh` autoscales on free cores and RAM. A spinning orphan makes the box look loaded, so the next sweep autoscales **down** — the E2 executor recorded its first full sweep dropping to **one thread** for exactly this reason, and neither of its two sweep attempts completed. **Every timing-sensitive or load-adjusted measurement taken on this box while an orphan is alive is suspect**, which in this round included at least one bootstrap run that false-redded on a load-adjusted deadline.
  - **DISPOSITION.** (a) The harness must reap its child on wrapper exit — process group kill, or a guard that refuses to start a sweep while a stale `*_diff` binary from a previous run is alive. (b) A cheap interim: have `scripts/run_integration.sh` detect and report orphaned `*_diff` / `integration-*` processes before it autoscales, rather than silently measuring a poisoned box.
  - **GUARD (the deliverable, not just the fix).** A pre-flight check that FAILS LOUDLY when a stale test binary is running. ⚠ Core #13: demonstrate it going RED with a deliberately orphaned sleeper — a check that has never been seen to fire is not evidence.
  - **VERIFY (all four commands; the first three were run 2026-08-29):**
    ```
    ps -eo pid,etime,time,stat,args --sort=-time | grep -E '_diff|integration-' | head
    cat /proc/<pid>/status | grep -E 'State|Threads|VmRSS'
    grep -n 'EXPECTED_HANGS' tests/integration.rs
    ls -d /tmp/gg_runtime_diff_* && du -sh /tmp/gg_runtime_diff_*
    ```
  - **⊕ SCRATCH ACCUMULATES WITH IT:** five `gg_runtime_diff_*` directories were present, four of them pre-dating the round, ~230 MB each. The orphan's own directory has been removed; the rest are round-close hygiene.
