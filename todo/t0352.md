- **[LOW — cosmetic, not conformance-compared] Message-form `assert` trap line renders `at <unknown>:0:0`.** T2a-rust reroutes assert-with-message to `gorget_trap(T_AssertFailed, msg)` → `gorget_trap_at` threading the emit-site span (like `panic`). The code + exit 101 are correct and BYTE-IDENTICAL across C/LLVM, but the source LOCATION on the assert trap line resolves to `<unknown>:0:0` (Q-D wanted a real span). Root cause is a PRE-EXISTING GIR→LIR span-propagation gap for these branch-target trap blocks — the old `gorget_panic` assert emitted `<unknown>:0:0` too, and `condition.span` IS a real byte range (verified), yet the LIR instruction carries no span (both `call_extern` and `call_void` reproduce it, so it is NOT the Call/CallExtern distinction). Conformance does NOT compare the location (impl-defined, Q1), so this is cosmetic. Fix belongs in the GIR→LIR span-map plumbing for branch-target blocks, not trap normalization.
