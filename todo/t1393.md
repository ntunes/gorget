- **🆕🚨💥 [CRITICAL — MEMORY-UNSAFE FROM ORDINARY SAFE SYNTAX; `gg check` CLEAN, `gg build` rc 0, then SIGSEGV on BOTH backends; found 2026-09-05 by R50 Track D0′ brief-review pass 1]** A call through an indexed place whose head is itself an index or a parenthesised field crashes at runtime, with no diagnostic at any stage.

  **Two measured cells — both `OK: no semantic errors`, both build, both SIGSEGV:**
  ```gorget
  Vector[Vector[Callable[int(int)]]] vv = ...
  print(vv[0][n](7))            # gg check OK -> builds -> SIGSEGV (signal 11)

  print((r.routes)[k](5))       # gg check OK -> builds -> SIGSEGV, rc 139
  ```

  ⭐ **THE MECHANISM IS THE `expr[...](` PARSE AMBIGUITY, RESOLVED THE WRONG WAY WITH NO RECOURSE.**
  `src/parser/expr.rs` resolves `expr[...](` **unconditionally** in favour of a generic call whenever the
  bracket contents parse as type arguments (regenerate:
  `grep -n "Ambiguity: expr\[...\] could be indexing" -A 20 src/parser/expr.rs`). With a bare identifier index
  the key is eaten as a **type name**, and nothing downstream re-examines it.

  ⛔ **THE VARIABLE-INDEX SIBLINGS FAIL LOUDLY; THESE FAIL SILENTLY. THAT IS THE DISCRIMINATOR.**
  `d[k](v)` and `v[i](5)` reject with `E_NotAFunction` — annoying but SAFE. **These two shapes are ACCEPTED and
  then crash**, which is strictly worse and is why this is filed separately from the `E_NotAFunction` class
  (`t0957`).

  ⊕ **A THIRD FACE, ALSO SILENT, FAILING EVEN LATER:** a `Dict[String,Callable]` **struct field** with a
  variable key — `gg check` → **`OK: no semantic errors`** plus a tell-tale `warning: unused variable 'k'`
  (**the key was consumed as a TYPE**) — then `gg build` fails at **LINK** time with
  `undefined reference to 'Router__routes'`. ⚠ **A raw linker error is not a diagnostic** (Core #10,
  lower-or-reject).

  ⚠ **SEVERITY ORDER:** memory-unsafety outranks the leak and reject classes this family is otherwise about.
  **`grep -rlniE "SIGSEGV" todo/` finds no existing item with this mechanism** — `t0959`/`t0164`/`t0024`/`t0406`
  are other mechanisms.

  ⭐ **A CANDIDATE FIX IS ALREADY MEASURED TO CLOSE ALL THREE:** Track D0′'s rewrite-layer disambiguation makes
  both SIGSEGV cells build and print the correct answer (`21`, `6`). ⛔ **BUT ITS CURRENT PROTOTYPE REACHES THEM
  THROUGH AN UNGUARDED SYNTACTIC SHORTCUT** (`Expr::FieldAccess { .. } | Expr::Index { .. } => true`, consulting
  no resolution) — so a fix that keeps the shortcut trades a crash for a shape heuristic. **The reference-grade
  close is resolution-based for these heads too.**
