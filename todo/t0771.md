- **🆕🚨💥 [CRITICAL — `AddressSanitizer: heap-use-after-free` under `--sanitize`, and on a plain build **rc 0 with SILENTLY WRONG OUTPUT**, which is the worse outcome; deterministic 3/3 runs at `f3feea79`; found R47 Track B while probing the escaped-closure arm] A closure that CAPTURES A PARAMETER and then ESCAPES its defining function reads freed memory.**
  - **REPRO.** `Callable[String()] make_adder(String p): return (): mk(p, "lo")` then `Callable[String()] g = make_adder("hel"); print(g())` → prints garbage bytes (`\xc4\xb8\xef\xbf\xbdlo`) on a plain build; under ASan: freed by `gorget_string_free ← make_adder ← main`, read by `gorget_str_cat ← mk ← __Closure_0__call`.
  - **MECHANISM.** `p` is a parameter, i.e. a BORROW. The capture stores the borrowed handle rather than an owned copy, so `make_adder`'s scope exit frees `p` while the escaping closure environment still points at it. A closure capture IS an ownership boundary — CLAUDE.md §Ownership at Consuming Positions lists *"returns, closure captures"* among the positions where the destination must own, with clone-if-live / move-if-dead. Here the boundary does neither.
  - **⚠ FAMILY, AND WHAT DISCRIMINATES THIS MEMBER — state this before merging it with either sibling.** `t0704` is the same boundary but its trigger is MUTATION of a captured collection (64 pushes force a realloc under a captured element view) and the captured thing is a LOCAL; its own text records that the prescan road is measured and closed. `t0108`(c) is the same boundary for a refcount `Shared` handle and is about incref at the return boundary. **THIS one needs no mutation, no collection and no refcount:** the captured thing is a PARAMETER and the deallocation is the DEFINING FUNCTION'S OWN scope exit, reached purely by the closure outliving its frame via `return`. A fix aimed at the mutation prescan or at refcount incref closes neither of the others nor this one.
  - **⚠ THE CAPTURE MUST BE A PARAMETER — the escape alone is not the defect.** `Callable[String()] make(): return (): mk("hel","lo")` (same escape, no capture) is CLEAN 3/3 at HEAD. So is the same capture without the escape.
