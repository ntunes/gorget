- **🆕🧹 [MED — `TODO.md` HAS NO FINAL NEWLINE, so every `>>` append silently CORRUPTS the last pointer row; found 2026-09-04 by R49 Track Q's executor when a planted-marker RED-verification landed mid-line instead of at column 0] The file that carries session state cannot be safely appended to.**
  - **MEASURED.** `tail -c 1 TODO.md | od -c` → `246`, i.e. the tail byte of a multi-byte UTF-8 character, **not `\n`**. `DONE.md` by contrast ends `\n`. Tree-wide census: **9 tracked files lack a final newline** — regenerate the SET, never the denominator, with `python3 -c "import subprocess;print('\n'.join(p for p in subprocess.run(['git','ls-files','-z'],capture_output=True).stdout.decode().split(chr(0)) if p and open(p,'rb').read()[-1:] not in (b'\n', b'')))"` (the tracked-file count moves every merge; the 9 is the load-bearing figure). The other 8 are fixtures where it is plainly deliberate (`tests/fixtures/embed_content.txt` and `embed_hello.txt` are embedded-content fixtures whose bytes ARE the expected output; the six `tests/fixtures/known_gaps/snag5{2b,3,8}*` files). **`TODO.md` is the only one where it is a hazard**, because it is machine-regenerated, appended to constantly, and its last line is a live `- [`tNNNN`](todo/tNNNN.md)` pointer row.
  - **THE HAZARD, DEMONSTRATED.** `printf '<<<<<<< HEAD\n' >> TODO.md` does **not** put that text at column 0 — it appends it to the end of the `t1065` pointer row, producing a truncated-looking hybrid line. This was observed live: the first RED-verification attempt for the R49 conflict-marker guard read as a false negative when the guard was in fact correct and the *append* was wrong.
  - ⚠ **DISCRIMINATED, NOT SPECULATED.** R49 recorded that the real corruption in `ef171a34a` was a **truncated pointer line** (`t0991`, cut mid-sentence) which `POINTER_RE` prefix-matched and therefore counted. This mechanism produces **exactly that shape**. Whether it *caused* that specific corruption is **not established** and is not claimed here — what is established is that the mechanism is live and yields the same signature.
  - **WHY THE GENERATOR DOES NOT REPAIR IT.** `scripts/todo_index.py` reads with `.read().split('\n')` and writes with `'\n'.join(lines)`. That round-trip is faithful in both directions: a file with a trailing newline keeps its final empty element and gets it back; a file **without** one keeps not having one. The generator perpetuates the state rather than normalizing it, so `--write` will never fix this on its own.
  - **INTENDED:** make `scripts/todo_index.py --write` terminate `TODO.md` with a single `\n`, and pair it with a guard that the file it regenerates ends in a newline. ⚠ **Scope the guard to the GENERATED file, not tree-wide** — a blanket "every tracked file ends with a newline" lint would be wrong: the 8 fixtures above depend on not having one, and a lint that has to carve them out is the allowlist shape this repo keeps retiring.
  - **WHY THIS WAS NOT REPAIRED INLINE.** The one-line fix rewrites `TODO.md`'s bytes, and `TODO.md` is the file every concurrent track and the orchestrator's handover block are editing during a round. Landing it mid-round is a guaranteed merge collision on the exact file whose corruption this item is about. It wants a quiet moment, not a parallel one.
