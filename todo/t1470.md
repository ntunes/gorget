- **🆕🚨 [HIGH — REFERENCE LAGS THE SELF-HOST. Found 2026-09-06 by R51 Track A's layer probe.]**

  A `trait Readable: int get_val(self)` behind `Box[Readable]`, read through a struct field / parameter / `&`-parameter, prints **`0 0 0` on Rust gg** and **`41 41 41` on the self-host**. The self-host is RIGHT and the reference is WRONG.

  ⚠ **THE SHAPE IS ONLY REACHABLE WITH THE METHOD RENAMED.** Spelled `get`, it collides with `Box`'s own `get` arm and fails to build on both lanes — which is why the family read as "already rejected" and no one looked. Renamed `get_val`, it **builds and runs on both lanes** and the divergence appears. SIX-Q #6: the passing-by-failing cell was green for a reason unrelated to the property.

  ⭐ **WHY THIS IS NOT A FOOTNOTE.** The succession plan makes the self-host the primary reference at parity, and Core #8 says reference-grade is the bar, not parity with a possibly-wrong reference. This is the *"reference lags the self-host"* finding the plan anticipates, so the fix is **on the Rust side as oracle hygiene** — never dumbing the self-host down to match.

  **INTENDED:** both lanes print the payload. The Rust-side defect shares the `deref_by_value_handle_receiver` enrolment root cause tracked by `todo/t1373`; confirm whether that fix subsumes it before opening a separate write site.

  ⛔ **FIXTURE CONSTRAINT (`todo/t0685`, binding, re-measured 2026-09-06):** `.get()` nets cannot be ported to LLVM for non-primitive payloads -- `Box[String].get()` is an `llc` HARD ERROR at base. **Use `Box[int]` for every `.get()` cell.**
