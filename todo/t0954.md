- **🆕🐛 [MED — a LEAK from ordinary safe syntax, BOTH backends, `gg check` clean; found 2026-09-03 by R48 Track T-a1 while ASan-attributing the three rows that round admitted to `tests/sanitize/LEAK_ALLOWLIST.txt`] `vector.map(f)` returning a heap element type leaks EVERY ELEMENT: the accumulator array is minted with a NULL `elem_drop`.**
  ```gorget
  String label(int n):
      return int_to_str(n * 10)

  void main():
      Vector[int] nums = [1, 2, 3]
      auto out = nums.map(label)
      print(out.get(0).unwrap())    # prints 10, leaks all three Strings
  ```
  **THE EMITTED C IS THE WITNESS.** The runtime's own array builders store the hook — `gorget_str_chars` (`src/backend/c/runtime/runtime_string_array.c:52-55`) does
  ```c
  GorgetArray arr = gorget_array_new(sizeof(Str));
  arr.elem_drop = (__gorget_drop_fn)gorget_string_free;
  ```
  — while the `map` accumulator for the same 32-byte `Str` element does
  ```c
  __v68 = (int64_t)32LL;
  __v69 = gorget_array_new(__v68);   /* no elem_drop, no elem_clone, no elem_materialize */
  ```
  The backing array **is** freed at scope exit — there is no `gorget_array_push` record in the ASan report — and the `Str` payloads it held are not.
  ⭐ **THE CALLEE IS A NAMED FUNCTION IN THE REPRO, DELIBERATELY.** A closure literal would add `todo/t0953`'s environment leak on top and the two mechanisms would be reported as one row; with `label` there is no closure anywhere in the program, so the only records are the leaked elements. `nums.map((int n): int_to_str(n * 10))` leaks `__gorget_closure_env_alloc*1` **and** `str_alloc_copy*1` — the two mechanisms superimposed — which is what the ISOLATION buys.
  ⭐ **THE AXIS IS PRODUCER x ELEMENT TYPE, AND NEITHER COLUMN IS THE DEFECT ALONE.** Measured, `gg build --sanitize`, records off the ASan report:

  | producer | element | HEAD |
  |---|---|---|
  | `map` | `String` (heap payload) | **LEAKS** `str_alloc_copy*1` — 9 B in 3 allocations |
  | `map` | a struct owning a `Vector[int]` | **LEAKS** `gorget_array_push*1` — 192 B in 3 allocations |
  | `filter` | `String` | **CLEAN** |
  | `sorted` | `String` | **CLEAN** |

  ⚠ **THE TOP FRAME CHANGES WITH THE ELEMENT TYPE WHILE THE MECHANISM DOES NOT** — so this class CANNOT be attributed by top frame, and a reader who groups by frame will split one defect across two items (A5/K8's refutation of top-frame grouping, met here in the wild). ⚠ **`gorget_array_push` is ALSO `todo/t0955`'s frame**, and they are different defects: there the leaked object is the husk a `flat_map` callee RETURNED, here it is the inner field of an element the accumulator never dropped. Discriminate by the program, not the symbol.
  ⭐ **THE CLEAN CELLS ARE LOAD-BEARING, not filler.** `filter` and `sorted` are ELEMENT-PRESERVING — they carry the source's elements rather than minting new ones — and they are clean. That is what localises the defect to the accumulator an element-TRANSFORMING producer mints, and it is the first place a fix should look: two array ctors in the same expander, one that installs the three hooks and one that does not.
  ⭐ **RECORDS vs ALLOCATIONS.** ASan merges identical allocation stacks, so three leaked Strings from one `int_to_str` call site are **one RECORD in three ALLOCATIONS**. The record count does not scale with the element count; the allocation count does. A net that pins the record count is pinning the number of producing SITES.
  **SAME FAMILY AS `todo/t0873(b)`, DIFFERENT WRITE SITE.** Both are "an array exists whose `elem_drop` was never synthesised". `t0873(b)` is `Vector[Callable].push`, where the ELEMENT TYPE (`Named("Callable__GorgetClosure")`) is what bypasses the synthesis at `src/lir/lower/insts.rs`. This one has an ordinary `Vector[String]` — the element type is one the compiler handles correctly everywhere else — so it is the ACCUMULATOR MINT in the HOF expander that skips the hook, not the element type. Fixing `t0873(b)` does not close it, and vice versa. ⚠ Ask, at whichever site is fixed, why the array ctor has two spellings at all: one that installs the three hooks and one that does not (Core #4 — the fix is the producer, not the arm).
  **DISCRIMINATED from `todo/t0955`** — that is the `Vector[U]` a `flat_map` CALLEE returns never being freed, which shows up as a `gorget_array_push` record (the husk's own backing store) with the elements as INDIRECT records underneath it. Here there is no husk and the leaked Strings are DIRECT.
