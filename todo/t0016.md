Census, one probe per name, all identical: **`abs` · `div` · `remove` · `exit` · `free` · `read` · `write` · `index` COLLIDE; `open` is fine.** ⚠⚠ **So the reserved set is not a curated list — it is "whatever libc happens to declare", which makes it PLATFORM-DEPENDENT**: the same program compiles for one user and fails for another on macOS/musl/a newer glibc. ⚠ **This is a LAYERING defect, not a naming policy question.** The C-emit boundary is the one place a runtime symbol name IS the contract; user names have no business sharing that namespace unmangled — and **structs already mangle (`__gg_Point`), so the mechanism exists and simply is not applied to functions.** ⚠ The diagnostic is the other half: the user wrote Gorget and gets a C compiler error naming a C symbol, with no hint that renaming their function is the fix. **INTENDED:** compiles and prints `7` (nothing in the spec reserves `abs`, and there is no `abs` builtin); a teaching check-time rejection is an acceptable alternative — accept-then-cc-fail is not.
