- **🆕🧹 [LOW — a SECOND, WEAKER writer on the element-metadata axis (Layering rule 3); found 2026-09-04 by R49 Track N2 while establishing that its runtime check could not false-positive] `emit_collection_constructor` installs `elem_drop` and neither `elem_clone` nor `elem_materialize`.**
  Two writers decide a collection's element metadata and they do not agree on how much of it to write:
  - `src/lir/lower/insts.rs::infer_fn_ptr_stores_from_types` writes the TRIPLE — `elem_drop` at offset 40, `elem_clone` at 48, `elem_materialize` at 56 — and consults `type_drop_fns`, so it covers `Recursive` and `Custom` drop strategies.
  - `src/backend/c_lir/helpers.rs::emit_collection_constructor` writes `X.elem_drop = (__gorget_drop_fn)…` and stops. It reads `elem_drop_fn_for_c_type`, which resolves `StructDef.elem_drop_fn` — populated only for trivially-droppable types — so it is both SHORTER and NARROWER than the other writer.
  Re-derive the census, and note it takes TWO greps because the Dict arms spell it differently: `grep -n 'elem_drop = (__gorget_drop_fn)' src/backend/c_lir/helpers.rs` reads **2** (the Tier-1 typed array arm and the Tier-2 name-parse array arm) and `grep -n 'val_drop = (__gorget_drop_fn)' src/backend/c_lir/helpers.rs` reads **2** more (the Dict value arms, same shape one axis over). `grep -c 'elem_clone = \|elem_materialize = ' src/backend/c_lir/helpers.rs` reads **0** — the companion hooks are written nowhere in the file.
  ⭐ **WHY A HALF-PAIR IS NOT MERELY UNTIDY.** `gorget_array_extend` memcpys and then deep-clones the appended range only when the DESTINATION's `elem_clone` is set. A destination carrying `elem_drop` without `elem_clone` therefore takes the raw-memcpy path and ends up ALIASING the source's buffers while also being registered to free them — the double-free shape, not a leak.
  ⚠ **MEASURED DORMANT, WHICH IS WHY THIS IS LOW AND NOT HIGH.** Its emissions are textually distinctive (`__vNN.elem_drop = `, an SSA temp) and appear in ZERO of 99 programs checked on 2026-09-04: 26 hand-written HOF/ownership probes plus all 73 buildable `tests/fixtures/*.gg` that call `.map(` / `.flat_map(` / `.extend(`. Every `.elem_drop = ` in those emitted files is runtime-prelude text (`runtime_string_array.c`'s own array builders, which do install a proper drop+clone pair) or `gorget_array_clone` / `gorget_set_to_array` propagating both hooks. The user's own `Vector[T]()` goes through the LIR-layer writer. **Re-verify with `grep -c '__v[0-9]*\.elem_drop = ' <emitted>.c` before acting: a nonzero reading anywhere is this item going live.**
  ⊕ **The runtime check added alongside this filing is deliberately IMMUNE to it, and that is not the same as fixing it.** `GORGET_ARRAY_EXTEND_CHECK` compares hooks asymmetrically — it fires when the DESTINATION lacks or contradicts a hook the SOURCE carries (the aliasing direction, which includes a half-pair destination) and stays silent when the destination is the richer of the two (safe). So a half-pair SOURCE cannot produce a false abort, and a half-pair DESTINATION still trips. The check makes the guard sound; it does not make the second writer agree with the first.
