- **🆕🚨💥 [CRITICAL — REGRESSION INTRODUCED BY R48 TRACK D2; MEMORY-UNSAFE, `gg check` rc 0, rc 134 on BOTH backends; found 2026-08-31 by the track's own executor while probing siblings of the output-review's blocking finding] One single-owner handle in TWO element slots double-frees.** `all.push(m); all.push(m)` on a `Vector[Mutex[int]]` — and the two-collections spelling `a.push(m); b.push(m)`, which is the same defect — give `free(): double free detected in tcache 2` on C and LLVM and `AddressSanitizer: heap-use-after-free` in `gorget_mutex_free` under `--sanitize`. **GREEN at the t0840 base blob `3b8a5561`** (rc 0, prints `2`), but green there only because the element slot held garbage that was never a real handle; the t0840 write repair put the handle in the slot and N slots became N owners.
- **WHY THE ONE-SLOT REPAIR DOES NOT REACH IT, and why no executor-level lowering can.** For a single slot the repair transfers the one owner to the collection and degrades the source to a BORROW, so exactly one drop runs (`mutex_vector_live_source_single_owner.gg` / `rwlock_vector_live_source_single_owner.gg` pin that, on the value lanes and under ASan). That has NO N-slot analogue: `elem_drop` is a per-ARRAY function pointer, not per-element, so every slot holding the handle will drop it. And there is nothing to put in slots 2..N — `Mutex[T]`/`RWLock[T]` have no clone path, which is the whole reason the class exists.
- **⛔ THIS IS THE OWNER ASK MADE CONCRETE, NOT A SEPARATE BUG.** `AGENTS.md` § Ownership at Consuming Positions lists `Guard` — what `Mutex.lock()` RETURNS — among the single-owner-by-design carve-outs that emit `E_MoveWithoutOperator`, and does NOT list `Mutex` or `RWLock`. **If they join that list this program is REJECTED and the gap closes with no lowering change at all. If they do not, they need a real clone path**, which is a semantics change of its own (a second independent mutex is wrong; a shared one is `Shared[Mutex[T]]`, a different type). Both are owner calls. **Do not let an executor pick one to make a red cell green** — the round that found this deliberately did not.
- **THE OPTION THAT WAS CONSIDERED AND NOT TAKEN, recorded so it is not re-derived:** suppress `elem_drop` wiring for single-owner handle element types, so the collection holds BORROWS and the source local stays the sole owner. That is memory-safe in every shape measured (one slot, N slots, live and dead sources) and needs no owner call — but it is a second unreviewed design pivot inside a track already past its output-review, and it trades the double free for a DANGLE whenever the collection outlives the source. Weigh it against the reject; do not ship it without its own gauntlet.
- **DISCRIMINATED from `t0907`** (refcount handles missing `clone_inplace_fn` — a different family, and those types DO have a clone path) **and from `t0108`** (the callee dropping a bare refcount PARAM — no container, no second slot).
- **INTENDED, under the accept resolution:** prints `2`, rc 0, ASan-clean. **Under the reject resolution:** a check-time `E_MoveWithoutOperator`, and the repro moves to a reject test.
