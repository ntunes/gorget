- **🆕📐 [MED — charter] A `String &`-param bind still costs ONE clone where a hand-writer pays ZERO.** The other resource types bind a `&`-param as a zero-cost CoW Ptr alias; String cannot, because a Copy-mode store of a String read through a pointer is `gorget_string_copy_cow` at BOTH backends (an eager deep copy), not the shallow `memcpy` every other aggregate gets. The frontend now tags that temp honestly (drop-registered + `FreshOwned`, which is what removed the double-clone at the return boundary), but the eager copy itself is a backend-layer decision the GIR cannot express: `AssignMode::Copy` means "shallow alias" for `GorgetArray` and "deep clone" for `GorgetString`. Reference-grade fix: make the GIR say which it means (the LIR already spells the shallow form as `SlotStore { is_move: true }`, and `insts.rs`'s own comment calls that "a SHALLOW byte-copy (an alias / borrow)"), then let the boundary chokepoints materialize uniformly. Related: the alias-at-bind leaves the now-dead auto-deref temp emitted (a wasted 64-byte struct `memcpy` per bind — no allocation, but it should be DCE'd or not emitted).
