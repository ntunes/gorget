- **🆕🐛 [HIGH — AN INSTRUMENT-CORRUPTING DEFECT, FOUND BECAUSE A TRACK VERIFIED ITS INSTRUMENT BEFORE TRUSTING IT. Measured 2026-09-06 by R51 Track H's scout.]**

  A blast-radius measurement over the fixture corpus reported **32/33 changed fixtures with the membership WOBBLING BETWEEN RUNS**. The cause is not the change under test:

  ⛔ **`gg build --emit-c-lir` IS NONDETERMINISTIC AT HEAD.** Same binary, same source, different emitted C. Measured HEAD-vs-HEAD over 10 fixtures; the delta is the emission **ORDER** of `static inline …__drop` definitions — a hash-iteration-order leak. Regenerate: `/tmp/scoutH51_selfdiff.sh` (⚠ **`/tmp` is pruned at round close — re-derive it as a HEAD-vs-HEAD diff over ≥10 fixtures if the artifact is gone**).

  ⭐ **WHY THIS IS FILED AT HIGH RATHER THAN AS A CURIOSITY.** It **silently corrupts every C-emit differential**, which is the primary instrument for answering *"what does this change actually affect?"*. A track using it without a HEAD-vs-HEAD control will attribute pre-existing noise to its own patch — in **both** directions: phantom changes it did not cause, and real changes hidden in the noise floor.

  ⚠ **THE CONTROL THAT MAKES IT SAFE, AND WHICH ANY TRACK USING THIS INSTRUMENT OWES:** normalise to a **sorted line multiset**, then run **HEAD vs HEAD over the whole corpus and require 0 differences** before trusting a single row of the real comparison. Track H did exactly this and got a clean 0/5419 control, which is the only reason its 23-fixture blast radius is believable.

  **INTENDED:** `--emit-c-lir` is deterministic — emission order of `__drop` definitions is stable across runs (sort the iteration, or emit from an ordered structure). SIX-Q #5: this is about emission ORDER, not emission, and order is only visible in the IR.
