- **🆕🚨 [HIGH — A BARE LOCAL BIND OF A REFCOUNT HANDLE CORRUPTS THE SOURCE AND FABRICATES THE DESTINATION. No call, no container, no sigil: two names and a read. SIGSEGV on one path and SILENT WRONG OUTPUT at rc 0 on the other, both backends. Found 2026-09-05 by R50 Track G while giving the `(Trivial, Trivial)` row of `src/ir/types.rs`'s ownership table a disposition in topic 30's scope disclosure.]**

  ```gorget
  from std.sync import Shared

  void main():
      Shared[int] a = Shared[int](7)
      Shared[int] b = a          # <-- the bind is the trigger
      print(f"{a.get()}")
      print(f"{b.get()}")
  ```

  **TWO ROWS, ONE DEFECT — and the quiet one is the reason both reads are in the repro:**
  | read after the bind | C | LLVM |
  |---|---|---|
  | `a.get()` | **rc 139** (ASan: `SEGV … in Shared__int64_t__get`) | **rc 139** |
  | `b.get()` **alone** | **rc 0, garbage integer** | **rc 0, garbage integer** |

  ⛔ **A fix that clears the crash and stops leaves the silent-wrong-output row standing.** ISOLATED: delete the bind and the same program prints `7` at rc 0.

  **MECHANISM — READ OFF THE EMITTED C, NOT INFERRED.** `gg build` emits:
  ```c
  static inline Shared__int64_t  Shared__int64_t__clone(Shared__int64_t  self) { return gorget_shared_clone(self); }
  static inline void             Shared__int64_t__drop (Shared__int64_t* self) { gorget_shared_drop(*self); }
  ...
      __s1 = __v1;                            /* a */
      __v3 = &__s1;                           /* the SLOT ADDRESS */
      __v5 = Shared__int64_t__clone(__v3);    /* ...into a BY-VALUE parameter */
      __s3 = __v5;                            /* b */
  ```
  `clone` takes the handle **by value**; `drop` takes it **by address**; the bind passes the address to `clone`. `strong` is field 0, so `__atomic_fetch_add(&s->strong, 1)` **increments the pointer variable `__s1` itself by one byte** (UBSan reports a misaligned address), and the "clone" returned is `&__s1` — so `b` is a handle pointing at **`a`'s own stack slot**. Hence `a` reads misaligned (SEGV) and `b` reads garbage.

  ⚠ **AN EARLIER VERSION OF THIS ITEM ASSERTED A DIFFERENT MECHANISM AND EVERY CLAUSE OF IT WAS FALSE** — *"duplicates the handle without an incref and drop-registers BOTH names, so the first scope-exit drop frees the control block"*. An incref **is** emitted; **nothing has been dropped** when it crashes (ASan's frame is the FIRST `.get()`, before either drop) and both drops take the correct `&local` form. That wrong mechanism pointed at `drops.rs`, **where nothing is broken.**

  ⭐⭐ **THIS IS CORE #4 SIBLING-SITE DRIFT ON THE CLOSED `t0840`** (DONE.md 2026-08-31, *"`Vector[Shared[T]]` segfaulted on both backends because a handle's REPRESENTATION says nothing about its PROVENANCE"*). That fix **added no metadata; it added CONSUMERS** of `is_refcount_clone_type_name` — the container write, the receiver, and the element read. `src/lir/lower/insts.rs` states this exact failure verbatim: *"Passing the slot address made `Shared__T__clone` incref whatever the SLOT ADDRESS pointed at (t0840: `v[i].get()` / `for h in v` both SEGV'd on both backends)"*. **The bare bind is the FOURTH route and consults nothing:**
  ```
  grep -rn "is_refcount_clone_type" src/                              # the consumers
  grep -c  "is_refcount_clone_type" src/ir/lowering/stmts/mod.rs      # -> 0
  ```
  ⭐ **The contrast that localizes it in one line: `Shared[int] b = a.clone()` prints the intended `7 / 7`**, because the explicit-clone path DOES read the predicate (`src/ir/lowering/exprs/methods.rs`). Same program, same types, one spelling apart — Core #8's two-spellings-different-results.
  ⇒ **`t0840`'s litmus test is the one that was never asked: "if the fix is *add the missing call to site N*, what stops site N+1?"** Nothing did. The fix here is the fourth consumer **plus** whatever makes a fifth impossible — an arm-count lint over the sites that hand an operand to a `clone_fn`.
