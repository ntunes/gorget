Neither is the `t0840` marshalling class: the bytes go to the right places, the retain/release COUNT is wrong.
  - **(a) CONTAINER CLONE.** `outer.push(inner.clone())` where `inner: Vector[Shared[int]]`. `gorget_array_clone` (`runtime_array.c`) memcpys the element bytes and then calls `elem_clone` on each slot IF the array carries one — the hook that makes a `Vector[String]` clone deep. `elem_clone_fn_for_type` (`src/lir/lower/types.rs`) reads `TypeMetadata.clone_inplace_fn`, and the refcount TypeDefs (`ensure_shared/weak/channel_type_def`) set `clone_fn` but NOT `clone_inplace_fn` — and no `{T}__clone_inplace` wrapper is emitted for them. So the slot stays NULL, both arrays alias the same handles with the refcount unchanged, and both drop: `AddressSanitizer: heap-use-after-free` in `gorget_shared_drop` ← `Shared__int64_t__drop` under TWO nested `gorget_array_free` frames. **DISCRIMINATOR: the identical `Vector[Vector[String]]` shape is ASan-clean**, because `GorgetString` carries `clone_inplace_fn`.
  - **(b) DICT VALUE-BIND ITERATION.** `for (k, v) in d` over `Dict[String, Shared[int]]` over-releases, so `gorget_map_free` walks its second entry into an already-freed control block: same ASan signature, one `gorget_map_free` frame. **TWO DISCRIMINATORS, both measured:** the identical loop over `String` VALUES is clean, AND `for h in v` over a `Vector[Shared[int]]` is clean — the Vector element bind takes the `Ptr`-borrow path (`index_load_borrow`, drop-disposition BORROW) and never needs a copy at all, while the Dict value bind copies the value OUT and expects the copy to be independent.
- **⚠ (a) AND (b) ARE ONE ROOT, NOT TWO — CORRECTED 2026-08-31 by the R48 Track D2 output-review, which was right and the executor's first reading was wrong.** The original text called (b) a bind-disposition problem needing its own fix. It is not. `gorget_map_iter_value` (`src/backend/c/runtime/runtime_map.c:1227`) memcpys the value out and then calls **`mm->val_clone(out)`** — the SAME in-place deep-clone hook `gorget_array_clone` calls as `elem_clone`. `val_clone` is wired at offset 112 from `elem_clone_fn_for_type` (`src/lir/lower/types.rs`), which reads `TypeMetadata.clone_inplace_fn` and returns `None` for a refcount handle. So the hook is NULL on BOTH paths, the copy is a bitwise alias with no incref, and the `for` bind's `bind_owned_for_drop(.., LoopOwned::Fresh)` then registers a drop for a reference that was never taken. The `String` twin is clean on both paths for the same one reason: `GorgetString` HAS `clone_inplace_fn`.
