- **[MED — RE-OPENED 2026-08-31 by R48 Track F's own output-review, after being closed the same
  day. Give the round-close `DONE.md` entry a TYPED MARKER, so the band-anchor guard stops
  name-matching prose.]**

  **WHAT THE FIRST CLOSE GOT RIGHT, and keep:** `scripts/clone_meter_check.sh`'s three modes now
  all have callers, which was this item's original complaint — `--track`
  (`clone_meter_check_refuses_an_unattributed_track`), `--pin-staleness`
  (`clone_meter_pin_provenance_shas_resolve`), `--anchor-age`
  (`clone_band_anchor_is_reseeded_before_work_resumes`). The lint's narrowed predicate — *"commits
  exist after the round-close records commit with the anchors un-reseeded"* — is also right, and it
  answers this item's original objection to lint-ness (a raw predicate would red the records commit
  that closes a round). Both are RED-verified in both directions. **None of that is what re-opens
  this.**

  **⛔ WHAT RE-OPENS IT: THE GUARD ANSWERS "HAS A ROUND CLOSED?" BY MATCHING A PROSE HEADLINE, AND
  SEES ABOUT 8% OF THEM.** Enumerated by hand over every round-ish headline in `DONE.md`
  (regenerate the populations with `bash scripts/clone_meter_check.sh --round-close-census`):

  | headline shape | closes | matched by `--anchor-age` |
  |---|---|---|
  | `**Round <ROMAN> close` | 31 | no |
  | `**Round <ROMAN> (Rnn) close` | 2 | no |
  | `**Rnn CLOSED` (R45) | 1 | no |
  | `**Rnn close-out` (R43) | 1 | no |
  | `**Rnn — <theme>` (R44) | 1 | no |
  | `**ROUND <ROMAN> (Rnn) CLOSED` (R47) | 1 | **yes** |
  | `**ROUND <ROMAN> (Rnn) — <theme>` (R42, R43) | 2 | **yes** |

  ⚠ **The two closes immediately before R47 are both invisible to it.** And the failure direction
  is a **FALSE GREEN**, which is quieter than the false RED the same guard had a day earlier — so
  it will not announce its own uselessness.

  **⛔ DO NOT FIX THIS BY WIDENING THE REGEX. MEASURED.** The obvious widening
  (`\*\*(ROUND|Round|R[0-9])`) matches **79** headlines, including mid-round entries — `**R42 Phase
  4b`, `**R41 T-FMT-A`, `**ROUND-33 rolling item 4`, `**R43 Track C`. That re-creates a false RED
  whose printed remedy is a **mid-round band re-seed**, which
  `tests/integration.rs`'s salami assertion exists to prove destroys the band. A false RED that
  instructs the harmful action is worse than no check at all.

  **THE REAL DEFECT IS ONE LAYER UP, AND IT IS CORE #2.** A round close is a semantic event being
  recovered from an identifier string. There is **no rule anywhere on the round-close entry's
  shape** — not in `AGENTS.md`, not in `tests/lints.rs` — so the convention has drifted through
  seven spellings across 47 rounds, and no predicate over an unenforced convention can be both
  complete and precise. **The fix is a typed marker the writer emits and the reader matches
  exactly**, e.g. a fixed token in the round-close entry, plus a lint that a round-close entry
  carries it. Then `--anchor-age` matches the marker and its reach is 100% by construction.

  **⚖ WHY THIS IS AN OWNER / ROUND-PROCEDURE DECISION AND NOT A CODE FIX.** Emitting the marker is
  a change to Round-lifecycle step 5 in `AGENTS.md`, and `wc -c AGENTS.md` is **exactly**
  `AGENTS_MD_SIZE_CEILING` — the line has to be paid for by compacting a neighbouring rule, which
  that ratchet's own comment instructs and which is a deliberate reviewed edit. Retro-fitting the
  ~38 historical entries is a separate question and probably a *no*: the record should not be
  rewritten to please a guard. A marker applied going forward is enough, because the guard only
  ever asks about the newest close.

  **⊕ WHAT STOPS THE GAP BEING SILENT UNTIL THEN — already landed, do not re-do it.**
  `tests/lints.rs::done_md_round_close_shapes_are_pinned` pins BOTH populations
  (`done_md.round_close.anchor_age_matched` and `done_md.round_close.roundish_headlines` in
  `scripts/figures.db`), so a close landing in a shape the predicate cannot see moves the round-ish
  count without moving the matched count and **fails**. RED-verified with an `**R49 CLOSED` entry:
  `--anchor-age` stays green on it, the pin fails. ⚠ It also fires on a mid-round round-ish entry;
  the remedy there is a 30-second adjudication and a number bump, never a re-seed, and the failure
  text says so.

  **⚠ THE PROCESS LESSON, because it cost two folds in one round.** The first version of the
  predicate read the top dated entry of ANY kind (false RED, harmful remedy). The second read
  `**ROUND ` and was justified with *"`ROUND ` is the stable prefix"* — **the enumerator's own
  regex output presented as the enumeration** (readiness item 2, six-questions #3). Running a
  predicate and reporting what it matched cannot show you what it misses. Both the executor and the
  orchestrator confirmed the "3" without asking whether 3 was plausible for a file spanning 47
  rounds.
