- **🆕🐛 [MEDIUM — codegen type-precision; discovered 2026-07-24 chasing the CI timeout] Self-host emits `int32 → void*` assignments that Apple clang 21 rejects (hard error, un-`-w`-suppressible).** The self-host's `--lir-c` output contains `void* __s2 = __v2;` where `__v2 = (int32_t)0LL` — a NULL-ish sentinel the lowering typed as `int32` but stored into a `void*` slot (repro line: stage1.c:~22866, `__s2 = __v2`). Functionally 0 (benign at runtime) but type-incorrect C: gcc / older clang emit a `-Wint-conversion` *warning* (suppressed by the `cc -w` in the self-host stage tests), so **CI (Linux/gcc) is unaffected**; Apple clang 21 promotes `-Wint-conversion` to a default *error* that `-w` does not downgrade. Consequence: `self_host_stage1_clone_ceiling` / `self_host_bootstrap_fixed_point` / the pinned-8MB self-compile **cannot run locally on recent macOS** (cc step fails at ~135s, well before any assert). Fix = give the sentinel/slot a consistent pointer type at the lowering source (the void* slot should receive `(void*)0`, not an int32), NOT paper over with `-Wno-int-conversion`. Pre-existing (codegen; predates the 2026-07-24 timeout fix). Verify it still repros before fixing.
