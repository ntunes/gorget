- **[MED — owner ruling 2026-08-30] Periodic clone-waste AUDIT, with a trigger that cannot rot.**
  The owner ruled that **slow accumulation stays UNBOUNDED** — sub-1% growth per round "may just be the
  compiler growing organically", and a cumulative cap (a down-only trend anchor) was explicitly
  **rejected**, because it would escalate on organic growth. The replacement obligation is a
  **periodic audit that we are not cloning wastefully**.
  - **Why an anchor was the wrong instrument, and the audit is the right one.** A cap measures the
    *number*; it cannot distinguish "the compiler grew" from "the compiler clones worse" — the exact
    distinction the owner asked for. The audit measures **waste directly**, per clone site, against the
    CoW materialization contract.
  - **⚠ THE AUDIT HAS NO TRIGGER TODAY, AND A CADENCE IN PROSE IS THE THING CORE #6 EXISTS TO FORBID.**
    `scripts/clone_attribution.sh` is cited in five prose sites (`tests/integration.rs:30418`, `:30633`,
    `:30677`, `:31143`, `:31150`) and **wired into nothing** — no gate, no CI target, no test. `git log`
    shows it untouched since its own creation commit `57cd0968`.
    **⚖ OWNER RULING 2026-08-30 — THE TRIGGER AND THE FORM ARE NOW DECIDED:** *"maybe this should be run
    at round close and measure increase. at least just a small table report that I can see."*
    ⇒ **Trigger = ROUND CLOSE, every round.** ⇒ **Form = a small table showing the INCREASE**, not just
    current state.
  - **It is CHEAP, and the battery already pays for the workload.** The script's header: *"`--clones=stats`
    instrumentation measured at ~1% wall on the self-compile workload — cheap enough to run routinely."*
    Its canonical invocation is the SAME workload `self_host_clone_ceiling` and
    `scripts/self_host_mem_baseline.sh` already build at round close:
    `scripts/clone_attribution.sh ./target/release/gg tests/fixtures/self_host_lowerer/driver.gg -o /tmp/drv
    -- tests/fixtures/self_host_lowerer/driver.gg "$PWD/lib" --lir-c` (`TOPN` widens the table).
  - **The one new piece: a COMMITTED BASELINE to diff against.** The tool reports current state only;
    "measure increase" needs the previous round's per-reason rollup and top-N counts committed, so the run
    prints `reason | sites | now | prev | delta`. Reuse R47 F5a's round-open baseline rather than inventing
    a second one.
  - **⛔ IT IS A REPORT, NOT A GATE — it must never RED.** The owner ruled accumulation UNBOUNDED and
    rejected a cap; a table that fails the build re-introduces the cap through the back door.
  - **⚠ AND THE INSTRUMENT CANNOT CURRENTLY SEE THE FAILURE CLASS (Core #13).** Its own header states it
    attributes **~3.5%** of aggregate `array_clone+string_clone` volume: synthesized deep `Type__clone`
    cascade into leaf calls, explicit `.clone()` mints no CloneId, and LIR-layer emissions have no
    CloneId concept. **⊕ Read that number correctly — "certifies no waste over an unexamined 96.5%" was
    unfair to the tool.** The 3.5% is *leaf calls*; the rows are top-level clone EVENTS whose cascades
    account for far more, and the script says so: *"killing a top-level clone removes its ENTIRE cascade."*
    ⇒ **The ranking IS the actionable lever; what it is NOT is a measure of total volume**, and an
    LIR-layer clone is invisible to it entirely. **The report must state which of the two it is**, or a
    clean table reads as an all-clear it cannot support. Coverage is filed separately as [[t0546]] (mint CloneIds at the LIR layer) — that
    is this item's DEPENDENCY, not a duplicate of it.
  - **Siblings already filed — read before designing:** `t0546` (instrument coverage), `t0561` (per-reason
    clone budgets off the CloneId×reason join), `t0012` (the current measured lever: 71% of attributed
