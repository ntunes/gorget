- **[LOW — PRECISION residual, not a correctness one; measured while closing `t0699`] Call sites inside `meta`-expanded bodies get the CONSERVATIVE receiver-mutation answer, because the classifier runs before the expansion.** The CoW prescan reads `semantic::safety::ReceiverMutations`, which the semantic pass populates per method-call span. `meta if` / `meta for` / `meta match` bodies — most sharply a `meta for` generating MATCH ARMS, where the arm's pattern binding has no resolved type at all until expansion — are expanded during IR lowering, so those spans are absent from the map and `CowPrescan::call_mutates_receiver` takes its unclassified branch. That branch answers MUTATING, which is the sound direction (`tests/fixtures/cow_user_mutator_meta_generated_arm.gg` is the pin, and the other direction was measured to REGRESS against stock), so the cost is extra private copies of bare-param receivers in meta-generated code, never a use-after-free.
- **Measure it before deciding it matters.** `GG_REPORT_RECV_MUT=1 gg build F` prints `[recv-mut-miss] <name>` per unclassified query. Census over `tests/fixtures/*.gg` (2147 files, 2026-08-29): the residual misses are dominated by lowering-SYNTHESIZED nodes — iterator-pipeline spines (`push`/`clone`), f-string `display` — with the meta class visible as the `lib/xtd/dataframe.gg` `meta for`-generated `Column` match arms (`null_count`/`is_null`/`col_len`). No fixture in the corpus showed a clone-count regression from it.
- **Two candidate fixes, neither free.** (a) Run the receiver-mutation classification again after meta expansion — rejected on sight: that is a SECOND classifier for one axis inside the lowering layer, which is the Layering rule 3 violation `t0699` existed to retire. (b) Expand `meta` before semantic analysis so there is one AST for both passes — architecturally right and much larger; `meta` currently reads `Self`-bound type information that only exists at monomorphization. Neither is worth doing for the measured cost; file so the *reason* the conservative branch exists is not mistaken for an oversight.
- **Do NOT "fix" this by flipping the unclassified branch to read-only.** Measured 2026-08-29: that makes `cow_user_mutator_meta_generated_arm.gg` rc 139 under BOTH method names, which is worse than the pre-`t0699` compiler (whose hand list rescued the shape whenever the name happened to be on it).
- **Sibling, CLOSED 2026-08-31 (R48 Track C, see DONE.md):** what was `todo/t0134` — generic-equip instances are classified during lowering on the self-host lane too, and had the same shape of gap. It is fixed: the classification now rides along in the generic-instances pre-pass, keyed on the MONO'D name. ⚠ That fix does NOT retire this item and the two were checked against each other: this one is about `ReceiverMutations` being populated BEFORE meta expansion on the RUST lane (a different map, a different pass, and the conservative answer here is the SOUND direction), whereas t0134 was an UNDER-detection on the self-host lane. Opposite directions, no overlap.
