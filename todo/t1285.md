- **🆕🧹 [LOW — a RATIFIED SPELLING that the compiler's own diagnostics never adopted; found 2026-09-04 by R49 Track N2's output review as a drive-by, filed rather than left as one] `E_MoveWithoutOperator` tells the user to ``write `!x` to move`` where D27 ratified `^`.**
  Re-derive the census: ``grep -c 'write `!' src/semantic/errors.rs`` prints **5**, and the five split 4 + 1. FOUR are message sites — two in the `&`-offering flavor, one in the bare flavor, one in the *"write `!` instead of `&`"* fix-it. The FIFTH is the unit test that pins the bare flavor **byte-identically**, under a message demanding it *"stay byte-identical"*. So the string and its guard both teach the retired spelling, and the guard is what would fail first on a fix. ⚠ The grep is cited as a count, not as a site list, precisely because it returns both halves: do not read 5 as five messages.
  ⚠ **THE SUGGESTED SYNTAX STILL WORKS, and saying otherwise would overstate this.** Measured 2026-09-04 on the same program: `take(^a)` builds rc 0 and prints `aabc` / `bye`, and `take(!a)` **also builds rc 0**. So this is not a diagnostic that sends users into a compile error — it is a diagnostic that teaches the spelling the language moved off. That is why it is LOW and not MED, and it is the reason the defect has survived: nothing breaks.
  ⭐ **WHY IT IS WORTH A ROUND ANYWAY.** D27's whole point is sigil economy — one spelling for move. An error message is the single most-read piece of documentation a compiler ships, and this one is the *first* thing a user sees at exactly the moment they are learning ownership syntax. Every such message is a vote for `!`, cast by the implementation, against the ledger.
  ⊕ **SCOPE, from the ratified record:** D27's in-repo scope is `src` / `tests` / `lib` / `spec` only. `src/semantic/errors.rs` is in scope; the out-of-repo consumers (gorget-js, arena, gglox, gorget-conformance) are not, and must not be swept in.
  ⚠ **CHECK WHETHER `!` SHOULD ALSO STOP PARSING** before writing the fix, and treat that as the real question rather than a follow-up: if D27 retires the spelling, a compiler that still accepts it is the larger half of this item, and flipping the message while continuing to accept `!` leaves the language with two move sigils and documentation for one. That is an owner-facing question about whether D27 is a rename or a deprecation, not something to decide inside a cleanup.
  **INTENDED:** the diagnostics read ``write `^x` to move``, the pinning test asserts that text, and the ratified sigil is the only one the messages name.
  **NO REPRO, and the reason:** this is diagnostic TEXT, not behaviour. Its RED-verification is the pinning test in `src/semantic/errors.rs` failing when the string changes — which is the guard that already exists, pointed the other way.
