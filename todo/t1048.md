- **🚨 [HIGH — MEMORY, both routes measured; found 2026-09-03 by the R49 Track K brief-review gauntlet, executor-verified at HEAD] Mutating a `String` through a `&` parameter LEAKS every buffer the CoW supersedes.**
  - **MEASURED, `gg build --clones=stats` on `known_gaps/cow_amp_route_leaks_superseded_buffers.gg`:** `string_cow=64 total_frees=65 live_bytes=32704`, exit 0. The identical 64 appends written INLINE in `main` (`s = s + "..."`) give `string_cow=0 total_frees=68 live_bytes=0`. The discriminator is the ROUTE, not the mutation.
  - **NO SLICE IS INVOLVED.** The repro is a plain `String` and a `void grow(String &s)`. That is what separates it from the `s[a:b]` view-tag class it was found next to.
  - **⚠ ASan IS STRUCTURALLY BLIND.** The runtime allocates from the custom `__gorget_current_alloc` pool, so no sanitizer report is emitted and `scripts/sanitize_sweep.sh` says nothing about it. `--clones=stats live_bytes` is the instrument; the wired `#[ignore]`d test reads that field rather than stdout, because a leak is not observable in stdout.
  - **⚠⚠ IT MASKS OTHER DEFECTS, AND THAT IS THE EXPENSIVE PART.** A dangling view of the source's buffer keeps printing the RIGHT answer through the `&` route precisely because the superseded buffer is never freed — so any `&`-rooted probe of a use-after-free class is green for the wrong reason (SIX Q#6). Two review passes of R49 Track K nearly concluded a live UAF did not reproduce for exactly this reason. **Every future memory probe must use the inline-reassign route, or state why not.**
  - **INTENDED:** `live_bytes=0` at exit, as the inline route already achieves. Independent of the `t0871` view tag (which landed R49): with the tag the `&`-route slice cells go `string_clone` 0→2 and are sound, so this is not blocked by it and does not block it.
  - **Owner-binding context:** leak-freedom is non-negotiable, so this is not "tolerable leak debt" — it is the one leak that actively degrades the repo's ability to measure the memory-safety classes.
