- **🆕🚨 [HIGH — SILENT WRONG OUTPUT on ordinary safe syntax, `gg check` CLEAN, both backends; found
  2026-09-03 by the R49 Track C v4 brief-review while hunting for what six mechanisms had missed;
  orchestrator-verified] A trait-implementing `equip` method with a SINGLE-LINE `return` body DISCARDS its
  return value.**
  - ⭐ **ONE-TOKEN DISCRIMINATOR, orchestrator-measured — same body, same struct, same call:**
    ```gorget
    trait Scorable:
        int score(&self)
    struct Sensor: int reading
    equip Sensor with Scorable:                    # ← WITH the trait
        int score(&self): return self.reading + 100
    # main: Sensor(7).score()  →  prints 0          ⛔ WRONG (107 expected)
    ```
    ```gorget
    equip Sensor:                                   # ← BARE equip, body IDENTICAL
        int score(&self): return self.reading + 100
    # main: Sensor(7).score()  →  prints 107        ✅ correct
    ```
    **`with Scorable` is the only difference.** `gg check` reports no errors in either case.
  - **THE GIR SHOWS THE VALUE BEING COMPUTED AND THEN THROWN AWAY:**
    ```
    _4 = cmp_gt i64 copy _3, const 0i64     ; the body's expression IS evaluated
    _0 = const unit                          ; ⛔ and then discarded
    return copy _0
    ```
    The bare-`equip` twin emits `_0 = copy _3`.
  - **FOUR-CELL DISCRIMINATION — it is the TRAIT × SINGLE-LINE cell only:**

    | trait `equip` + MULTI-LINE `return` | ✅ correct |
    | trait `equip` + expression body (no `return`) | ✅ correct |
