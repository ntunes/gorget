- **🆕🧹 [MED — LAYERING RULE 3 + CORE #2: TWO SOURCES OF TRUTH FOR "IS THIS NAME A TYPE", ONE OF THEM A STRING MATCH; surfaced 2026-09-05 while scoping D0′'s shadow-reject]** The ScopeTable's type namespace is incomplete by construction, and the gap is invisible to every consumer that trusts it.

  **THE TWO MECHANISMS, regenerated:**
  1. `grep -n "BUILTIN_GENERIC_TYPES" src/semantic/resolve.rs` — a **hardcoded string list** (16 names:
     `Vector`, `Deque`, `Dict`, `HashMap`, `Set`, `HashSet`, `Box`, `Future`, `Task`, `Channel`, `Shared`,
     `Weak`, `Mutex`, `Guard`, `TaskGroup`, `FxHasher`) that seeds the type namespace.
  2. `grep -n 'matches!(name.node.as_str(), "Callable"' src/semantic/types.rs` — a **separate `matches!` on
     string literals** for `Callable` / `MutCallable` / `ConsumeCallable`. ⛔ **Core #2's exact target: deciding
     what a name MEANS by matching the string.**
  ⊕ **`Owned` is in NEITHER** (`grep -rn '"Owned"' src/parser/ src/semantic/` → no registration).

  **MEASURED CONSEQUENCE (2026-09-05, at HEAD):** a value binding may take a type's name, and whether anything
  notices depends on which mechanism owns that name:
  ```
  Box[int] Box = Box.new(5)                    -> noticed (unused-variable warning names `Box`)
  Callable[int(int)] Callable = (int x): x + 1 -> gg check CLEAN, nothing notices
  ```

  ⭐ **WHY THIS MATTERS BEYOND TIDINESS — IT MAKES A RATIFIED RULE UNIMPLEMENTABLE AS STATED.** The owner ruled
  2026-09-05 that **a value may not take a type's name** (D0′'s shadow-reject). ⛔ **A check keyed on the type
  NAMESPACE is blind to the two generic spellings MOST LIKELY to be shadowed by a callable-valued local.**
  ⇒ **the reference-grade shape is to key the check on the `DefKind` the resolver already carries — "resolve
  by kind", one layer over — and to close THIS item so the namespace is complete.** ⛔ **DO NOT add `"Callable"`
  and `"Owned"` to a list inside the check: that replicates the defect in the code written to fix it.**

  **WHAT WOULD CLOSE IT.** One registration path for builtin type names, read through one accessor: the
  callable family and `Owned` join the same registry as the other sixteen, and the `matches!` retires.
  ⚠ **The callable family may genuinely need distinct TREATMENT** (it is parsed as a function-type form, not a
  plain named generic) — **so the fix is one source of truth for MEMBERSHIP, not necessarily one code path for
  BEHAVIOUR. Establish which before designing.**

  ⚠ **A consumer that keys on the type namespace today is silently under-covering, not failing** — that is the
  shape this item exists to make visible, and it is why it is filed rather than left to D0′'s brief.
