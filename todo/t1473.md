- **🆕 [MEDIUM — NAME-MATCHING ON THE FUTURE REFERENCE LANE. Found 2026-09-06 by R51 Track F's brief-review pass 1, as a NAMED OMISSION.]**

  In the self-host lowerer, `map_ast_type` lowers `Ref[T]` to `GtNamed("Ref__T")` and attaches **no typed id**. Everything downstream that needs to know "this is a borrow" therefore reconstructs it from the **`Ref__` name prefix** (regenerate: `grep -n 'Ref__' tests/fixtures/self_host_lowerer/lir_lower.gg`).

  That is precisely Core #2 / Layering rule 2: *if a downstream pass reconstructs information from names, the boundary upstream was drawn wrong.* The fix is upstream — carry the borrow fact as typed metadata on the lowered type, read via an accessor.

  ⭐ **AND IT IS CHEAP RIGHT NOW.** The Rust-side `Ref[T]`/`MutRef[T]` parameter-ABI fix tracked by `todo/t0952` addresses the *same* upstream loss on the Rust lane. Porting that fix would let the self-host retire the `Ref__` residual **in the same motion** — a Core #2 violation closed as a side effect of a Core #1 fix, rather than as its own campaign later.

  **INTENDED:** the self-host lowerer carries `Ref`/`MutRef` as typed metadata; the `Ref__` name probes are deleted, not widened.
