- **🆕🚨 [HIGH — SILENT WRONG OUTPUT on the most ordinary syntax in the language, `gg check` CLEAN, rc 0, both
  backends; surfaced 2026-09-03 by the R49 Track F pass-3 review as a FIXTURE HAZARD and filed here because
  the cardinal rule requires it, orchestrator-verified] `print(v)` on a `Vector` prints a RAW ADDRESS.**
  ```gorget
  Vector[int] v = [30, 25, 40]
  print(v)          # → 281474249037680     ⛔ a heap pointer, formatted as a decimal integer
  ```
  **`gg check` reports no errors; the program exits 0.** No `Displayable` equip for `Vector` exists in
  `lib/std/`, so nothing rejects the call and the value reaches the integer print path.
  - ⭐ **WHY IT IS FILED RATHER THAN LEFT AS FIXTURE HYGIENE.** Track F found it while writing the M1 fixture
    matrix and treated it as a convention (*"assert with a `for` loop, never `print(collection)`"*). That
    convention is necessary — **a fixture written as `print(v)` pins a garbage address and READS AS GREEN** —
    but the underlying behaviour is a **silent wrong answer from ordinary user syntax**, which is #2 on the
    owner's severity ranking (mem-unsafety > **silent-wrong-output** > ICE > leak). A convention that stops
    *our* fixtures from tripping over it does nothing for a user who writes the same line.
  - ⛔ **DISCRIMINATED FROM `t0020`** — that item is the `auto`-empty-literal path printing an *element* as a
    raw pointer. **This one needs no `auto` and no element access**: it is `print` applied to the collection
    itself, with a fully-typed declaration.
  - **AXIS TO COVER (Core #12) — the collection surface, not one cell:** `Vector` · `Dict` · `Set` ·
    `Deque` · `HashSet` · `HashMap`, each × element type (`int` · `String` · a struct) × the `Option[T]`
    wrapper (`print(v.find(…))` prints an address the same way). **Name every omitted cell.**
  - **INTENDED — an owner call the item should force, not guess.** Two defensible answers and the item
    exists to pick one: **(a) REJECT at check time** with a diagnostic naming the type and pointing at the
    idiom (`for x in v: print(x)`), which is Core #10's lower-or-reject and costs no runtime; or **(b) give
    the collections a `Displayable` impl** so `print(v)` prints something like `[30, 25, 40]`, which is what
    a Python-shaped language leads a reader to expect. ⚡ **(b) is a language-surface addition and therefore
    an owner ask; (a) is implementable today.** ⛔ **What is not defensible either way is the current
    behaviour** — printing a pointer with no diagnostic.
  - **REPRO OWED:** `known_gaps/` cells for `print(<collection>)` across the axis above, asserting the
    INTENDED output once the direction is settled — plus a positive control (`for x in v: print(x)`) that is
    green today, so the fixture cannot pass for the wrong reason.
