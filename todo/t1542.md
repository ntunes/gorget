- **🆕🛡 [MED — A RATCHET THAT PENALISES DOCUMENTING THE THING IT RATCHETS. Found 2026-09-06 by R51 Track A's executor, re-confirmed by its output-review with an independent control.]**

  `count_name_prefix_in_tree` (`tests/lints.rs`) matches `starts_with\("(<prefixes>)__"\)` over every `src/**/*.rs` file. **It does not distinguish code from comments.**

  **Positive control, both directions** (regenerate: append one line reading `// probe: name.starts_with("Box__")` to any `src/**/*.rs`, then `cargo test --test lints no_growth_in_name_prefix_routing`): **204 → 205, RED. Delete the line: 204, GREEN.** No compiled code changed in either direction.

  ⛔ **THE COST FALLS EXACTLY WHERE IT HURTS MOST.** A track migrating a routing site to typed metadata — the migration `[[t0690]]` and `[[t0027]]` prescribe — has to explain what it retired and why the new site must not regress. Writing that explanation faithfully spends the ratchet's budget on PROSE. R51 Track A hit this with three doc comments and had to respell all three (*"a prefix match on the mangled `Box__` symbol"*), which is a **worse** artifact in one place and, in `src/lir/lower/mod.rs`, a better one — but the choice should not be forced by a text scanner.

  ⚠ **AND THE HAZARD ITSELF IS UNFILED.** Checked `t0131`, `t0904`, `t0905`, `t1256` (the ratchet family) and `t0690`, `t0027`, `t1218`, `t0992`, `t0058` (the name-matching family): none records it. It lives only in a code comment inside the one file that hit it — which is the failure mode `[[t0690]]`'s own history demonstrates (a census figure that was wrong for months because it was read off a `| head`).

  ⊕ **NOT A CASE FOR WIDENING THE PREDICATE INTO A PARSER.** The lint's own doc already concedes it is "bookkeeping, not a class-retiring guard" and that a site respelled outside the pattern is invisible to it. The cheap correct move is a comment-stripping pre-pass on each file before the scan, with a positive control asserting a commented instance is NOT counted and a real one IS — the same two-sided shape `live_lines_of_ci_job` already uses for the CI-step lints, which strips `#`-comments for exactly this reason.

  **INTENDED:** the ratchet counts routing SITES, not sentences about them; documenting the anti-pattern is free, and a commented-out real site does not hide from the count either.
