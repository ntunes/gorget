- **🆕 [MED — A GUARD THAT RECORDS A LIVE BUG AS EXPECTED. Found by R50 Track H while landing `t1387`'s fix; the pinning pre-dates the round.]** The robustness map's `asan` column accumulates `SANITIZE-FAIL` baselines that are never re-adjudicated, so it can hold *pinned instances of a live, unfixed defect* and report the lane green.

  **THE POPULATION, and it is not small** (regenerate — the column-audited form, because `SANITIZE-FAIL` appears in no other column so the cheap line-grep is not accidentally right):
  ```
  awk -F'\t' 'NR>1 && $10=="SANITIZE-FAIL"' tests/fixtures/robustness_map/MANIFEST.tsv | wc -l   # -> 87
  ```

  **WHAT MADE IT VISIBLE.** `t1387`'s one-line runtime fix (`gorget_map_put` dropping the incoming key on a duplicate-key hit) turned **five** of those 87 from `SANITIZE-FAIL` to `WORKS` at once:
  `dict_count_words_unwrap_or`, `set_of_strings` (topic 07); `pair_count_a_unwrap_or`,
  `pair_count_b_contains_subscript`, `pair_count_c_match` (topic 16).
  ⇒ **five separately-pinned rows were five instances of ONE defect**, each recorded as an expected failure. Nothing in the tree could say they shared a cause, and nothing would have noticed if they never got fixed.

  ⊕ **AND TWO MORE ARE STALE IN THE OTHER DIRECTION** — `pair_upper_d_map_named` (topic 16) and `deg_vec_empty_sort_reverse` (topic 24) are recorded `SANITIZE-FAIL` but are **already green on unmodified HEAD**. Measured as a pristine control:
  ```
  python3 scripts/robustness_map.py --lanes asan --topic "16 spelling-equivalence pairs"   # PROGRESS pair_upper_d_map_named
  python3 scripts/robustness_map.py --lanes asan --topic "24 empty & singleton collections" # PROGRESS deg_vec_empty_sort_reverse
  ```
  ⇒ the column drifts **both ways**: it holds fixed cells as failing and failing cells as expected.

  ⚠ **THE SAME DRIFT EXISTS IN THE `WORKS` DIRECTION, WHICH IS THE DANGEROUS ONE.** `ex_char_frequency`'s baseline read `asan = WORKS` while the cell **leaked at HEAD** — that is what made `t1387` visible at all, as a REGRESSION rather than as a pin. A wrong `WORKS` reds the gate loudly; a wrong `SANITIZE-FAIL` is silent forever. **Only the loud direction has ever been caught.**

  ⛔ **WHAT DISCRIMINATES THIS FROM `t1387` AND `t1407`:** those are the DEFECTS; this is the INSTRUMENT that recorded five of them as expected. Fixing every leak the map currently pins would leave this mechanism untouched and the next class equally invisible. It is also **not** `t0956` (folding `robustness_map/` into `scripts/sanitize_sweep.sh`): that would change WHICH sweep runs the cells, not the fact that an accepted `SANITIZE-FAIL` cites nothing and expires never.

  **THE SHAPE OF A FIX** (Core #6 — a ratchet, not prose): make an `asan` baseline of `SANITIZE-FAIL` require a **citation to a `todo/` item**, the way `tests/sanitize/LEAK_ALLOWLIST.txt` distinguishes cited from uncited rows and `tests/sanitize/CORPUS_MANIFEST.txt` requires a named item that must exist. An uncited pin then has to justify itself, and a pinned row whose item closes becomes a lint failure rather than a permanent baseline.
