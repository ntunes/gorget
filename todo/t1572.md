- **🆕📐 [LOW — THE "SITE N+1" SHAPE OF R51 Track H's FIX: A SPELLING WITH NO REJECT AND NO CONSUMER. Named 2026-09-06 by that track's third brief-review, landed unfixed by its executor, deliberately.]**

  A declared parameter carries **two** independent borrow channels and they now compose:

  | channel | carrier | Track H's accessor |
  |---|---|---|
  | the **type** `MutRef[T]` | `Type::Named { name: "MutRef", generic_args: [T] }` | `map_param_ast_type` → `MutPtr(T)` |
  | the **sigil** `&` in the name slot (D35) | `Param.ownership == MutableBorrow` | `resolve_param_type` wraps in `MutPtr` |

  ⇒ `void f(MutRef[T] &x)` yields **`MutPtr(MutPtr(T))`**.

  ⛔ **IT IS NOT A REGRESSION, and saying so precisely matters.** Before Track H the same spelling yielded `MutPtr(UNIT_TYPE)` — equally wrong, differently wrong. **The fix does not introduce the hazard; it changes what the wrong answer looks like.**

  **WHY IT IS FILED RATHER THAN FIXED.** Zero occurrences tree-wide (regenerate: `grep -rnE '(Ref|MutRef)\[[^]]*\] *&' lib/ tests/fixtures/ src/`), so nothing exercises it, no fixture can pin it without writing the shape, and the shape is D41-illegal in user source anyway. Fixing it inside Track H would have been an unexercised edit shipped under a fixture that cannot go red — Core #12's own failure mode.

  ⚠ **AND THERE IS NO SUBJECT THAT REJECTS IT (SIX-Q #4).** The borrow-spelling rejects that exist are about the `Ref`/`MutRef` TYPE; nothing anywhere asks whether a type that is *already* a borrow is *also* carrying a borrow sigil. A rule widening will not reach it — the case has no subject.
