- **🔧 EARLY-RETURNING BUILD SUB-PATHS SILENTLY DROP FLAGS — a CLASS, not one flag.** `try_build_ir` has **FIVE** build sub-paths, and **FOUR** of them construct their **own** compiler invocation and `return` from it before control reaches the flag-application code at the bottom of the fifth: **(a)** the `--shared` library build, **(b)** the hot-reload split (its own `guest_cmd` + `host_cmd`), **(c)** the LLVM pipeline (`compile_llvm_pipeline`'s runtime `cc -c` + link), **(d)** freestanding/UEFI. The fifth is the normal C path, which is where the flag site lives. Separately, **(e)** the `gg script.gg` shorthand builds its own `LoweringOptions` and is a fifth place a flag can go missing. A flag wired only on the normal path is therefore **accepted and silently discarded** on the others, with rc 0 and no diagnostic. Wire each flag into every sub-path, or reject the combination by name — never drop it (Core #10).
  - **THE PENDING WORK IS `--release` (-O2), on FIVE shapes: (a) `--shared`, (b) hot-reload, (d) freestanding, (e) the `gg script.gg` shorthand, and (f) `gg test`.** Re-measured at HEAD 2026-08-29 with the argv probe below, each against its own no-flag control — `-O2` occurrences went 0→0 on every one. It IS correctly threaded on `gg build`'s and `gg run`'s normal C path and on **(c) the LLVM pipeline** (`options.release` → `llc -O2` for the user IR; the runtime `cc -c` is unconditionally `-O2`, which is why the census compares with-vs-without rather than testing for presence). The main `build`/`run` paths WORK (see DONE.md); `gg build --shared --release` silently emits a `-O0` lib and **`gg test --bench --release` benchmarks a `-O0` build**. Nothing breaks (default intact); completeness gap. Fix by wiring `release` into those five sites' opt-level, or by scoping the `appendix-cli.md` wording.
  - **⚠ THE FAMILY HAS TWO AXES, AND THE ENTRY-POINT ONE IS THE EASY MISS.** Within `try_build_ir`, the sub-paths above. **Across dispatchers, the ENTRY POINTS** — `gg build`, `gg run`, `gg test` and the `gg script.gg` shorthand each construct their OWN `LoweringOptions`, so a field one of them omits is dropped for every sub-path beneath it. `gg test`'s omits `release` (`src/main.rs`'s `"test" =>` arm carries `sanitize, scheduler_mode` and simply not `release`; there is no comment, so it is a forgotten field rather than a decision). Two earlier revisions of this item enumerated only sub-paths and therefore said "four"; the fifth was found the moment the census grew an entry-point row. **Enumerating one axis of a two-axis family is a selection, not a total.**
  - **⚙ THE ENUMERATION IS NOW A GUARD, NOT PROSE — `build_flags_are_never_silently_dropped` (`tests/integration.rs`, `#[ignore]`d).** It walks (flag × shape) for `--sanitize` and `--release` across all EIGHT invocation shapes — five `try_build_ir` sub-paths plus `gg run`, `gg test` and the shorthand — measuring the ACTUAL constructed argv via `CC`/`LLC` = `/bin/echo`, each cell self-controlled by the same invocation without the flag. A cell passes if the flag is threaded **or** rejected by name; only silent absence fails. Today it reports exactly the five `--release` holes above and zero `--sanitize` holes, and `gg run`'s passing cells are what would catch a regression there. **Un-ignore it when this item closes** — and note that instruction lives HERE because the guard is not on `scripts/known_gaps_census.sh`'s roster (that roster enrols `#[ignore]`d tests naming a `known_gaps/` fixture, and this guard's subject is an argv, not a program), so nothing external will notice if it rots. Adding a flag or a shape is one array row each.
  - **⚠ THE GUARD'S INSTRUMENT IS ARGV-ONLY — it does NOT cover this whole family.** A flag carried inside `LoweringOptions` and consumed during lowering never reaches a compiler command line and is structurally invisible to it: `--scheduler`, `--strip-asserts`, `--trace`, `--feature`, `--hot-reload`. One of those is live on the main path right now — **`gg build --scheduler=` is silently dropped**, filed as a side-bullet of **`todo/t0627`** and stale-scanned as still live. It is cross-linked here because this item is the family record and a member hiding in an unrelated item's side-bullet is exactly the indexing failure that let `t0038` be re-discovered twice. Catching that sub-class needs a different probe: diff `gg build --emit-c-lir` output with and without the flag. ⚠ MIND THAT PROBE — it needs a program that actually USES the flag's feature. On a trivial `print` program the emitted C is identical with and without `--scheduler` on **every** path, so the control passes for the wrong reason; on an async program (`spawn` + `await`) the `--shared` path's output genuinely DIFFERS while plain `gg build`'s stays identical, which is what makes the drop visible. Verified at HEAD 2026-08-29 both ways.
  - **HOW TO CLOSE IT — mechanical, with a control.** Per flag, per sub-path, capture the constructed argv via the driver's own `CC` override rather than reading the source: `CC=/bin/echo gg build <flags> f.gg` prints the cc command line, and a run WITHOUT the sub-path flag is the control proving the probe works. A guard shape already exists in-tree: `release_flag_optimizes_at_o2` (`tests/integration.rs`, `#[serial]`) proves flag→argv reachability by overriding `CC` with a logging wrapper and grepping the log, so a per-sub-path cell is a copy of an existing test, not new machinery.
  - **PRECEDENT ON THE SAME MECHANISM, for whoever picks up `--release`.** `--sanitize` had the identical hole on sub-path (b) and R47 Track C handled it, so this item's mechanism now has a worked example. Its disposition there was **reject, not wire** — a UEFI image is built `-ffreestanding -nostdlib` and the sanitizers need a hosted environment with a libc to intercept, so that combination cannot be honoured at all; it is pinned as a cell of `unhonourable_build_flag_combinations_are_rejected`. `--release` is different in kind: `-O2` *can* be honoured on every one of these paths, so wiring is the right answer there, not rejection. ⊕ Sub-paths (a) and (c) were measured for `--sanitize` and thread it correctly — note the asymmetry, since `--release` is missing on (a).
