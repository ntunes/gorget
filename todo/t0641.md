- **🔧 EARLY-RETURNING BUILD SUB-PATHS SILENTLY DROP FLAGS — a CLASS, not one flag.** `try_build_ir` has **FIVE** build sub-paths, and **FOUR** of them construct their **own** compiler invocation and `return` from it before control reaches the flag-application code at the bottom of the fifth: **(a)** the `--shared` library build, **(b)** the hot-reload split (its own `guest_cmd` + `host_cmd`), **(c)** the LLVM pipeline (`compile_llvm_pipeline`'s runtime `cc -c` + link), **(d)** freestanding/UEFI. The fifth is the normal C path, which is where the flag site lives. Separately, **(e)** the `gg script.gg` shorthand builds its own `LoweringOptions` and is a fifth place a flag can go missing. A flag wired only on the normal path is therefore **accepted and silently discarded** on the others, with rc 0 and no diagnostic. Wire each flag into every sub-path, or reject the combination by name — never drop it (Core #10).
  - **THE PENDING WORK IS `--release` (-O2), on FOUR sites: (a) `--shared`, (b) hot-reload, (d) freestanding, and (e) the `gg script.gg` shorthand.** Re-measured at HEAD 2026-08-29 with the argv probe below, each against its own no-flag control — `-O2` occurrences went 0→0 on every one of the four. It IS correctly threaded on the normal C path and on **(c) the LLVM pipeline** (`options.release` → `llc -O2` for the user IR; the runtime `cc -c` is unconditionally `-O2`). ⚠ An earlier revision of this item said "all three of (a), (b) and (c)" using a different lettering and omitted the hot-reload split; that under-count is what the census guard below now makes impossible. The main `build`/`run` paths WORK (see DONE.md); `gg build --shared --release` silently emits a `-O0` lib. Nothing breaks (default intact); completeness gap. Fix by wiring `release` into those four sites' opt-level, or by scoping the `appendix-cli.md` wording.
  - **⚙ THE ENUMERATION IS NOW A GUARD, NOT PROSE — `build_flags_reach_every_sub_path` (`tests/integration.rs`, `#[ignore]`d).** It walks (flag × sub-path) for `--sanitize` and `--release` across all six invocation shapes, measuring the ACTUAL constructed argv via `CC`/`LLC` = `/bin/echo`, each cell self-controlled by the same build without the flag. A cell passes if the flag is threaded **or** rejected by name; only silent absence fails. Today it reports exactly the four `--release` holes above and zero `--sanitize` holes. **Un-ignore it when this item closes** — and if a future contributor adds a build flag, adding its row is one line. This item's prose under-counted the family twice; a guard cannot.
  - **HOW TO CLOSE IT — mechanical, with a control.** Per flag, per sub-path, capture the constructed argv via the driver's own `CC` override rather than reading the source: `CC=/bin/echo gg build <flags> f.gg` prints the cc command line, and a run WITHOUT the sub-path flag is the control proving the probe works. A guard shape already exists in-tree: `release_flag_optimizes_at_o2` (`tests/integration.rs`, `#[serial]`) proves flag→argv reachability by overriding `CC` with a logging wrapper and grepping the log, so a per-sub-path cell is a copy of an existing test, not new machinery.
  - **PRECEDENT ON THE SAME MECHANISM, for whoever picks up `--release`.** `--sanitize` had the identical hole on sub-path (b) and R47 Track C handled it, so this item's mechanism now has a worked example. Its disposition there was **reject, not wire** — a UEFI image is built `-ffreestanding -nostdlib` and the sanitizers need a hosted environment with a libc to intercept, so that combination cannot be honoured at all; it is pinned as a cell of `unhonourable_build_flag_combinations_are_rejected`. `--release` is different in kind: `-O2` *can* be honoured on every one of these paths, so wiring is the right answer there, not rejection. ⊕ Sub-paths (a) and (c) were measured for `--sanitize` and thread it correctly — note the asymmetry, since `--release` is missing on (a).
