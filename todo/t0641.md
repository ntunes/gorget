- **🔧 EARLY-RETURNING BUILD SUB-PATHS SILENTLY DROP FLAGS — a CLASS, not one flag.** `try_build_ir` has sub-paths that build their **own** `cc` invocation and `return` from it before control reaches the flag-application code near the bottom of the normal C path: (a) the `--shared` library build (own cc invocation early-returning before the `-O2` site), (b) the freestanding/UEFI cc path (same early-return), (c) the `gg script.gg` shorthand (threads its own `LoweringOptions`). The hot-reload host/guest split is a fourth such sub-path with its own two cc invocations. A flag wired only at the bottom of the normal path is therefore **accepted and silently discarded** on those paths, with rc 0 and no diagnostic. Wire each flag into every sub-path, or reject the combination by name — never drop it (Core #10).
  - **THE PENDING WORK IS `--release` (-O2), on all three of (a), (b) and (c)** — the original report. The main `build`/`run` paths WORK (see DONE.md); `gg build --shared --release` silently emits a `-O0` lib. Nothing breaks (default intact); completeness gap. Fix by wiring `release` into those sites' opt-level, or by scoping the `appendix-cli.md` wording.
  - **HOW TO CLOSE IT — mechanical, with a control.** Per flag, per sub-path, capture the constructed argv via the driver's own `CC` override rather than reading the source: `CC=/bin/echo gg build <flags> f.gg` prints the cc command line, and a run WITHOUT the sub-path flag is the control proving the probe works. A guard shape already exists in-tree: `release_flag_optimizes_at_o2` (`tests/integration.rs`, `#[serial]`) proves flag→argv reachability by overriding `CC` with a logging wrapper and grepping the log, so a per-sub-path cell is a copy of an existing test, not new machinery.
  - **PRECEDENT ON THE SAME MECHANISM, for whoever picks up `--release`.** `--sanitize` had the identical hole on sub-path (b) and R47 Track C handled it, so this item's mechanism now has a worked example. Its disposition there was **reject, not wire** — a UEFI image is built `-ffreestanding -nostdlib` and the sanitizers need a hosted environment with a libc to intercept, so that combination cannot be honoured at all; it is pinned as a cell of `unhonourable_build_flag_combinations_are_rejected`. `--release` is different in kind: `-O2` *can* be honoured on every one of these paths, so wiring is the right answer there, not rejection. ⊕ Sub-paths (a) and (c) were measured for `--sanitize` and thread it correctly — note the asymmetry, since `--release` is missing on (a).

The mechanism was already written down here.
