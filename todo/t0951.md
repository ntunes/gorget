- **🆕🐛 [MED — a LEAK from ordinary safe syntax, BOTH backends, `gg check` clean; found 2026-09-03 by R48 Track T-a1 while ASan-attributing the three rows that round admitted to `tests/sanitize/LEAK_ALLOWLIST.txt`] A consuming `^` PARAMETER emits the callee-side drop; a consuming `^self` RECEIVER never does, so the receiver's heap fields leak.**
  ```gorget
  struct Bag:
      Vector[int] items

  void take_bag(Bag ^b):
      print(3)          # CLEAN — take_bag emits Bag__drop(__v5)

  equip Bag:
      void drop_it(^self):
          print(3)      # LEAKS 64 B — Bag__give emits no drop at all
  ```
  **THE WRITE SITE, and it is a TWO-SITE CLASS (Core #4).** `ctx.drops.register_owning_param(...)` (defined at `src/ir/lowering/drops.rs:282`) is called for a `Move`-ownership parameter of a resource type at `src/ir/lowering/functions.rs:1749`, `:2080`, `:2436` and `:2840`. The two METHOD sites — `:2080` and `:2840` — sit inside a parameter loop whose first statement is `if p.node.name.node == "self" { continue; }` (`:2071-2073` and `:2831-2833`), so `self` never reaches the registration whatever its ownership sigil says. A fix at one site does not transfer to the other.
  ⭐ **THE FIX ADDS NO NEW `== "self"` NAME-MATCH (Core #2).** The typed flag is ALREADY COMPUTED at both sites: `self_is_consuming` at `functions.rs:1996-1998` (with `self_type_id` at `:1973`) and at `:2776-2778` (with `self_type_id` at `:2738`). ⚠ `src/semantic/traits.rs:18,68` carries a `self_ownership: Option<Ownership>` field, but it is **NOT reachable from IR lowering** (`grep -rn self_ownership src/ir/` → 0 hits) — do not route the fix through it without first wiring it down.
  ⚠ **THE TWO SITES DISAGREE ON THE RECEIVER ABI, which is a second reason a one-site fix is wrong.** Verified at HEAD: `functions.rs:1974-1976` computes `self_needs_mut_ptr` from `matches!(ownership, MutableBorrow | Move)`, so a `^self` receiver is a **MutPtr**; `:2739-2744` computes `self_is_mutable` from `MutableBorrow` ALONE, so a generic-equip `^self` falls to `register_ptr_type` at `:2746` and is a plain **Ptr**. One construct, two lowering paths, different ABI — Core #4 sibling drift plus Layering rule 1. ⊕ `functions.rs:1995` still says *"Track consuming self (`!self`)"*, a stale pre-D27/D35 sigil; fix the comment when you touch the site.
  ⭐ **A SECOND OBSERVABLE, SAME CARVE-OUT: `^self` AT AN ARGUMENT POSITION IS LOWERED AS A CLONE, NOT A MOVE.** `void give(^self): take_bag_reads(^self)` emits
  ```c
  void Bag__give(void* __p0) {
      __v2 = Bag__clone(__v0);     /* a full deep clone of the Bag */
      take_bag_reads(&__s2);       /* which the callee then drops */
  }
  ```
  The callee drops the CLONE; the original is what leaks. `^` is the user's explicit move opt-in and the CoW rule is move-when-liveness-allows — `self` is dead after the forward, so this is both a wasted deep copy and a silently-ignored `^`. Either half alone leaks: the no-forward cell leaks with no clone anywhere.
  ⭐ **THE DISCRIMINATING MEASUREMENT — and it CORRECTS the attribution R48 Track T-a1 was briefed with.** The brief's stated control was *"a `^self` method that forwards nothing is CLEAN"*, which appeared to contradict the mechanism. Measured, the control was mis-designed: its body was `print(self.items.len())`, and a field projection inside a `^self` method MOVES the field out into a local (`__s2 = *self->items` followed by `memset(&self->items, 0, 64)`) and THAT local **is** drop-registered (`gorget_array_free(&__s2)` at exit). It was clean because it emptied the struct's only heap field, not because the receiver was handled. Five cells, `gg build --sanitize`, records off the ASan report:

  | cell | shape | HEAD |
  |---|---|---|
  | A | `void take_bag(Bag ^b): print(3)` — PARAM, touches nothing | **CLEAN** (emits `Bag__drop`) |
  | B | `void drop_it(^self): print(3)` — RECEIVER, touches nothing | **LEAKS 64 B** |
  | C | `void give(^self): take_bag_reads(^self)` — forwards | **LEAKS 64 B** |
  | D | `void project(^self): print(self.items.len())` — projects the SOLE heap field | **CLEAN** — the projection temp incidentally frees it |
  | E | two heap fields, `^self`, projects ONE | **LEAKS 64 B** (the un-projected one) |

  A vs B is the whole finding: same body, same struct, `^` param clean and `^self` receiver leaking. D and E are why the net has five cells — **a regression net built only from projecting shapes, or only from no-forward shapes, is green on arrival** (Core #12).
