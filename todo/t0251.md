- **SELF-HOST lexer bug (NOT a Rust bug): string literal inside an f-string interpolation truncates the enclosing `match`.** A nested string literal in an f-string interpolation (`f"... {f(\"add\", x)} ..."`) is mis-lexed: the `\"` inside `{...}` ends the f-string early → everything after that `case` arm is silently dropped (nasty: no parse error at the site, a downstream non-exhaustive-match error one function over + a phantom extern). The Rust compiler does NOT have this (`src/lexer/mod.rs:691-694` calls `skip_quoted_string` which skips `\\` escapes). Fix the self-host interpolation-segment scanner (`tests/fixtures/self_host_*/lex.gg`) to mirror `skip_quoted_string`. Workaround: bind the inner call to a `String` local first.
