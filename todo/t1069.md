- **🆕🐛 [MED — SELF-HOST lane LEAK, `gg check` clean and rc 0 on a plain run; found R49 Track L, ASan-measured over the self-host-emitted C 2026-09-04] The result of `Callable.clone()` never gets its environment field dropped, so an ESCAPING cloned closure leaks the environment and the collection the environment owns — 136 B on the repro.**
  - **REPRO.** `Callable[int(int)] mk_it(): Vector[int] v = [1]; Callable[int(int)] f = (int x): x + v.get(0).unwrap(); return f.clone()` → rc 0 printing `2`, and under ASan: `Direct leak 72 B __gorget_closure_env_alloc ← mk_it`, `Indirect leak 64 B gorget_array_push ← mk_it`, `SUMMARY: 136 byte(s) leaked in 2 allocations`. No double-free, no use-after-free.
  - **MECHANISM.** The self-host emits `__Closure_N__drop(closure.env)` before `gorget_closure_free` (`tests/fixtures/self_host_lowerer/lir_lower.gg`) — **this is the half Rust gg does not have**, and it is why the SH lane is ahead here. But it keys `closure_env_type` at closure MAKE-SITES only. `f.clone()` produces a second `GorgetClosure` that is not a make-site, so the clone carries no env type, no field drop is emitted for it, and nothing reclaims the environment once the clone outlives its maker.
  - **⚠ THE ESCAPE IS LOAD-BEARING — control measured alongside.** The same program WITHOUT the escape (`Callable[int(int)] g = f.clone()` used in the same frame, `tests/fixtures/known_gaps` sibling shape) is rc 0 and **fully ASan-clean**: the make-site `f` is still in scope and its own field drop reclaims the shared environment. Only a clone that OUTLIVES its make-site leaks.
  - **⚠ IT IS A LEAK, NOT A DOUBLE-FREE — an earlier characterisation of this shape called it a latent double-free and that is REFUTED by measurement.** `gorget_closure_clone_to_owned` shallow-copies the 16-byte `{fn_ptr, env}` handle, so the clone and the original share ONE environment; emitting an env-field drop for both would double-free. The rescue owed is ownership at the clone (deep-copy the env, or refcount it), not a second drop.
  - **⚠ THE INSTRUMENT.** A plain run is rc 0 on both lanes and stdout is identical, so only ASan over the SELF-HOST-emitted C can see it: `driver <fixture> lib --emit-c --runtime-dir=… > out.c` then `cc -O0 -g -fsanitize=address -o out out.c -lm -lpthread`. The Rust lane's own version of this shape is `t0953`'s class (heap env never freed at all).
  - **FAMILY.** `t0953` is the Rust-lane closure-literal env leak — the env is never freed because Rust emits NO field drop for a heap env at all. **THIS is the self-host, which DOES emit one and misses exactly the clone-result cell.** Different lane, different subject (make-site coverage vs. no coverage), same buffer class; state that before merging them.
