- **🆕🐛 [MED — a LEAK from ordinary safe syntax, BOTH backends, `gg check` clean; found 2026-09-02 by the R48 Track R POST-HOC OUTPUT REVIEW while ASan-attributing the two rows that round added to `tests/sanitize/LEAK_ALLOWLIST.txt`, and confirmed by a fix-forward reproduction] Every `Vector[Callable]` INDEX READ leaks a closure environment: the element materializes by CLONE into a temp that is never registered for drop.**
  ```gorget
  int base = 40
  Vector[Callable[int(int)]] fs = []
  fs.push((int x): x + base)
  print(f"{fs[0](1)}")          # <- 16 bytes leaked, per read
  print(f"{fs[0](2)}")          # <- 16 more
  Callable[int(int)] g = fs.get(0).unwrap()
  print(f"{g(3)}")              # <- this one's temp IS freed
  ```
  Prints `41 42 43` correctly and leaks **48 bytes in 3 allocations** on C and LLVM at HEAD.
  **THE WRITE SITE** is `ptr_materialization_kind` (`src/ir/lowering/context.rs`, immediately below `clone_fn_for_ptr`): for the pointer `gorget_array_get_at` returns it answers `PtrMaterialization::Clone("gorget_closure_clone_to_owned")`, which mints a freshly-owned heap env — and nothing registers that temp for drop. Emitted C:
  ```c
  __v18 = gorget_array_get_at(__v16, __v17, "T_Bounds", ...);
  __v19 = gorget_closure_clone_to_owned(__v18);   /* fresh heap env */
  __s8  = __v19;                                  /* never gorget_closure_free'd */
  ```
  **Core #3 — register ownership at the value's BIRTH.** The producer materializes an owned, droppable value and does not tag it; the read side then has nothing to drop. This is the leak class the invariant exists to prevent.
  ⭐ **THE DISCRIMINATING MEASUREMENT — the count scales with the number of READS, not with the number of ELEMENTS.** One element, `--sanitize`, records counted off the ASan report:

  | index reads | a `.get()` bind elsewhere in the program | leaked records |
  |---|---|---|
  | 2 | no | **1** (the pushed element only; the index reads are a `DerefLoad` memcpy) |
  | 1 | yes | **2** (pushed + 1 read temp) |
  | 2 | yes | **3** (pushed + 2 read temps) |

  The `.get(0).unwrap()` bind is a **PRECONDITION, not a leaker**: it is what instantiates the `Named("Callable__GorgetClosure")` element type, after which `clone_fn_for_ptr`'s `Named` branch answers and the index read's materialization flips from `DerefLoad` to `Clone`. ⭐ **Its OWN clone temp is registered and freed** — `gorget_closure_free(&__s17)` is emitted for it — which is exactly why the index-read temp's absence is a defect and not a policy. Whoever fixes this should ask why one `PtrMaterialization::Clone` product gets a drop registration and the sibling does not; that asymmetry is the bug's shape (Core #4 — fix the class of materialization sites, not the index-read instance).
