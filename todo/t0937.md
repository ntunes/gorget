- **🆕🚨💥 [CRITICAL — `AddressSanitizer: stack-buffer-overflow`, READ of size 16 out of a 1-byte object; `gg check` is clean and both backends SEGV at rc 139] A closure LITERAL passed to a CONSTRUCTOR or an enum-init is never constructed.**
  ```
  struct S:
      Callable[int(int)] f
  void main():
      S s = S((int x): x + 1)
      Callable[int(int)] g = s.f.clone()
      print(g(1))                          # rc 139
  ```
  Reproduces at `S(...)` AND at `Some(...)`, i.e. at both constructor and enum-init — the exact positions AGENTS.md § Ownership at Consuming Positions names as consuming boundaries (*"constructor / struct / enum field init like `S(name)` / `Some(name)`"*).
  **Emitted C (probe, `main`):** `__v2 = &__s2;` where `__s2 : __gg___Closure_0` is the ENV struct, then `memcpy(__v18, __v2, sizeof(GorgetClosure))` — 16 bytes read out of a 1-byte object. **No `__gorget_closure_env_alloc` and no `.fn_ptr =` designator are emitted anywhere in `main`**, whereas the var-decl path for the same literal emits both. ASan: `stack-buffer-overflow ... READ of size 16 ... [48, 49) '__s2' <== Memory access at offset 48 partially overflows this variable`.
  ⇒ **The literal is never lowered into a closure at all at this position** — this is Core #3 (register ownership at the value's birth) failing at the producer, not a clone bug.
  **Found 2026-09-02 by R48 Track R's brief-review pass 1 while probing a NON-MEMBER of a proposed class** — the probe that falsified the "receiver shape" axis also turned this up as an independent defect.
  ⚠ **DISCRIMINATED FROM ITS FAMILY:** related to `t0936` (the `FnPtr` value form's clone strategy is blind) and `t0927` (a closure capturing a `Callable[T]` parameter cannot be compiled at all) — all three are *"the value form of `Callable` carries lossy type metadata"*. **This one is distinct: the failure is at the CONSTRUCTOR/ENUM-INIT argument position and the closure is never CONSTRUCTED, where `t0936` constructs it correctly and fails to CLONE it, and `t0927` fails at cc/link on a capture.** Fix `t0936` and this one does not go away.
