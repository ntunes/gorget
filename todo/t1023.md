- **🆕🐛 [MED — Core #10 lower-or-reject, `gg check` CLEAN on a method no bound provides; both backends;
  found 2026-09-03 by the R49 Track C executor while closing readiness row 3 (`|pinned| == |changed|`)]
  A method call on an UNBOUNDED generic parameter is not checked for existence.**
  ```gorget
  bool probe[T](T a):
      return a.is_some()

  void main():
      print(probe[int](5))
  ```
  `gg check` → `OK: no semantic errors`; `gg build` → rc 1,
  ``undefined reference to `int64_t__is_some'`` — a mangled internal symbol naming a type in a
  spelling the user never wrote. Nothing in `probe`'s signature promises `T` has an `is_some`.
  - ⚠ **`t1019`'s RULE DELIBERATELY DOES NOT REACH THIS, AND WIDENING IT IS THE WRONG FIX.** That rule
    scopes its "this type has no such method" claim to `DefKind::{Struct, Enum, Newtype}` precisely to
    EXCLUDE `DefKind::GenericParam` — a BOUND type parameter's methods live on the bound, never in
    `impls_by_name`. An earlier attempt without that exclusion rejected **57 healthy fixtures**,
    `lib/std/iter.gg`'s `equip [Iter, T] TakeIter[Iter, T] with Iterator[T]:` and all 26 `iter_*`
    cells among them. The bound-provided case is live and correct and is pinned green by
    `tests/fixtures/user_four_name_method_provenance.gg`'s trait-bound cell.
  - ⇒ **THE RULE THIS NEEDS IS A DIFFERENT ONE:** for a `GenericParam` receiver, reject when no bound
    on that parameter provides the method. It reads the parameter's BOUNDS (`struct_generic_bounds` /
    the fn's generic bounds), not an impl table, which is why it is a separate subject with its own
    risk surface rather than a widening.
  - ⭐ **PRE-EXISTING, and the fixture proves it in-band:** `probe_bogus[T](T a): return
    a.totally_bogus_method()` link-fails identically BEFORE and AFTER the R49 Track C
    `t1017`/`t1019` pair. What the pair changed is only that `is_some` joined the class — before it,
    the lowering gate folded the four names to `Constant::Bool(false)` and the missing method was
    invisible in a different way.
  - **DISCRIMINATED FROM `t0942`:** that item's receivers have NO lowering type name at all (a
    `Callable` parameter lowers to GIR `unit`), so its cells fold to `Constant::Unit` and print `0`.
    This receiver HAS a name after monomorphization (`int64_t`) and fails LOUDLY at link. Different
    representation, different failure mode, different fix site.
  - **INTENDED:** `gg check` REJECTS both calls with a spanned diagnostic naming the method and the
    unbounded parameter.
  - **DURABLE REPRO:** `tests/fixtures/known_gaps/no_method_on_unbounded_generic_param.gg` + the
    `#[ignore]`d `known_gap_no_method_on_unbounded_generic_param`. RED-verified 2026-09-03 against
    both the pre- and post-R49-Track-C compiler.
