- **🆕🚨 [HIGH — a NAME MATCH decides MEMORY SAFETY in Rust gg; Layering rule 2 head-on, and the reference-grade blueprint already exists in-tree] Route the CoW materialize gate through a computed mutation classifier instead of `is_mutating_method_name`.** `src/ir/lowering/functions.rs:999` decides whether a method call mutates its receiver — and therefore whether `cow_before_mutation` materializes a private copy of the root — by matching the method's *identifier text*: `if is_mutating_method_name(method.node.as_str()) { record_path_mutation(...) }`. For built-in collection methods the name list is closed and this is merely ugly. **For USER methods it is a live memory-safety hole**: any `&self` mutator whose name is not in the list (`grow`, `bump`, `extend_in_place`, …) is simply absent, the materialize is skipped, and the alias survives the mutation. This is the mechanism behind `todo/t0699` ("a user method's *name* decides memory safety; SIGSEGV on both backends") — see that item for the committed reproducer; this item is the class fix, not a second filing.
  - **Why the existing design note does not cover it.** `docs/devbook/11-copy-on-write.md` (the "`&self` mutation-inference pass" section) argues that a blanket over-approximation "is not a correctness bug (the extra clone is harmless), but it is a *memory* bomb", and concludes the precise classifier "is a **self-host-only** need" because "Rust's CoW gate uses the analogous name/signature over-approximation (`method_mutates_receiver`) but is never compiled through these hot loops, so it never balloons". **That reasoning is sound for builtins and inverts for user methods.** A closed name list over-approximates; an *open* set of user-chosen identifiers **UNDER**-approximates, and under-approximation is precisely the correctness bug the paragraph says cannot happen. The doc needs correcting alongside the code (Core #9 spans docs) — the claim to fix is the "self-host-only need" conclusion, not the clone-bomb measurement, which stands.
  - **The blueprint is already in-tree and is the reference-grade shape.** `compute_method_mutates_self` (`tests/fixtures/self_host_lowerer/lower.gg:1612`, invoked at `:3713`) computes the answer precisely: a monotone fixpoint over self-callee edges, seeding each `&self`/`^self` equip method with a direct-mutation flag and propagating along call edges. Per the succession plan a self-host-correct / Rust-buggy split is **oracle hygiene** — fix the Rust side, never dumb the self-host down to match.
  - **Scope is small and the guard is obvious.** There is exactly **one** consumer to reroute (`functions.rs:999`). The fix is Layering rule 2's standard shape: put the typed flag on the method's decl, set it once where the method is resolved, read it through an accessor — never re-derive it from the identifier. Add a lint asserting `is_mutating_method_name` has no callers that make a *semantic* decision, so the next one is forced through the typed path (Core #4/#6).
  - **Verification when it lands.** `t0699`'s reproducer must go from SIGSEGV to correct output on BOTH backends; a user `&self` mutator with an arbitrary name must materialize; and the clone ceilings must NOT balloon — this replaces a name test with a computed answer, so measure `cargo test --test integration clone_ceiling -- --nocapture` and show the numbers did not move materially.
