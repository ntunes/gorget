  ```

  ```

  **Then, on the same tree, with nothing changed:**
  ```
  python3 scripts/reap_orphans.py --self-test    -> rc 0, "self-test: 0 failures"
  cargo test --test lints                        -> rc 0, 237 passed
  ```

  **THE SHAPE.** The self-test **spawns real processes**, reaps them, and asserts liveness on both the reaped and the deliberately-spared controls. Under contention a spawn or a signal can lose its race, so the assertion observes the wrong state. **The guard is correct in what it checks — the `NAME`, `OOD` and `NOTAG` controls are exactly the "a guess is never a kill" property that a past `pkill` incident earned — but its instrument is timing-dependent.**

  ⛔ **WHY IT MATTERS MORE THAN ONE FLAKY TEST.** A red that clears on re-run trains the reader to re-run reds. That is the habit that lets a *real* regression through, and this suite is the one carrying the round-close ratchets. **A guard that cries wolf is a guard being disarmed slowly.**

  ⊕ **AND IT IS THE `FLAKY_CEILING=0` PHILOSOPHY APPLIED INCONSISTENTLY**: `scripts/sanitize_sweep.sh` refuses to tolerate a single flaky row, while this lint's own flakiness has no ceiling and no record.

  **INTENDED:** the self-test is deterministic under load — wait on an observable state transition rather than on a spawn completing, or run the process-spawning half behind an env gate with the pure-logic half always on. **Do not fix it by widening a timeout**; that trades a fast wrong answer for a slow one.
