- **🆕🧹 [MED — a blanket fallback that converts "the lowering emitted a call nobody defines" into a silently-linked binary. Found 2026-09-04 by R49 Track A2-α while closing the two dead prefix predicates in `validate.rs`] `auto_register_externs` makes `ValidationErrorKind::UndefinedFunction` structurally unreachable.**
  - **THE MECHANISM, read in source.** `auto_register_externs` (`src/ir/lowering/mod.rs`) walks every `Call` / `CallExtern` / `Invoke`, collects the callees that are in neither `module.functions` nor `module.externs`, and pushes each one as `ExternDecl { params: vec![], is_variadic: true, .. }`. It filters on exactly two things — `known` and the enclosing function's `param_names` — and contains **no name test of any kind**. It runs at `mod.rs:1688`, and validation runs at `:1717`. `validate.rs` builds its `callables` set from `functions` + `externs`, so by the time the check executes **every callee is in `callables` by construction, whatever it is called.**
  - **MEASURED TWO-STAGE (Core #13), 2026-09-04.** On an ordinary `Callable` program with no name games: (1) delete the two `__callable_` / `__gorget_closure_call_` prefix carve-outs from `check_instruction_calls` → still `42`, rc 0, output byte-identical; (2) additionally early-return from `auto_register_externs` → **build rc 101, `call to undefined function @__callable_1`.** The sweeper, not the carve-outs, is what keeps the check inert. ⛔ **A2-α's brief carried the claim that closing those two predicates would make the check TOTAL once the mints were gone. That claim is FALSE and was retracted before the executor ran; it is false both before and after α.** Do not re-derive it from the deletion.
  - **BLAST RADIUS, so nobody "just fixes the sweeper" in passing.** With `auto_register_externs` disabled, a sample of 31 fixtures (every 13th) gives **26 FAIL / 5 pass**, 19 of the 26 on `call to undefined function`, and the invented names are entirely ordinary runtime spellings — `gorget_array_push`, `gorget_array_new`, `__option_unwrap`, `Vector__int64_t__push`. This is a corpus-wide dependency, not a handful of sites.
  - **WHY IT MATTERS.** The check it disables is the one that would have caught a whole class at the GIR boundary: a lowering arm emitting `Instruction::Call` to a name nothing defines. R49 Track A2-α retired one such class by construction (the indirect callee no longer HAS a name), but the validator that should have caught it never fired, and will not fire for the next one either.
  - **THE REFERENCE-GRADE SHAPE.** The sweeper exists because the lowering emits calls to runtime symbols it has not declared. That is the actual defect — a declaration the producer owes and does not write (devbook/24 rule 4, resolve once + write through). Burning it down means making each producer declare its runtime callee, then narrowing the sweeper to an env-gated census, then to fatal (Core #6's env-gate → burn down → fatal ratchet). Sizing needs its own scout; the 26/31 figure says it cannot ride along with anything else.
