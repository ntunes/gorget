- **🆕🚨 [HIGH — A FIFTH ROUTE INTO `t1388`'s META-CLASS: A SLOT ADDRESS HANDED TO A BY-VALUE POSITION. Found 2026-09-05 by R50 Track A2's scout, measured at the C-emit output.]**

  ```c
  __v17 = &__s2;                          /* address of the GorgetArray local */
  __v18 = (__gg_NV){ ._0 = __v17 };       /* ...into a BY-VALUE struct field */
  ```

  **Positive control — the runtime's own invariant catches it:**
  ```
  gorget: panic: gorget_array_free invariant: data=0xffffef46b0b0 but alloc=NULL (cap=0, len=0)
  ```

  ⭐ **AND THE SIBLING PATH IN THE SAME PROGRAM IS CORRECT** — ordinary struct construction emits `memcpy(&field, &src, size)`. **Two construction emit shapes, one deref-correct.**

  ⚠ **DISCRIMINATOR vs `t1388`:** that item is `Shared__T__clone(&slot)` at a **bare-bind** in `stmts/mod.rs`, with a refcount type. **This is a newtype / compound-literal CONSTRUCTOR FIELD INIT, no refcount type involved, and `is_refcount_clone_type` is irrelevant.** Same meta-class, different route.

  ⛔⛔ **IT IS MASKED TODAY, AND THE MASK IS ABOUT TO BE REMOVED.** `newtype N(Box[T])` currently lowers its payload field to `Unit` (1 byte, never dropped), so the bad store is harmless. **R50 Track A2's fix makes that field faithful — which UNMASKS this as a double-free.** ⇒ **the two are COUPLED: shipping the registration fix alone moves `newtype N(Box[T])` from silent pointer truncation UP the severity ladder to a double-free.** Sequence them together or gate the fix on this.

  ⚠ **SOURCE SITE UNDETERMINED.** The mechanism is measured at the emitted C; **the scout did not trace it to a source line and did not guess one.**

It is a valid **build-level** pin for the registration fix; **it is NOT evidence the newtype lowering is correct for a droppable payload.**

  ⛔⛔ **AND THIS ITEM IS NOT SUFFICIENT ON ITS OWN — see `todo/t1375`.** The constructor also **fails to move its source temp**, so fixing the address store alone leaves two owners of one pointer and **still double-frees**. Both are owed.

  ## ⛔ ROOT CAUSE CORRECTED 2026-09-05 (R50 Track A2's brief-review pass 2)

  **This is not an independent emit bug: it is the SAME root cause as `todo/t1375`.** The newtype constructor never becomes a `StructInit`, so both backends re-derive it by **name-matching** (`s.name == *name && s.fields.len() == 1`) — and the C arm writes `._0 = {arg}` with **no pointer/value adaptation** while **the LLVM arm HAS one** (`arg_ty.is_ptr() && !field.is_ptr()` → load-then-store).

  ⭐ **THAT ASYMMETRY *IS* THE MEASURED C/LLVM DIVERGENCE** recorded above — not a coincidence beside it. ⊕ Extended: `newtype NS(Vector[String])` → **C rc 1, LLVM rc 0.**

  ⇒ **Fix both at the upstream write site (lower to `StructInit`), which deletes both name-matching arms. Do not fix the two arms separately.**
