  ⭐⭐ **THE GUARD'S OWN SENTENCE IS WHAT IT FAILS TO KEEP TRUE.** `AGENTS.md`'s round-close block says
  local-green is the sign-off *"only for as long as that lint holds it true"*, and records that the earlier
  prose claim was **measured FALSE — three CI steps were absent, so a round could run the whole documented
  battery green while CI was red, and did.** ⇒ **the lint was written for precisely this class and cannot see
  this instance.**

  **THE MECHANISM, regenerated:**
  `grep -n "battery.contains(target)" tests/lints.rs` → the coverage predicate is a **substring containment**
  over the battery text. A CI step is "covered" the moment the battery mentions the same script path, **whatever
  arguments either side passes.**

  **THE LIVE INSTANCE, all three halves regenerated 2026-09-05:**
  1. `grep -n 'robustness_map' AGENTS.md` → the battery prescribes **bare** `python3 scripts/robustness_map.py`
     and describes it as *"five lanes (C · LLVM · self-host · ASan · ggdef)"*.
  2. `grep -n 'default=' scripts/robustness_map.py | grep -i lane` → **`--lanes` defaults to `"c"`.**
     ⇒ ⛔ **the bare command runs ONE lane. THE PROSE BESIDE IT IS FALSE.**
  3. `grep -n 'robustness_map' .github/workflows/ci.yml` → CI runs **`--lanes c,llvm`** *and* **`--lanes all`**.
  ⇒ **CI's five-lane step is a gate the battery does not run, and the lint reports it covered.**

  ⛔ **THE FIX IS NOT "ADD A ROW".** The predicate must compare what is actually GATED, not what is spelled:
  reconcile a CI step against a battery leg on **script + the arguments that change the gate's scope**, or
  require each CI step to name its battery leg explicitly. ⚠ **A fix that only special-cases `--lanes` repeats
  the defect on the next flag** — `GG_STAGING_MOVE_GUARD=fatal` and `--release` are the same shape.

  ⚠ **AND THE GUARD MUST BE ABLE TO CATCH ITS OWN CLASS (Core #6, both directions):** the RED direction is a CI
