- **🆕🚨 [HIGH — AN ENTIRE TYPE COMBINATION IS UNCOMPILABLE, AND IT IS WHY A MEMORY-SAFETY CELL COULD NOT BE REACHED. Found 2026-09-05 by R50 Track J's second scout while trying to construct the `elem_drop != NULL && elem_clone == NULL` cell.]**

  ```
  error: redefinition of 'Box__T__drop'
  ```

  **`Vector[Box[T]]` does not compile for ANY `T`.** Reproduced with a plain `.push` and with a concrete `Box[int]`, so it is **independent of the method and of the element type** — the glue is emitted for the **unsubstituted type parameter `T`** instead of the substituted instantiation, and two instantiations then collide on one symbol.

  ⭐ **WHY IT MATTERS BEYOND ITSELF.** It is the *only* surface route to the runtime configuration `elem_drop != NULL && elem_clone == NULL` — a configuration `src/backend/c/runtime/runtime_array.c` documents as legitimate. R50 Track J needed that cell to test a fix's behaviour there; **it could not be reached, and this is the reason.** That makes the cell *"unreachable with a nameable reason"* rather than an unnamed omission — but it also means **nothing in the corpus exercises that runtime configuration at all**, so a defect living there is invisible today. *(Measured by nulling `elem_clone` **by line number**, Core #13: HEAD double-frees; the `v3` candidate double-frees; the shipped hybrid refuses with a diagnostic.)*

  **INTENDED:** `Vector[Box[int]]` compiles, runs, and is ASan-clean on C and LLVM. Owes a `known_gaps` repro asserting the successful compile.
