- **🆕🐛 [gorget-arena snag #1 — filed 2026-08-09, R39] LLVM backend drops the C typedef for FFI-only-module structs.** A plain Gorget `struct` defined in an FFI-only module (`struct` defs + `extern "C"` block + NO Gorget-body functions — e.g. `xtd.sdl`'s `SDLEvent`, `xtd.audio`'s `AudioMusic`) never gets its C typedef emitted by the LLVM backend's runtime shim (`__gorget_runtime_*.c`). Any shim-emitted signature that mentions such a struct fails to compile with `error: unknown type name 'GorgetSDLEvent'`. C backend fine unless the struct is constructed directly (Gorget `SDLEvent(...)`) — related-but-distinct defect, same root. **Verified triggers** (`tests/fixtures/known_gaps/gorget_arena_snag_1_llvm_ffi_only_typedef/`): `mini.gg` = LLVM fails / C ok; `ctor_c_backend.gg` = C fails too (direct construction); `control_ok.gg` = both pass (module has method bodies, isolates trigger to "module contributes no lowered function bodies", not "library struct" or "passed by value"). **Root-cause hypothesis:** the shim's type-collection walks types reachable through each module's lowered functions; a body-less library module is skipped, so its struct typedefs are never gathered even when another module references them by value. **Fix path:** extend the shim's type walk to also include struct defs from modules that only contribute extern signatures — or, treat the collection axis as the extern-reachable types (not function-body-reachable). Reproducer preserved with README + `run.sh` that regenerates artifacts.
