- **📏 R47 Track F5a — MEASURED: (c) IS A CLONE RECLAIM, NOT A RENAME, AND NOBODY HAD MEASURED IT.**
  `.slice(a, b)` materializes an OWNED `String` on every call; the ratified colon form `s[a:b]`
  materializes NOTHING. One program, 1,000 identical calls, identical results (`5000` both):
  `string_clone` **1,002** with `.slice(0, 5)` versus **2** with `[0:5]`. So every remaining
  `.slice()` call site in the self-host is paying one heap materialization per call that the
  ratified spelling does not. **Recounted 2026-08-30: 205 CALL SITES across 11 files** — the count
  after strings and comments are stripped, which is what `tests/lints.rs::count_dot_slice_in_code`
  measures and what a migration actually has to change. A raw `grep -o '\.slice('` over the same
  glob says 211 across 12; the 6 extra are inside string literals and comments. All of them are in
  `tests/fixtures/self_host_lowerer/*.gg` —
  `tests/fixtures/self_host_typechecker/*.gg` has NONE of its own (the ones that appear to be
  there are the symlink seam). ⚠ The `no_dot_slice_after_d22` allowlist comment carried **208**
  for three rounds; regenerate the number rather than quoting either. That reframes (c) from a
  cosmetic migration into a sized, mechanical clone reclaim against the four clone ratchets, and it
  should be re-derived (not quoted) before the track is scoped: rebuild and re-run the A/B, then
  measure the four meters before and after a pilot file.
  ⊕ The live instance that made this visible is `todo/t0850` — `loader.gg::parent_dir` scans a path
  character by character with `path.slice(i, i + 1)`, so it costs one heap `String` per character

  the checkout. Its repro
  (`tests/fixtures/known_gaps/sh_parent_dir_clones_one_string_per_path_char.gg`) is the one
  allowlisted `.slice()` site in `tests/lints.rs::no_dot_slice_after_d22`.
