- **🆕🚨 [HIGH — SILENT WRONG-CODE, BOTH LANES, `gg check` clean; ratified 2026-08-16 (define-gorget ledger), surfaced by the R42 A2 style review] A `case` arm naming something that does not exist silently becomes a CATCH-ALL that kills every arm below it — implement the ratified two-rule REJECT.** Measured at HEAD, one probe, `enum Day{Mon,Sat}`, scrutinee `Mon()` returned from a function (nothing const-folds), `gg check` → "OK: no semantic errors" for every cell:

  | pattern | name is a variant of the scrutinee? | Rust gg | ggdef | verdict |
  |---|---|---|---|---|
  | `case Sat:` | yes | `else-arm` ✓ | `sat-arm` ✗ | DIVERGENCE A — ggdef BINDS instead of matching |
  | `case Sat():` | yes | `else-arm` ✓ | `else-arm` ✓ | agree |
  | `case Satx:` | no (typo) | `typo-arm` | `typo-arm` | agree — both silently catch-all |
  | `case Satx():` | no (typo) | `typo-arm` (catch-all) | `else-arm` (never matches) | DIVERGENCE B |

  With the typo'd arm FIRST, Rust gg prints `typo-arm/typo-arm` — two live arms dead — while ggdef prints `mon-arm/sat-arm`: one accepted program, two different behaviours ⇒ Core #8, ≥2 bugs. Not limited to typos: `case Red:` where `Red` is a variant of a DIFFERENT enum than the scrutinee is taken by BOTH engines. Root: `src/semantic/typecheck.rs:5833-5840` deliberately treats a `Pattern::Binding` whose name is not in the scrutinee's variant set as a variable binding ("It's a variable binding — acts as a catch-all"), and the qualified spelling (`case Day.Sat:`) is a fixed point of the whole axis on both engines.

  **RATIFIED FIX — two rules, both compile ERRORS (ledger 2026-08-16):** **(1) UNREACHABLE-ARM** — any arm following a catch-all (bare binding, `_`, or `else`) is an error (Rust's `unreachable_patterns`, promoted from lint to error); this catches the typo'd variant, the typo'd CONSTANT, and works on non-enum scrutinees. **(2) BARE NAME ON AN ENUM SCRUTINEE MUST RESOLVE** — where the scrutinee's type is an enum, a bare identifier in the arm's TOP-LEVEL pattern must resolve to a variant or a `const`/`static`, else an error whose diagnostic points at `else:`; this closes (1)'s blind spot, a typo in the LAST arm where nothing below becomes unreachable.

  **Bindings are NOT removed and cannot be** — `Pattern::Binding` is how destructuring names payloads (`case Custom(r, g, b):`), how guards name the scrutinee (`case x if is_even(x):`), and how `is` introduces names into the following `then` block (`docs/language-reference.md:1930`). All SIX bare-binding sites in the corpus match on `int` and are unaffected by rule (2): `match_guard_complex.gg:30`, `test_match_advanced.gg:121`, `const_match_pattern.gg:41`, `match_patterns.gg:17`, `fmt_suite_layout/orphan_close_arm_containers.gg:59,71`.

  **PRECEDENT — this project was already bitten by this exact class:** before 2026-05-13 a bare `case CONST_NAME:` always shadowed the constant with a fresh binding, "so the FIRST `case` arm always matched (every input went down it)", found during self-host `format_gir.gg` work (see `tests/fixtures/const_match_pattern.gg`'s header). Fixed for constants only; the variant flavour stayed live.

  **OPEN for the implementing scout:** whether rule (2) extends to NESTED pattern positions — `case Some(v):` where the payload type is itself an enum would reject a legitimate destructuring bind under a naive reading, while `case Some(None):` must keep working. Decide with the scout, not in the brief. Accept/reject change ⇒ Core #9: all three lanes + cross-lane NEG conformance fixtures, its own round.
