- **[MED — ggdef PHASE-0 SUBSET GAP, filed while closing the per-function-prescan class] The 3 standing generic-equip `EXCLUDE`s have no oracle row, and nothing in the tree says what it would take to give them one.** `register_equip` (`spec/ggdef/src/elaborate/mod.rs`) opens with `if eq.generic_params.is_some() { return Err("generic `equip` blocks are excluded from phase 0 …") }`, so `cow_element_borrow_alias_mutate`, `cow_p3_alias_chain_mutate` and `cow_p3_index_mutate` are excluded by the elaborator itself — named as "the standing exclusions (RFC §6)" in `corpus_a.rs`, `corpus_b.rs`, `corpus_b1.rs` and `reports/phase0_completion.md`, but never filed as work.
- **Why it matters now.** Generic-equip `&self` mutators were just shown to be a use-after-free class on the Rust lane and a write-through class on the self-host lane. ggdef is the truth axis for value semantics (Core #13), and the one construct where both compilers were provably wrong is the one the oracle refuses to elaborate. Every generic-equip CoW question is currently adjudicated by "the two compilers agree", which Core #8 says is necessary and not sufficient.
- **The gap is narrower than the error message implies.** The gate keys on `eq.generic_params`, i.e. the `equip [T] Cell[T]` spelling. The `equip Cell[T]` spelling (type args on the target, no leading `[T]`) has `generic_params == None` and **elaborates fine** — `cargo run -q -p ggdef -- run tests/fixtures/cow_generic_equip_mutator_view_uaf.gg` prints `helloworld`, which is exactly how that fixture's UAF was adjudicated. So a monomorphising elaboration already works for one spelling; see `todo/t0875` for the asymmetry itself.
- **What to do:** elaborate a generic `equip` by monomorphising per concrete receiver instantiation (the same shape the Rust and self-host lowerers use), or state in the RFC why phase 0 cannot, and turn the three `EXCLUDE` rows into cited subset-gap rows rather than a bare exclusion list. Verify with `cargo test -p ggdef` plus the three fixtures above.
