- **🆕🧹 [MED — A GUARD THAT LOOKS WIDER THAN IT IS. Measured 2026-09-06 by R51 Track A's executor, carrying forward two named omissions its brief-reviews established.]**

  `validate_box_wrapper_abi` and `validate_box_get_ptr_result_consumed` (`src/lir/validate.rs`) both walk `module.externs` / `module.functions` at LIR. Two arms sit outside that domain, and **the same diagnosis was reached independently at each, one review generation apart**:

  - **`drop`.** `emit_box_wrapper` really does emit a `"drop" | "free"` arm by value (regenerate: `grep -n '"drop" | "free"' src/backend/c_lir/helpers.rs`). But `module.externs` contains **no `Box__*__drop` under any spelling** — the by-slot producer emits a DEFINITION, not a declaration. Adding the arm to the guard's match would not widen it; it would add **an arm that can never fire**. Two earlier justifications for the exclusion were checked and both were FALSE before this one was found.
  - **`GuardAccept`.** The D36 block has a second wrapper-kind arm doing the identical `recv = <projection result>` rewrite, and the downstream `field_place_info` re-derivation is wrapper-kind-agnostic. Measured with a positive control in the same run: `--emit-gir` shows two `get_ptr` calls, `--emit-lir` shows **zero** — the projection is eliminated between the layers. So the sibling is outside the ITERATION DOMAIN, not merely outside the name filter. (It is also not a live defect today: `g1_guard_accept`-shaped programs build and print correctly.)

  ⭐ **THE CONSTRUCTIVE FIX IS ONE LAYER UP, AND IT IS THE SAME FIX FOR BOTH.** The value guard's question — *is the receiver projection's result consumed* — is a **GIR** property implemented at LIR. At GIR both wrapper-kind arms exist and the `Box__*__drop` producer is visible, so the subject would be genuinely TOTAL rather than total-looking.

  ⚠ **WHY IT IS FILED RATHER THAN DONE:** moving a guard up a layer changes what "an extern" means for it and needs its own RED/GREEN calibration against the same cell set. Both omissions are recorded in the guards' own doc comments, so the record does not depend on this item surviving.

  **INTENDED:** the receiver-projection subject is asked where both arms exist, and the guards' arm set matches `emit_box_wrapper`'s without any arm that cannot fire.
