- **🆕 [LOW — A TEMP-FILE FAMILY THAT NO CLEANER OWNS. Found 2026-09-09 while measuring the orphan reaper's over-rejection gate against the real roots on this box.]**

  Regenerate the census:

  ```
  ls -Ap /tmp | grep '^gg_' | grep -v '/$' | wc -l          # stray FILES
  ls -A  /tmp | grep '^gg_' | sed 's/[0-9]\+/N/g' | sort | uniq -c | sort -rn | head
  ```

  At the time of filing that was **759 files** against **93 directories**, in a handful of shapes — `gg_selfhost_build_N.c`, `gg_amp_route_leak_N.c`, `gg_two_types_same_name_N.c`, `gg_capcost_*_N.c`, `gg_slice_cost_*_N.c`.

  **PRODUCERS, cited rather than guessed:**
  - `tests/integration.rs:21265` — `.join(format!("gg_capcost_{name}_{}", std::process::id()))`
  - `tests/integration.rs:21394` — `.join(format!("gg_two_types_same_name_{}", std::process::id()))`
  - `tests/fixtures/self_host_lowerer/driver.gg:651` — `String c_path = "/tmp/gg_selfhost_build_" + int_to_str(time_ms()) + ".c"`

  ⭐ **WHY THIS IS NOT JUST UNTIDINESS.** `scripts/reap_orphans.py` decides domain membership with `entry.is_dir(follow_symlinks=False)` before anything else, so **a `gg_`-prefixed FILE is invisible to every bucket, including the UNDECIDABLE one that exists precisely so a blind spot has a number.** The tool's header enumerates what the domain cannot see — untagged `.tmp` dirs, unreadable `/proc/<pid>/exe`, other PID namespaces — and this family is a fourth one that is not on the list. A reaper whose stated design principle is *"everything this tool cannot decide is COUNTED AND NAMED"* is currently silent about the largest `gg_`-prefixed population on the box.

  ⚠ **AND ONE OF THE STAMPS IS NOT A PID.** `gg_selfhost_build_<time_ms>.c` carries a millisecond stamp, not an owner. Today that is harmless — it is a file, so it never reaches the owner-tag reader — but it means the `gg_` prefix does **not** imply the `gg_<label>_<pid>` convention the reader's census asserts, and a future producer that mints a *directory* on that pattern would land as UNDECIDABLE rather than owned.

  **INTENDED:** the producers write into a scratch root they own and remove (the `TmpRootGuard` shape the harness already has) instead of straight into the temp dir, so the file family stops existing rather than gaining a cleaner. Failing that, `[[t0900]]`'s run ledger subsumes it — a run that registers its artifacts at birth can unlink files as easily as directories. **Do not "fix" this by teaching the reaper to delete files**: the tool's whole discipline is that it signals only what it can prove ownership of, and a filename is not proof.
