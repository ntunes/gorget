- **🆕🚨 [HIGH — A GUARD-BLINDING HAZARD IN THE RUNTIME: a static scratch buffer SILENTLY SUPPRESSES LEAK REPORTS; found 2026-09-05 by R50 Track J's scout, BY MEASUREMENT, in its own prototype]** A stale element copy in a static thread-local makes a real leak invisible to LSan.

  ⭐⭐ **HOW IT WAS FOUND, AND WHY THAT MATTERS:** the scout's intermediate prototype introduced a static
  thread-local scratch buffer. Under it, a **pre-existing `Vector[Box[Speaker]]` leak DISAPPEARED —
  deterministically, 3 of 3 runs.** Adding a `memset` of the scratch at function exit **brought the leak back**,
  matching HEAD. ⇒ ***the buffer is an LSan ROOT: a stale copy of the element keeps a genuinely-leaked payload
  REACHABLE, so LSan never reports it.*** **A guard-blinding regression that would have shipped invisible.**

  ⛔ **AND `sanitize_sweep.sh` DOES NOT PROTECT AGAINST IT.** It runs `LSAN_OPTIONS='use_stacks=0'`
  (regenerate: `grep -n "use_stacks" scripts/sanitize_sweep.sh`), which disables **STACK** roots — **not static
  ones.**

  🚨 **THE PRE-EXISTING SITES HAVE THE SAME PROPERTY AND NO `memset`:** `gorget_array_swap` and
  `gorget_array_remove_opt` (regenerate: `grep -n "static.*scratch\|thread_local" -B 3 -A 8
  src/backend/c/runtime/runtime_array.c`). ⇒ **any leak whose payload happens to be the last element swapped or
  removed may be silently under-reported by the whole sanitize sweep.**

  ⛔ **THE FIX IS NOT ONLY `memset` AT THOSE TWO SITES (Core #6): the sweep needs a guard that CATCHES THIS
  CLASS** — a static root that can hide a leak is exactly the shape a leak gate must not have. ⚠ **A positive
  control is required: show a known leak going UNREPORTED with a populated scratch and REPORTED after.**
  *(Core #13 — verify the verifier; the scout's own accidental discovery is the template.)*
