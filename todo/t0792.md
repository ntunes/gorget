- **🆕🐛 [MED — WRONG ANSWER, `gg check` clean, both backends, ASan-clean; found 2026-08-29 by R47 Track E2's executor while closing the for-loop producer class] `for x in it` over a direct-Iterator reached through a `&`-param advances a COPY of the iterator, so the caller's object is never advanced.** `void consume2(Counter &c): for x in c: if x >= 1: break` consumes two elements, so `p.idx` must read **2** after `consume2(&p)`; it reads **0**.
  - **THE ADDRESSING IS THE DEFECT, and it is one layer BELOW the for-loop.** A local that borrows a param carries `LocalOwnership::Borrowed { origin: Param(_), .. }` and its SLOT holds the caller's pointer, while its GIR type stays the **pointee's value type**. So the for-lowering can reach the caller's object by neither route, and both were measured: `BorrowMut(Place::local(l))` emits `memcpy(&copy, *slot, sizeof(T)); &copy` — the address of a materialized copy; `BorrowMut(Place{local: l, projections: [Deref]})` **SEGVs** (`AddressSanitizer: SEGV`, `Bag__next` ← `memcpy`); and passing `Copy(Place::local(l))` straight through as the receiver still materializes, because the operand's type is the value type, not a pointer. **Fix the representation** (a param borrow should be Ptr-typed, or carry a typed accessor that yields the pointer operand) rather than adding a fourth special case at a consumer.
  - **⚠ SAFE, NOT SILENT-UNSAFE — and the carve-out that makes it safe MUST NOT be removed on its own.** `for_loops.rs`'s `iterator_source_place` recognises this shape and returns `IteratorRef::ShallowAlias`, and the element binding then skips `bind_owned_for_drop`: over a shallow alias the caller's object still owns everything the loop was handed, so the elements are BORROWS and a move-out body clones instead of moving. **Deleting that carve-out while the addressing is still broken converts this wrong answer into a DOUBLE-FREE** — measured, `attempting double-free` from `Bag__drop` after the elements were moved into a `Set`.
  - **⚠ THE CARVE-OUT CARRIES ITS OWN (PRE-EXISTING) COST: over a `ShallowAlias` iterator, an element `next()` FRESHLY ALLOCATES leaks.** The alias case cannot tell a transferred element from a fresh one, so it treats every element as a borrow. That is HEAD's behaviour for this shape — no regression, nothing new leaks — but it means the R47 element-leak fix does not reach loops over a `&`-param iterator. Both halves close together when the addressing does.
  - **THE SIBLING SHAPES ARE FIXED, so this is the residual cell, not the class.** A bare named local and a struct FIELD both advance the real object at HEAD after R47 Track E2 (`iterator_source_place` sees past `deref_ptr_collection_iterable`'s bit-copy for the Ptr-typed field read); `tests/fixtures/security/foriter_direct_advances_source.gg` and `foriter_direct_drain_move_out.gg` pin them.
  - **⚠ `lib/std/iter.gg` DEPENDS on the general property.** `VectorDrain`'s `Drop` "reverses the remaining buffer back if the caller breaks early, so unconsumed elements drop in insertion order" — a contract that is only meaningful when the advanced object is the dropped one. A drain-shaped iterator passed by `&` still silently violates it.
