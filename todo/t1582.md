- **🆕⚙️ [LOW — REFERENCE-GRADE UPGRADE: MAKE THE SWEPT POPULATION AN ARTIFACT INSTEAD OF INFERRING IT. Filed 2026-09-06 by R51 Track J's executor, which shipped the proxy deliberately and states its limit here.]** `adjudicate_leaks` routes an allowlist row with **no verdict line at all** to a new `absent` bucket, fatal, with a message naming three causes: the `.gg` was deleted; the fixture still exists but left the swept population; a worker died before printing its row. **The gate cannot tell which**, because "was it in this run" is inferred from the absence of output rather than read from the input.

  **The fix is small and keeps the arity.** All four `adjudicate_leaks` call sites pass `<dir>/verdicts.tsv`, so `tee`ing the walked file list to `$OUT/population` and deriving presence from `"$(dirname "$2")/population"` adds no operand — the property that lets the existing self-test pick the change up for free. Then `absent` splits into *"not in the population"* (deleted or de-listed, and the manifest says which) and *"in the population, no row"* (a worker died — a run-integrity failure, not an allowlist finding).

  **⊕ AND THE SECOND HALF OF THE SAME SYMMETRY: EXTRACT `adjudicate_corruption()`.** The corruption
  allowlist is adjudicated by four inline `comm` pipelines in the script body, while the leak allowlist
  goes through the `adjudicate_leaks` function that `run_selftest` drives on every invocation. That
  asymmetry is why `todo/t1360`'s defect survived one list over for a whole round after being fixed on
  the other, and why the corruption split can only be pinned by string needles today. Lifting it into a
  function with the same `<allow> <verdicts> <dst>` shape lets the existing self-test watch it fire with
  the controls that already exist.

  **⚠ THE SILENT-MOVE HAZARD THIS WOULD ALSO SURFACE.** `awk -F'\t' '$2=="IN"' tests/sanitize/CORPUS_MANIFEST.txt` returns **nothing** today: every directory row is `OUT`, so the swept corpus is exactly the top-level `*.gg`. Moving a fixture into any subdirectory therefore drops it from the sweep with no declaration and no diff in the manifest. The `absent` bucket catches that only for a fixture that happens to hold an allowlist row.

  **⊕ THE NEW RED SURFACE THIS BUCKET INTRODUCED, STATED PLAINLY** (it is intended, not a defect): an allowlist row whose `.gg` was **deleted** used to be `rc 0` — an advisory *"✅ no longer leaking — DELETE these rows"* — and is now **`rc 1`**. That is fail-closed and nothing else in the tree catches it (`LEAK_CEILING`'s `assert_eq!` still passes on the stale row, and `covered` drops by one against roughly 97 rows of floor slack), but it is a mode that used to be green. The fix for the benign case is to delete the row **and** lower `LEAK_CEILING` in `tests/lints.rs` by one, which is what the gate now prints.
