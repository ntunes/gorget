- **🆕🚨 [MED — A FLAKY SELF-TEST THAT, WHEN IT FLAKES, IS REPORTING A REAL MIS-REAP. Found 2026-09-09 by an orchestrator lint run.]**

  `cargo test --test lints orphan_reaper_self_test` failed once and then passed three consecutive re-runs. **The failure is not noise — it is the reaper killing something it must not.**

  Observed, verbatim from the failing run:

  ```
  FAIL NOTAG unparsable owner tag is UNDECIDABLE, not reapable  pid ...
  FAIL NOTAG control is STILL ALIVE after --reap  untouched — a guess is never a kill
  ...
  scratch roots: 4 tagged (3 owner-dead), 0 with no parsable owner tag
      pid ...  owner 8 dead   /tmp/gg_st..._notagxhj99ug_8/async_select_diff
      reaped pid ... [group kill]
  ```

  **THE MECHANISM.** The NOTAG root's name ends in a **random token**, and the scan reports `0 with no parsable owner tag` — i.e. it parsed the "unparsable" one. A token whose tail is `_<digits>` matches the owner-tag convention (`<label>_<ownerpid>`, as the sibling roots show), so the reaper resolved a bogus owner pid, found it not running, classified the root REAPABLE, and **killed the control**.

  ⭐ **WHY THIS IS NOT MERELY A FLAKY TEST.** The reaper's stated invariant is *"a guess is never a kill"*, and the whole tool exists because of an earlier `pkill` incident. This case is the tool **guessing an owner out of an arbitrary string and killing on it**. The self-test is correct; it caught a real hazard and is then dismissed as flake because it usually passes. SIX-Q #6 inverted: the case is usually GREEN for a reason unrelated to the property — the random token usually happens not to end in digits.

  ⚠ **AND IT IS A GATE.** `orphan_reaper_self_test` runs in `cargo test --test lints`, part of the round-close battery, so this can red a close for a reason nobody will reproduce.

  **INTENDED, two independent fixes, both owed:**
  1. **The control must be un-parsable BY CONSTRUCTION**, not by luck — a tag that cannot end in `_<digits>` (or an explicit non-numeric sentinel), so the case tests what it claims.
  2. ⛔ **THE REAPER ITSELF SHOULD NOT ACCEPT ANY TRAILING `_<digits>` AS AN OWNER.** That is the actual defect the flake exposes — the tag needs a discriminating shape (a fixed prefix it must carry), so an arbitrary directory name cannot be misread as an ownership claim. Fixing only (1) hides the finding.

  **REPRO:** run the self-test in a loop until the generated NOTAG token ends in `_<digits>`; the two `FAIL NOTAG` lines appear with the control reaped. A durable reproducer should instead call the tag parser directly with a name ending `_8` and assert it is rejected.
