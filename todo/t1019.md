- **🆕🚨 [HIGH — Core #10 lower-or-reject, `gg check` CLEAN on a method that does not exist; both backends;
  found 2026-09-03 by the R49 Track C pass-2 review, orchestrator-verified. ⭐ **THIS IS THE SUBJECT SIX
  REFUTED MECHANISMS WERE CIRCLING**] The checker never asks whether a user type HAS the method.**
  ```gorget
  struct Plain:
      int a
  void main():
      Plain p = Plain(1)
      print(p.some_bogus_method())
  ```
  **`gg check` → `OK: no semantic errors`. `gg build` → rc 1, ``undefined reference to `Plain__some_bogus_method'``**
  (orchestrator-verified). A misspelling survives the entire front end and dies as a raw linker error with
  no span, no diagnostic, and nothing pointing at the typo.
  - ⭐ **AND ON A NAMELESS RECEIVER IT DOES NOT EVEN FAIL LOUDLY.** On a `Callable[int(int)]` parameter,
    `print(f.totally_bogus_method())` is **`gg check` clean, builds rc 0, and PRINTS `0`** — the call folds
    to `Constant::Unit`. **Same missing check, two outcomes: a raw link error where the receiver has a type
    name, a silent wrong answer where it does not.**
  - ⭐ **WHY THIS MATTERS BEYOND ITS OWN SEVERITY — it is why R49 Track C burned six mechanisms.** That
    track kept trying to add a *lowering-side* guard for four specific method names
    (`is_some`/`is_none`/`is_ok`/`is_error`), and every attempt died on a healthy population:
    a receiver-keyed table cannot see a method reached through a **trait bound** (`impls_by_name`), nor one
    reached through a **trait impl** (`fn_sigs`), and a name-scoped guard covers *four names out of an
    unbounded set* — yielding a compiler that would reject `is_some` and silently miscompile `is_somee`.
    ⇒ **The subject was never "these four names". It is "the receiver type has no such method", and it
    belongs at CHECK time.** One rule closes the whole family.
  - ⛔ **CONSEQUENCE FOR TRACK C, stated so nobody re-derives it:** Track C's step 1 (letting a
    non-Option/Result receiver fall through to normal dispatch) **creates NO new class.** Every apparent
    "regression" it produces — `Plain` / `Color` / `Callable` local → raw link error; `Callable` param and
    `Callable &` param → prints `0`; `bool` → raw link error — is **an instance of THIS pre-existing hole**,
    reachable today by a one-token typo.
  - **DISCRIMINATED FROM ITS NEIGHBOURS:** `t0025` is the same *symptom* (check-accepts, methods vanish,
    link dies) with a **different mechanism** — cite it, do not merge. `t0942` is the **Callable half's**
    upstream cause (*"a `Callable` PARAMETER lowers to GIR `unit` … the fix is upstream — the
    representation must carry the type (Layering rule 1)"*), so the nameless-receiver cells are **its**
    write-site, not this item's. `t0987` is mechanism-adjacent (an unresolved method fabricating a *runtime
    symbol* rather than falling through). This item is the **missing check itself.**
  - **INTENDED:** `p.some_bogus_method()` is **REJECTED at check time with a spanned `E_NoMethodFound`
    naming the method and the receiver type** — the diagnostic the language already emits for a struct that
    *does* carry an `equip` block. ⊕ `f.totally_bogus_method()` on a nameless receiver rejects the same way
    once `t0942` gives the representation its type.
  - ⚠ **THE RISK TO MEASURE BEFORE LANDING IT, because two adjacent attempts died exactly here:** a
    method-existence rule must not reject methods that arrive through a **trait bound** on a generic
    parameter (`equip [Iter, T] TakeIter[Iter, T] with Iterator[T]` calling `self.inner.next()` —
    `lib/std/iter.gg:473`), through a **trait impl** (registered as `{Trait}_for_{Type}__{method}`,
    `traits.rs:311`), through a **trait default**, through `Box[Trait]`, or through an **auto-derivable**
    (`typecheck.rs:3145-3148`). **Sweep the whole corpus check-only and require ZERO new rejections** — an
    earlier attempt at an adjacent rule produced **57**.
  - **REPRO OWED:** `known_gaps/` cells for the misspelled method on (a) a bare struct, (b) an enum, (c) a
    `Callable` local, (d) a `Callable` parameter — **plus the positive controls that make the rule
    provable**: a struct WITH an `equip` block (rejects correctly today), a trait-bound generic parameter, a
    trait-default method, and `Box[Trait]`. RED-verify against HEAD.
