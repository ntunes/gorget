- **[MED — R47 Track F5a, measured] `parent_dir` costs ONE heap `String` per CHARACTER of the path, and
  that is why the clone ratchet reads a different number depending on where your checkout lives.**

  **THE SITE.** `tests/fixtures/self_host_lowerer/loader.gg:26-38`:

  ```gorget
  String parent_dir(String path):
      # Extract parent directory: find last '/' by scanning
      int last_slash = -1
      int i = 0
      while i < path.len():
          if i + 1 <= path.len():
              String ch = path.slice(i, i + 1)      # ← loader.gg:32:25
              if ch == "/":
                  last_slash = i
          i += 1
  ```

  `String ch = path.slice(i, i + 1)` is a `VarDeclFromBorrow` on a freshly-minted one-character
  `String`, executed once per character, to answer "is this byte a slash".

  **THE MEASUREMENT, and it is exact.** `parent_dir` runs 7 times per self-host compile, on paths
  rooted at the project root, so the compiler's total `string_clone` is a linear function of the
  length of the absolute path to the checkout. One fixed instrumented driver binary, four root
  paths, zero residual:

  | root path | len | `string_clone` |
  |---|---:|---:|
  | `/tmp/s` | 6 | 31,474,135 |
  | `/workspace/gorget` (the main checkout) | 17 | **31,474,212** |
  | an agent worktree under it | 59 | **31,474,506** |
  | a 84-character root | 84 | 31,474,681 |

  ⇒ `string_clone = 31,474,093 + 7 × len(root)`. `array_clone` is invariant.
  `--clones=sites-tsv` attributes the WHOLE delta to ONE CloneId (#2985 = `loader.gg:32:25`,
  `VarDeclFromBorrow`, `String`, `gorget_string_clone_to_owned`) — 1 differing site out of 1,475,
  delta 546 out of 546 over a 78-character span.

  **WHY IT MATTERED ENOUGH TO CHASE.** R47 pinned the stage-0 string ceiling at 31,474,212, measured
  in the main checkout, while every measuring worktree reads 31,474,506. That 294 was recorded in the
  tree as *"two instruments disagree, track F5 adjudicates which is right"*. **Neither instrument was
  wrong**: 7 × 42 characters = 294. The effect is three orders of magnitude below the ~1%
  authorization band so it cannot flip the gate, but it corrupts ATTRIBUTION — the thing an exact pin
  exists for — because a track measuring in its worktree reports a delta it did not cause. The gate
  now prints `[clone-meter] root_len=…` so two readings are never silently compared across checkouts;
  that is a declaration, not a fix.
  ⚠ **THE EFFECT IS STAGE-0 ONLY, MEASURED.** Both STAGE-1 pins reproduce to the digit across the
  same 42-character checkout difference (1,129,955,831 / 2,371,710,742, pinned from a run in
  `/workspace/gorget` and re-measured in a 59-character worktree). The likely reason is that
  stage-1's counts come from C the SELF-HOST emitted, and the self-host's own lowering of this bind
  does not route through `gorget_string_clone_to_owned` — but that is an inference, not a
  measurement, and it should be checked before anyone leans on it.

  **THE FIX IS ONE CHARACTER CLASS, AND IT IS MEASURED FREE: spell the slice the way D22 ratified.**
  `.slice(a, b)` materializes an owned `String` on every call; the colon form `s[a:b]` materializes
  NOTHING. Measured on one program, 1,000 identical calls, identical results (`5000` both):
  `string_clone` **1,002** with `.slice(0, 5)` versus **2** with `[0:5]`. Swapping the two `.slice`
  calls in `parent_dir` for `path[i:i + 1]` / `path[0:last_slash]` was measured to take the repro
  from 7-vs-38 clones (scaling with length) to 3-vs-3 (flat), with byte-identical output on every
  probe path (`/a/b/c` -> `/a/b`, no separator -> `.`, `/a` -> ``). Do that, and consider the
  clearer `split`-based rewrite separately.
  ⚠ `parent_dir` has two callers (`loader.gg:64`, `loader.gg:624`); landing this moves the clone
  meters DOWN, which needs no sign-off, and makes the STAGE-0 string meter checkout-invariant by
  construction.
  ⊕ **THIS IS AN INSTANCE OF A MUCH LARGER LEVER, recorded on `todo/t0316` (the D22 migration,
  Track C-3b).** Every remaining `.slice()` site in the self-host pays the same per-call
  materialization. That migration has been carried as a cosmetic rename; it is a sized clone
  reclaim, and this is the first measurement of it.

  **THE FAMILY** is the `VarDeclFromBorrow` clone class: `t0543` (return-view lazy materialization),
  `t0561` (per-reason budgets), `t0540` (the ceiling re-pins). ⊕ **What DISCRIMINATES this one:** it
  is not waiting on any of them. A perfect lazy-bind reclaim still leaves `path.slice(i, i + 1)`
  minting a genuinely new one-character `String` — the defect is the algorithm, not the ownership
  analysis, and it is also a "self-host reads like the user manual" violation (nobody would
  recommend this scan in `docs/book/`).
