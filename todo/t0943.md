- **🆕🐛 [MED — Core #8 REFERENCE LAGS THE SELF-HOST: the same place, two spellings, two verdicts] Rust gg accepts `v.push(t._0)` on a `Mutex` tuple element while rejecting `v.push(t.0)`.**
  ```
  (Mutex[int], int) t = (Mutex[int](5), 1)
  v.push(t.0)     # error[E_MoveWithoutOperator]  ✓
  v.push(t._0)    # ACCEPTED — rc=0                ✗
  ```
  `._N` is the ratified alias for `.N` (language-reference §4.2/§7.8) and Rust honours it everywhere else — `print(t._0)` compiles and prints `7`, via the `strip_prefix('_')` path at `src/semantic/typecheck.rs:3817`. But `src/parser/expr.rs:1263` only builds `Expr::TupleFieldAccess` when the token after `.` is an `IntLiteral`; `_0` falls to `expect_name()` and becomes `Expr::FieldAccess{field: "_0"}`. `lvalue_value_type` (`src/semantic/safety/helpers.rs`) then splits on the node: the `TupleFieldAccess` arm reads `ResolvedType::Tuple(elems)`, while the `FieldAccess` arm requires a `Defined | Generic` def id to index `struct_field_names`. A tuple has neither, so it returns `None` and D53's consume gate sees no type.
  **THE SELF-HOST IS THE CORRECT LANE HERE.** Its parser has no tuple-index node at all — `t.0` and `t._0` both fold into `EFieldAccess` — and since R48 Track P both of its resolvers read the spelling through one shared `tuple_field_index` helper, so the two spellings CANNOT diverge by construction. Per "the succession plan", fix the Rust side as oracle hygiene; do not weaken the self-host to match.
  ⚠ **The likely-wrong fix is to special-case `_0` in `lvalue_value_type`.** The defect is that ONE surface concept (a tuple index) has TWO AST spellings, and every consumer of the place AST must then remember both — the safety walk is simply the first consumer caught. Prefer normalising at the parser (fold `._N` into `TupleFieldAccess`), which retires the class; a read-site patch fixes this gate and leaves the next consumer exposed.
  ⊕ Scope beyond D53: any `lvalue_value_type` consumer inherits it. Worth a sweep of the other `expr_is_place` gates on the `._N` spelling when this is picked up.
