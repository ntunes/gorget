- **🆕 [MED — A GATE THAT CANNOT SEE HALF OF WHAT IT ENABLES (Core #13). Found by R50 Track H while filing `t1410`.]** `assert_gg_sanitize_clean` builds through `gg build --sanitize`, which is **`-fsanitize=address,undefined`** — the helper's own doc-comment says so. Its verdict, however, is:

  ```rust
  let has_report = asan_stderr.contains("LeakSanitizer")
      || asan_stderr.contains("AddressSanitizer")
      || asan_stderr.contains("ERROR:")
      || asan_stderr.contains("SUMMARY:");
  assert!(run.status.success() && !has_report, ...);
  ```

  **UBSan's default mode is non-fatal**: it prints `<file>:<line>: runtime error: <what>` — lowercase `error:`, no `SUMMARY:`, no sanitizer name — and the process **exits 0**.

  **MEASURED, under the helper's exact `ASAN_OPTIONS=detect_leaks=1:abort_on_error=0:exitcode=99`**, on a program that commits signed-overflow UB:
  ```
  rc = 0
  LeakSanitizer:0   AddressSanitizer:0   ERROR::0   SUMMARY::0
  stderr: ...: runtime error: signed integer overflow: 3335314298909070151 * 31 cannot be represented in type 'long int'
  ```
  ⇒ **every predicate term misses, the exit status is success, and the assertion passes.** The UBSan half of the build is decorative.

  **THE BLAST RADIUS — 44 GATES** (regenerate with the CALL-SITE form, `grep -c '^\s*assert_gg_sanitize_clean(' tests/integration.rs` → **44**; the bare `grep -c "assert_gg_sanitize_clean("` returns **45** because it counts the function's own DEFINITION — a regenerator that includes its own subject is not a valid one, Core #15a). ⊕ **22 of the 44 are live and 22 are `#[ignore]`d**, so half the blind gates run on every `cargo test`. ⛔ **CORRECTED 2026-09-05 (R50 Track H's output-review): `assert_box_deref_asan_clean` is NOT in this class** — it builds with `-fsanitize=address` ONLY (`grep -n "fsanitize" tests/integration.rs`), so its 4 gates were never configured to produce a UBSan report at all. The original filing said 50 by adding them in. The gates are disproportionately the ones that matter — `assert_gg_sanitize_clean` is how a filed memory defect's `known_gaps` repro is pinned, and `known_gaps/` is an explicit `OUT` row in `tests/sanitize/CORPUS_MANIFEST.txt`, so **for those fixtures this helper is the only sanitizer instrument there is.**

  ⭐ **WHAT DISCRIMINATES IT FROM THE SWEEP, AND WHY THE TREE IS NOT CURRENTLY BURNING.** `scripts/sanitize_sweep.sh` classifies `runtime error:` as its own `UBSAN` class and gates it at `UBSAN_CEILING=0` (regenerate: `grep -n "UBSAN" scripts/sanitize_sweep.sh`), so the **top-level** corpus is genuinely protected. The hole is precisely the population the sweep does not walk. Two instruments, one of which can see the class and one of which cannot, and the blind one guards the filed defects.

  **THE FIX** is one line in each predicate — add `|| asan_stderr.contains("runtime error:")` — or, better and Core #6-shaped, set `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1` on the child so a UBSan finding becomes a nonzero exit and the existing `run.status.success()` term catches it without relying on string-scraping at all. **Verify the verifier: whichever is chosen, show it going RED on a deliberate signed-overflow variant before believing it** — the current predicate was never seen to fail on this class, which is how it survived.
