- **🆕📐 [MED — CAMPAIGN, owner-ratified 2026-09-05: D27's `^` MIGRATION EXTENDS EVERYWHERE, superseding the earlier `src`/`tests`/`lib`/`spec`-only scope]** Owner, verbatim: *"D27's ^ migration extends everywhere. That is the new move operator that will eventually free the `!` operator."*

  ⭐ **THE END STATE IS THE POINT: `^` is the move operator and `!` is to be FREED.** Migration is therefore
  not cosmetic — it is the prerequisite for retiring the prefix-`!` move spelling from the grammar.

  ⛔ **`!` DOES NOT GO AWAY ENTIRELY, AND A BLIND SED BREAKS THE LANGUAGE.** D26 ratified **suffix-`!` as the
  FALLIBLE marker** — `+! -! *! /! %!`, `<<! >>!`, `**!`, `f()!` (regenerate:
  `grep -n "FALLIBLE OPERATORS ADOPTED" docs/define-gorget/decisions.md`). ⇒ **the migration is
  position-sensitive: the NAME-SLOT prefix `!` becomes `^`; the SUFFIX `!` stays.**

  ⚠ **AND NOTHING CURRENTLY FLAGS THE OLD SPELLING.** The parser accepts both — regenerate:
  `grep -rn "Token::Bang) || self.check(&Token::Caret)" src/parser/` → 3 sites. So a `!`-move compiles clean
  today and the tree cannot drift back toward `^` on its own.

  **SCOPE, measured 2026-09-05 on the ONE unambiguous position** (`Type !name` — negation never follows a type
  name; regenerate:
  `grep -rhoE '[A-Za-z_][A-Za-z0-9_\]\[]* +![a-z_][a-z0-9_]* *[,)]' --include='*.gg' . | wc -l`):
  **236 declaration-position `!`-moves across 158 `.gg` files**, against **49** already on `^`.
  ⛔ **THAT IS A LOWER BOUND AND THE INSTRUMENT SAYS SO.** It cannot see CALL-site moves (`f(!x)`), which are
  ambiguous with negation (`if (!ok)`) to every regex. **The first deliverable is an instrument that can SEE
  the class — a lexer/parser-level counter, not a grep** (Core #13).

     (5 sites) and `docs/`, which the superseded scope excluded.
  3. **A `tests/lints.rs` ratchet (Core #6): env-gate → burn down → fatal**, both directions, so the count
     cannot regrow. ⚠ A tolerance band would green every step of its own drift.
  4. **Only then** consider rejecting prefix-`!` in the parser — an accept→reject surface change, so **Core #9
     binds all three lanes** and it owes conformance fixtures for the FINAL state.
