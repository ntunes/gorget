- **🆕📐 [LOW — ggdef SUBSET GAP, Core #9's "out-of-subset shapes get a note + a filed subset gap"; filed by R48 Track β as the fourth-lane half of its cross-lane pins. ⛔ FILED, NOT FIXED, on the owner's 2026-08-31 ruling that ggdef ABSTAINS on directives rather than being taught them.] ggdef cannot adjudicate ANY program that carries a `directive`.**
  - **MEASURED:** `ggdef run` on a program whose only unusual feature is a `directive` line returns `ggdef: elaboration error @ 0..0: item kind other is outside the phase-0 subset`. `Item::Directive` has **no arm anywhere in `elaborate`** — the failure is at the item dispatcher, not at a directive-specific check, so it is total: an ACCEPTED directive (`directive scheduler=pool`) is as unadjudicable as a rejected one.
  - **Consequence.** The eleven `spectests/run/` fixtures R48 β landed for the directive class all carry `adjudicator: production-v1` and say so inline. Their adjudicators are C, LLVM and the self-host; ggdef abstains, so `ggdef gen` cannot own their expect blocks and `GGDEF_MATCH_FLOOR` does not move for them.
  - **Why the abstention is cheap here, and where it is not.** A directive changes COMPILATION, not value semantics — `strip-asserts` removes asserts, `scheduler` picks a runtime — and ggdef adjudicates value semantics, so the directive class is nearly outside what an oracle for the definition would ever want to say. The one thing it COULD usefully adjudicate is the accept/reject verdict on the closed name/value sets, which is exactly what `directive_name_sets_agree_across_lanes` (tests/lints.rs) now enforces across the three implementation lanes plus two doc witnesses instead.
  - **If it is ever closed:** the minimum is an `Item::Directive` arm that validates the closed sets and is otherwise a no-op for the evaluator — the directives phase-0 can actually honour are none of them, so the arm would be "check and ignore". That is a small change, and it would let the eleven fixtures move to the generated adjudicator.
