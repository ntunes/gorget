- **[MED — the reference-grade instrument for the borrow-into-an-owning-destination class; filed 2026-09-04 by R49 Track N1, which shipped a text ratchet that is NOT sufficient] A BIR-validator borrow-provenance check.**
  - **WHAT EXISTS TODAY:** `tests/lints.rs::hof_borrowed_elem_ptr_sinks_are_cloning` — a source-text ratchet over `src/bir/lower.rs` pinning, as a keyed multiset, the SINK of every read of a borrowed collection-element pointer, plus the `gorget_array_adopt_hooks` call-site count and the context-struct brace-form count. It is bidirectional, fails CLOSED (a read whose sink it cannot identify is a violation, not an exemption), and was measured RED on **eleven compiling mutants**, including a new sibling expander that binds the scaffold under a name other than `ctx` and one that DESTRUCTURES it.
  - ⛔ **IT IS NOT SUFFICIENT, AND THE FIRST VERSION OF THIS ITEM SAID IT WAS.** That claim came from a mutant set built in the guard's own image. Two successive fresh reviewers invented probes the executor had not shown it, and **five were GREEN on compiling code that was exactly the class**: a sibling binding the scaffold under a name other than `ctx` (the read pattern was anchored on that name, which every existing expander happens to use); a literal destructure; a SEVENTH borrowed field, invisible because `BORROW_FIELDS` is a hand-written list; a destructure through a TYPE ALIAS; and an existing bare local. Three are closed. **Two are not, and are recorded below rather than papered over.** ⚡ **A guard measured only against probes its own author designed has been measured for consistency, not for coverage — and it took two independent adversarial passes to find that out, which is the argument for this item in one sentence.**
  - **WHAT IT STILL CANNOT DO, MEASURED — three shapes, each GREEN on code that compiles:**
    1. **A borrowed-pointer field whose NAME is outside the hardcoded six.** Closed 2026-09-04 by pinning the three context structs' DECLARED FIELD COUNTS, so a seventh cannot arrive without someone classifying it. ✅ now RED.
    2. ⛔ **A struct pattern through a TYPE ALIAS or renamed import** (`type FilterCtx = HofLoopCtx;` then `let FilterCtx { elem_ptr: b, .. }`). It spells no pinned name, so the brace census never sees a tenth site. **STILL OPEN.**
    3. ⛔ **A BARE LOCAL holding a locally-emitted `Inst::ElemPtr`** — it never spells a field at all. **NOT HYPOTHETICAL: `expand_reduce` already holds one (`first_ptr`, `src/bir/lower.rs:1520`), benign today only because it is `Load`-ed rather than pushed.** **STILL OPEN, and it is the sharpest of the three.**
  - ⊕ **CORRECTED 2026-09-04:** an earlier version of this line listed a value threaded out of a same-file HELPER'S RETURN as an open shape. **It is CAUGHT** — the guard fails closed on the helper's own `c.elem_ptr` read (measured: guard rc 101, `NO identifiable sink`). Do not carry that example forward.
  - **WHY 2 AND 3 WERE NOT CHASED WITH MORE TEXT PATTERNS (a decision, not an omission):** each would need another hand-written list — of alias names, of local bindings — i.e. another enumerator's own list with no independent witness, which is the exact defect that produced all five green mutants. The line was drawn where a DECLARATION could serve as the witness; past that point the honest answer is this item, not a longer regex.
  - **AND IT READS SINKS, NOT BEHAVIOUR:** a mutation that keeps the sink spelling and corrupts the arguments passes it (measured — the fixtures catch that one, 8 of 18 cells red). A validator carrying the provenance has none of these limits.
  - **WHY IT WAS NOT ATTEMPTED IN R49:** it needs a typed borrow tag the BIR does not carry — `Inst::CallExtern` and `Inst::CallClosure` both take a bare `Vec<ValueId>` on one shared enum, so there is nothing at the instruction level distinguishing "pointer into the source" from any other pointer. Adding the tag is the real work, and `src/bir/validate.rs` was another track's zone that round.
  - **WHY A TYPE DOES NOT SUBSTITUTE (measured, do not re-litigate):** a newtype over the pointer field hides it (`E0616`) but the defect walks straight through whatever accessor the BENIGN role needs, and the benign role is 26 of the 33 reads. A single `clone_into_owned()` as the only route to a consuming position DOUBLE-CLONES at four of the seven, because `gorget_map_put_cloned` calls `gorget_map_put` and THEN deep-clones in place (`src/backend/c/runtime/runtime_map.c`). The roles are three, not two.
  - **WHEN THIS LANDS:** the text ratchet becomes redundant and should be removed in the same change, not left as a second source of truth.
