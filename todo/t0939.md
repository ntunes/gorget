- **🆕🐛 [MED — Core #10 SILENT DROP: `gg check` ACCEPTS, the build dies at LINK] Calling a `Callable`-typed struct FIELD dies with `undefined reference`.**
  ```
  struct S:
      Callable[int(int)] f
  void main():
      S s = S((int x): x + 1)
      print(s.f(1))
  ```
  → `gg check` clean; link fails: ``undefined reference to `S__f'``. The lowering resolves `s.f(1)` as a METHOD call on `S` and emits a call to the method symbol `S__f`, which no pass ever defines, rather than an indirect call through the field's closure value.
  **Core #10 (lower-or-reject):** every lowering arm either lowers the construct or emits a check-time rejection; resolving to a symbol nobody emits is the silent-drop shape.
  ⚠ **FAMILY, and what DISCRIMINATES this row:** `t0025` is the same OUTCOME class (`gg check` accepts, symbol vanishes, build dies at link) but a different mechanism — there the trigger is a mis-spelled `equip Pt(Shifter):` header, here it is field-call-vs-method-call resolution on a `Callable` field. Neither fix implies the other. The family also includes `t0936`/`t0937`/`t0927`, all *"the value form of `Callable` carries lossy type metadata"*.
