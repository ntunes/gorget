  **MEASURED at HEAD**, `gg run` vs the self-host lane:
  | probe | Rust `gg` | self-host |

  | `grid.map([z * 2 for z in it])` | `2 4 6 8` | **rejected** |

  | `grid.map([z for z in it if z > 2])` | runs correctly | **rejected** |
  The self-host's message is `error: cannot lower a call whose callee is a EListComp (in fn 'main')`.
  **MECHANISM.** `tests/fixtures/self_host_lowerer/lower_closures.gg::expr_has_it` decides whether a HOF argument IS an implicit-`it` body. It has no `EListComp` / `ESetComp` / `EDictComp` arm, so it answers `false`, and `extract_hof_closure` then treats the comprehension as a CALLABLE and synthesizes `([z * 2 for z in it])(__hofp0)`. The `ECall` callee dispatcher refuses that (R48 Track U's lower-or-reject arm), which is why the failure is LOUD and not a miscompile — Core #10 is doing its job. The defect is upstream of it.
  **THE FIX IS PROBABLY THREE ARMS**, and it is cheap in a way the old excuse hid: these variants carry NO statements. `tests/fixtures/self_host_lowerer/ast.gg` gives `EListComp(Box[SpannedExpr], String, Box[SpannedExpr], Option[Box[SpannedExpr]])`, `ESetComp` the same, `EDictComp` one field wider — all `Box[SpannedExpr]` / `Option[Box[SpannedExpr]]`. So `expr_has_it` can walk them with the machinery it already has; there is no `Stmt` walk to write. ⚠ Walk the ELEMENT expression, the SOURCE expression and the optional FILTER; the loop VARIABLE is a binding, and an `it` that appears only as that variable's name is not this closure's `it`.
  ⚠ **WHY IT WAS NOT FIXED IN THE ROUND THAT FOUND IT:** the finding arrived as a correction to a false COMMENT, and the pass that corrected it was comment-only. Adding three arms is a compiler change and owes a bootstrap + parity re-run; it was recorded rather than smuggled into a documentation fix.
  ⚠ **THE RECORD THIS REPLACES WAS FALSE TWICE OVER.** `expr_has_it`'s header claimed the comprehension-bodied form "ICEs" on the reference (it does not — it runs) and grouped it with `EBlock`/`EDo` as "needs a `Stmt` walk" (it does not — there are no statements in it). Both claims are now corrected at the site, which is how this item was found: the review checked each named omission against the reference rather than believing the list.
