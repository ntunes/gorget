- **🔧 [LOW — THE PHANTOM-STEM CLASS WAS FIXED WITHOUT A GUARD, AND THE GUARD IS NOT FREE. Filed 2026-09-09 by the `[[t1631]]` trap fix.]**

  `collect()` in `scripts/known_gaps_census.sh` now drops a `known_gaps/<stem>` match whose next character is a glob or brace metacharacter, which retired the two phantoms that existed (`rust_gg_bug_` from `known_gaps/rust_gg_bug_*`, `sh_comprehension_` from a brace list). Regenerate the absence:

  ```
  scripts/known_gaps_census.sh --list | tail -n +2 | cut -f3 | tr ',' '\n' | sort -u |
    while read -r s; do
      [ -e "tests/fixtures/known_gaps/$s.gg" ] || [ -d "tests/fixtures/known_gaps/$s" ] ||
        echo "PHANTOM: $s"; done
  ```

  ⛔ **BUT THAT COMMAND IS NOT WIRED, so the class is retired by a regex and not by a guard (Core #6).** The obvious wiring — make the census fail when a roster stem has no file — is NOT safe as written, and the reason is already recorded one file away: `tests/lints.rs`'s registry-integrity check documents that flagging `known_gaps/` mentions in COMMENTS produced six false failures, because a doc comment saying *"graduated from `known_gaps/X.gg`"* is CORRECT history and X is *supposed* to be gone. The census reads comments on purpose (an `#[ignore]` reason names the fixture as often as the body does), so it inherits that false-positive class in full.

  **INTENDED:** settle the discriminator before wiring anything. The candidate is that the census's collector is already narrowed to `#[ignore]`d tests, where a "graduated from" note is self-contradictory — so the false-positive class may be empty for THIS collector even though it is real for the lint's. Measure that claim over the current tree before making it fatal; a gate that reddens on a correct history note is worse than the phantoms it retires.

  ⚠ **AND THE STRONGER SHAPE IS A WITNESS, NOT A FLOOR.** `tests/lints.rs`'s registry-integrity check and this census are two independently-written extractors of `known_gaps/` references over the same tree, and nothing compares them. Comparing the two reference sets would name whichever extractor is broken instead of reporting a count nobody can adjudicate — the same conversion `[[t1631]]` applies to the parity reader.
