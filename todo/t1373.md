- **🆕🚨 [HIGH — SILENT WRONG OUTPUT ON THE DEFAULT BACKEND FROM `struct { Box[int] }`, THE PLAINEST SHAPE THERE IS. Found 2026-09-05 by R50 Track A2's scout; pre-existing on pristine HEAD, verified by revert + rebuild.]**

  ```gorget
  struct S:
      Box[int] b
  # print(s.b.get())  ->  C prints 187650890461856   ·   LLVM prints 9
  ```

  **Read off the emitted C, not inferred:**
  ```c
  __v8  = &s.b;                                   /* the FIELD'S ADDRESS */
  __v10 = Box__Box__int64_t__get(__v8);           /* handed to a BY-VALUE __get */
  /* ...and the sibling call one line down DOES deref: */
  __v12 = Box__int64_t__get(*(Box__int64_t*)__v11);
  ```

  **Two call-emit shapes for the same operation, one of them deref-correct.** rc 0 both ways, `gg check` clean, no diagnostic.

  ⛔⛔ **THIS INVERTS A FILED MEASUREMENT, AND THAT IS THE POINT.** `todo/t0685` records *"`Box[int].get()` C ✓ LLVM ✓"* — **true for a LOCAL receiver.** On a **FIELD** receiver the same payload type is **C ✗ LLVM ✓**. ⇒ **the axis `t0685` enumerates is the PAYLOAD TYPE; the axis that actually discriminates is the RECEIVER PLACE.** A fixture set sampling only local receivers is an anecdote on the axis that matters (Core #12).

  ⚠ **DISCRIMINATE — this is not `t0685` and not `t0684`.** Those are about which payload types survive; this is about which *place* the receiver is read from. **Do not merge it into either; a fix aimed at payload types leaves it alive.**

  **INTENDED:** `print(s.b.get())` prints `9` on C and LLVM. Owes a `known_gaps` repro asserting the LLVM answer.
