- **[LOW — self-host, Rust; T-B residual, Core #8] name-collision on an UNRESOLVABLE projection stays read-only (both the SCAN and the GATE tail).** The user→builtin order closes the name-collision for a RESOLVABLE receiver (named, or a projection whose root local + field/element types resolve — verified: `v[i].get()` / `s.v[i].get()` materialize). Two unresolvable tails remain, both DEGRADE-TO-BASE (write-through, no bomb): (a) SCAN — in `mutinf_scan_expr`, a self-projection whose type resolves to −1 at scan time (`self.field.get()` where `self.field`→−1) falls to `builtin(get)=Some(false)`; (b) GATE — in `mutinf_recv_type_name`, a projected receiver whose base is NOT a named-root chain (e.g. an element of a METHOD-returned collection `f().v[0].get()`, or a root local absent from `ctx.locals`) resolves to "" → the guard returns false. Fix = a fuller projection-type oracle (or route the scan/gate through the typechecker's per-link `expr_link_types` where present), re-validating RSS since a conservative "unresolved ⇒ mutating" fallback here is the re-bomb the whole pass avoids.
