- **🧹 [MED — MaterializePlan campaign follow-up, filed 2026-07-28 (owner-suggested during Track I close)] Extend auto-move-at-last-use to POST-MATERIALIZE parameters.** Today docs/devbook/11-copy-on-write.md excludes parameters from last-use move ("not from a parameter — those bind borrows") because the parameter slot is a borrow view of caller-owned data. AFTER a §3.1 materialize fires on a bare-param root (`p` becomes locally Owned), the slot IS owned; the analysis doesn't pick that up and treats the post-materialize `p` as a borrow through end-of-frame. Consequence: in the recursive-materialize pathology (branch-per-frame, N=12→~250K clones), the FINAL bare-forwarded self-call in each frame would be a move-eligible last-use, saving one clone per node (half-win for branching; full-win for the terminal frame of linear). MaterializePlan campaign fit: read Phase-D `LocalOwnership` post-materialize; classify per-arg as OWN-post-mat + last-use → emit MoveWithoutOperator elision + IR `MoveZero`. Requires callee-ABI extension for bare-param callee optionally receives owned-in, or call-mode specialization at the call site. Owner-suggested during Track I close (2026-07-28); Track I chose to WARN not FIX, so this is the compiler-side complement (a fn the user writes to be `&`-forwarding runs the whole gauntlet; a fn the user leaves bare-recursive still gets fewer clones under this optimization). Measurement floor: with the compiler-side auto-move, the recursive linear case at large N should drop dramatically (one clone per final frame).
