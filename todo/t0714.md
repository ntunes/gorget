  **⚠ Two measurement traps, both of which produced a wrong answer first.** (1) **The byte ceiling is not coverage.** At a few dozen free bytes it catches EVERY clause-length insertion in the file, headings included, which reads as total coverage and evaporates the moment the file shrinks; the sweep excludes it from the verdict and reports it in its own column. (2) **A two-anchor probe cannot separate the factors.** Insert-here-vs-there over two anchors produced first "capitalisation is the discriminator" and then "pinned-vs-unpinned is", and both anchors were in fact UNPINNED positions differing in host-run length. Measure per class, over the whole file, or do not quote a rate.

  **The ratchet's sensitivity is its own SLACK**, exactly like the byte ceiling's — and this was measured the hard way, not reasoned about. Adding ONE probe split a run and took the `>= 100` count one below its constant; the very next cross-check run went from 10/10 to **0/10** on band B, with every lint in the suite still green. One unit of slack switched a whole band off. `agents_md_unpinned_prose_ratchet` now asserts the constants EQUAL the measurement, so shrinking unpinned prose without following the constants down is a red with the two values to set printed in the message; prose saying "re-ratchet after a compaction" had been in the tree for exactly one pass and did not stop it (Core #6).

  **DELETION has one guard and it reaches exactly as far as the probes do.** `agents_md_rule_inventory_is_pinned` fires when an inventoried clause stops being stated; everything else is a ceiling that deletion can only satisfy. An earlier pass demonstrated it by removing every uncovered run ≥ 60 chars — about 41% of the file at the time — with the whole suite green; that is a historical demonstration, not a live figure, and the live one is whatever the second command prints now. Nor does any lint check that a compaction's evidence actually LANDED in devbook/29-30.

  **Burn-down, in the order that pays.** (a) Add probes for the uncovered runs ≥ 100 chars until that count reaches 0 — the no-slack assert forces `AGENTS_MD_MAX_RUNS_OVER_100` down with it, so the burn-down cannot silently stall — and at 0 the ratchet subsumes the sentence census and band C disappears, which is the largest hole. (b) Then the 60-99 band, which is real obligations too. (c) The `agents_md_every_clause_is_classified` *contains-a-probe* test stays the weak link either way: a chunk passes if it contains ANY key, so text added beside a probe inside the same sentence is unguarded by construction. Fixing that means a stronger predicate than containment, and it is the only part of this item that needs a design call rather than a burn-down.
