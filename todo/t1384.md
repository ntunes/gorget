- **🆕🔬 [MED — WHAT TOPIC 30 DOES NOT COVER, WRITTEN DOWN SO THE FAMILY IS NOT DECLARED CLOSED. Filed BY the track that built the corpus, not against it.]** `tests/fixtures/robustness_map/` topic 30 (`30 view invalidation (9 of N sources, mirror 2/11)`, 820 cells) is a **SELECTION on two of its four axes**, and it LOOKS like an enumeration of "value semantics under mutation". The 2026-07-06 sweep of this same family found four holes and vanished leaving no record of what it had never run; this item is the record.

  **(1) FOUR VIEW-BINDING SHAPES ARE UNPROBED, and no widening of SITE or PAYLOAD reaches them.** The SOURCE axis's witness is `BorrowOrigin` x `CollectionId` — what the compiler can RECORD, not what a user can WRITE. Missing:
  - **closure captures** — a view captured by a closure and read after the source is mutated outside it. (Distinct from `t0026`, which is a captured collection-ELEMENT borrow returning an address; here the capture is of an already-bound view and the question is severance, not materialization.)
  - **trait-default receivers** — a view bound inside a trait DEFAULT method body from `self`.
  - **comprehension binds** — a view bound by a comprehension's binder.
  - **generic-`equip` receivers** — a view bound through an `equip` block on a generic type, where the receiver's concrete provenance is only known after monomorphization.

  **(1b) THE PAYLOAD AXIS IS A SELECTION ON THE PAIR `(CopySemantics, DropStrategy)`, NOT ON `DropStrategy` ALONE — AND IT COVERS ONE OF SIX.** The corpus's first disclosure claimed the seven payloads "cover all four values" of `DropStrategy`; that was **false**, and enumerating over four values was itself the defect, because `None` and `Trivial` each span BOTH copy semantics and the halves get OPPOSITE dispositions. The independent witness is the "Valid combinations" table in `src/ir/types.rs` (`awk '/# Valid combinations/,/Suspicious/' src/ir/types.rs`), which enumerates SIX legal pairs. All seven payloads are one of them.
  - **`(Trivial, None)`** — primitives, plain value structs. **NO SUBJECT.** A Copy bind DUPLICATES the storage rather than sharing it, so the two places never overlap and the rule has nothing to say (`docs/language-design.md` 3.5, *"overlap is about storage, not spelling"*). Widening cannot manufacture a subject.
  - **`(Trivial, Trivial(fn))`** — the refcount handles `Shared` / `Weak` / `Channel`. **NOT COVERED, and the rule is deliberately INVERTED for them** — a handle bind shares the referent BY DESIGN, so *"every other place reads the value it had before"* is the wrong expectation rather than an unmeasured one. ⛔ **And it is worse than uncovered at HEAD: `Shared[int] b = a` — a bare bind, no call — SEGVs on both backends and returns garbage at rc 0 when only the second name is read. Filed as [[t1388]], found while writing this row.** A cell here would be measuring a crash, not value semantics.
  - **`(Resource, None)`** — the ownership-tracked handles `Thread` / `Process`. ⚠ **NOT COVERED, AND THIS ROW IS GENUINELY OPEN RATHER THAN DISPOSITIONED — it is the deferral this item exists to carry.** Unlike the first row a bind does NOT duplicate storage (measured: `Process c = proc` checks clean, rc 0), so a second live place demonstrably exists — but the value is a handle with no observable payload for the rule to read. **Whether that makes it a no-subject cell or an uncovered one is NOT settled**, and an enumeration with only "covered" and "no subject" could not even express the question. Settle it, or widen to it, when this item is worked.
  - **`(Resource, Trivial(fn))`** — `String`, `Vector`, `Dict`, `Set`, `Guard`. **COVERED.** This is the entire payload axis of the corpus.
  - **`(Resource, Recursive)`** — structs holding droppable fields. Present only on the SOURCE side (the `Store` / `Inner` / `Outer` wrappers), never as the aliased payload. ⭐ **A REAL WIDENING TARGET**: measured, `Store t = s` for `struct Store: Vector[int] f` checks clean, so a struct-valued payload is constructible. ⚠ **But the reachable region is narrower than "any struct with droppable fields":** the reject reads a `Drop`-taint flag seeded from `equip T with Drop` and propagated by a **transitive fixpoint over the field graph**, so a `Recursive` struct that merely *contains* a custom-`Drop` type anywhere below it is rejected too. Widen to structs whose field graph is `Drop`-free; the measured example is inside that region.
  - **`(Resource, Custom(fn))`** — a user `Drop` impl. ⛔ **A CELL WITH NO SUBJECT THAT NO WIDENING REACHES.** Both assignment sites (`grep -n "DropStrategy::Custom(format!" src/ir/lowering/mod.rs` → exactly 2; the broader grep returns a third hit that is a READ, not an assignment) are gated on a `Drop` impl, and **the line ABOVE each** sets `CopySemantics::Resource`. A resource is single-owner, so the bare view bind the whole corpus is built on is rejected: `error[E_MoveWithoutOperator]: cannot copy 'v': 'v' is a resource (a type with a custom 'Drop' is single-owner)`. With no second live place, *"every other place reads the value it had before"* has no other place. **That is a boundary of the RULE, not a hole in the corpus.**

  ⚠ **MEASURED, NOT DEDUCED — and the deduction is wrong.** The natural inference, that the upgrade scan setting `Resource` alongside `Recursive` rejects those binds too, is FALSE: `Store t = s` is accepted. The rejection is specific to a CUSTOM `Drop`. Anyone widening this axis by reading the source instead of running it will get the `Recursive` row backwards.

  **(2) THE MIRROR DIRECTION COVERS 2 OF 11 SITES.** Forward (mutate the source place, read the view) is full-width, 9 x 11 x 7 = 693. The mirror (mutate the view, read the source place and the view) ships `straight` x `while` only, 9 x 2 x 7 = 126. The justification is measured rather than assumed — SITE is SATURATED at HEAD in BOTH directions (`straight` correct, each of the ten other sites broken identically, per source), so the 2-site slice loses nothing TODAY. ⚠ **It stops being true the moment a PARTIAL fix lands** — one that repairs `if` and not `match` — which is the single thing the site axis exists to catch. **Widen the mirror to full width in the same round as the first partial fix, not after it.**

  **WHY THE MIRROR IS NOT A SYMMETRIC RE-RUN, measured:** the two directions differ on exactly one cell of the SOURCE axis — `getvia` is broken on 1 of 7 payloads forward (`string`) and on 7 of 7 in the mirror — so the mirror finds six payload-cells the forward direction structurally cannot. All eight other sources behave identically. `t0750` names both directions as one filed defect and records that whether they are ONE mechanism or two is **open**.

  ⊕ **An eighth PAYLOAD, `Vector[Option[String]]`, is deliberately absent:** all 99 of its cells fail to BUILD on both value lanes today (`t0002`), so they would measure nothing. Re-add it in the round that closes `t0002`.

  ⛔ **DO NOT WIDEN THE FORWARD OBSERVATION to read both places.** Measured over all 693 forward cells: zero cells where the source place reads its pre-mutation value, and view-only vs both-observed verdicts agree everywhere. Widening changes nothing except invalidating the seeded baseline.

  **HOW TO WIDEN:** the axes are three tables at the top of `scripts/gen_value_semantics_cells.py`; add a `source_parts` arm, regenerate, and seed the new rows with `--lanes all --accept --seed-new --topic`. The generator refuses to overwrite a committed expectation, so a widening cannot silently move an existing baseline.
