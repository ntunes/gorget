- **[HIGH — the self-host's `int32 → void*` emit is not a portability nuisance, it is the MECHANISM behind run-to-run GARBAGE output, and the parity harness suppresses the one diagnostic that names it] Four corpus rows print a DIFFERENT wrong answer on every run because the self-host stores an `int32_t` into a `void*` slot.** **Family — THREE existing items, and the closest one is easy to miss.** `todo/t0639`'s second bullet files the IDENTICAL mechanism and is arguably the nearest relative: *"int↔pointer untyped-local stores — the self-host emits `void* local = (int32_t)0` for some unresolved-type locals … a local whose type the lowerer couldn't resolve defaults to `void*` + an int-0 init"*, and it already names `-Wno-int-conversion`. `todo/t0473` files the same emit shape as a macOS/clang-21 PORTABILITY problem ("Self-host emits `int32 → void*` assignments that Apple clang rejects"). `todo/t0164`'s parity-backlog bullet calls two of these rows "memory-corruption-smell WRONGs". ⚠ Naming all three is not bookkeeping: `todo/t0641`'s own closing bullet warns that *"a member hiding in an unrelated item's side-bullet is exactly the indexing failure that let `t0038` be re-discovered twice"* — and `t0639`'s bullet is exactly such a side-bullet. **What DISCRIMINATES this filing: the smell is now MEASURED as nondeterminism, on Linux/gcc, with two more members, and with the reason the gate cannot see it.**
  - **Measured** by `self_host_runtime_diff`'s new mismatch attribution at HEAD `176909d8` (each row re-run 7×, self-host lane): `closure_fstring_capture`, `cow_lazy_w3c_arg_temp`, `ecs_advanced`, `iter_map_after_filter` — **7 distinct outputs over 7 runs, each**. The variants are raw pointer values (`187650750784464`) and garbage bytes (`a = \xef\xbf\xbd\xe5\xac\xaa` where the oracle prints `a = hello`), i.e. an address that moves with ASLR, not a stable wrong answer. `ecs_advanced` and `iter_map_after_filter` are NOT named in `t0164`.
  - **Root cause visible in one command.** Emit the self-host C and compile it WITHOUT `-w`: `cc -O0 -c -o /dev/null <emit>.c -Wint-conversion` reports `assignment to 'void *' from 'int32_t' makes pointer from integer without a cast`. Counts at HEAD: `cow_lazy_w3c_arg_temp` 4, `closure_fstring_capture` 10, `ecs_advanced` 18, `iter_map_after_filter` 18.
  - ⚠ **The gate is structurally blind to it**: `self_host_emit_cc_run` compiles with `cc -O0 -w` (`tests/integration.rs`), and `-w` suppresses exactly this warning. So a self-host emit that fabricates a pointer from an integer builds silently and is only ever seen as a stdout diff.
  - ⚠ **And it is endemic, which is the Core #8 part.** `shared_with_check_then_act` carries **25** such warnings and MATCHes. So the class is pervasive and merely *benign by luck* in most rows — "it happens to work on gcc/x86_64" is not a property, and the four rows above are what it looks like when the luck runs out. Do not treat the warning count as a defect predictor; treat the CONSTRUCT as the defect.
  - **Fix direction:** the emit must carry the slot's real type rather than relying on implicit int↔pointer conversion — a layering question at the LIR→C boundary (which typed field decides `void*` vs a scalar for a local), not a per-fixture patch. **A guard is available and cheap but must be RATCHETED, not switched on**: adding `-Wint-conversion` (eventually `-Werror=int-conversion`) to the self-host cc step would red most of the corpus today, so it needs a per-fixture warning-count ceiling that only shrinks, in the shape `tests/lints.rs` already uses for the sanitize allowlists. ⚠ A corpus-wide census of the warning count is OWED and was not run here (it is a full emit+cc sweep, ~2.5 min warm); the six counts above are a sample, not the set.
