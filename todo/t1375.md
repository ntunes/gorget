- **🆕🚨 [HIGH — A SECOND, INDEPENDENT DEFECT AT THE NEWTYPE CONSTRUCTOR, AND IT IS WHY FIXING ITS SIBLING ALONE DOES NOT WORK. Found 2026-09-05 by R50 Track A2's brief-review pass 1, which read the emitted C rather than reasoning about it.]**

  Under Track A2's registration fix, `newtype NX(Box[int])` emits **two** defects, not one:

  ```c
  __v2  = &__s2;   __v3 = (__gg_NX){ ._0 = __v2 };   /* t1374: slot address into a by-value field */
  __v8  = __s2;    __gorget_box_free_int64_t(__v8);  /* THIS ITEM: the SOURCE temp is dropped -- no MoveZero */
  __v10 = &__s1;   NX__drop(__v10);                  /* ...and NX__drop frees _0 again */
  ```

  ⛔⛔ **FIXING `t1374` ALONE STILL DOUBLE-FREES, BY CONSTRUCTION.** Store the payload by value (`._0 = __s2`) and `__s2` and `__s1._0` hold **the same pointer**, and **both are freed**. `t1374` as filed describes only the address store, so *"gate the registration fix behind `t1374`"* gives **false confidence**.

  ⭐ **THE RULE IS EXPLICIT AND THE MOVE IS OWED.** `AGENTS.md`'s *Ownership at Consuming Positions* names **constructors** as a consuming position, and lists *"expression temp (last-use + owning by construction)"* as one of the three move-eligible shapes. **The source here is exactly that shape.** ⇒ **Core #3: the ownership tag is missing at the producer**, and the read-side symptom is a double free.

  ⚠ **DISCRIMINATOR vs `t1374`:** that item is about **WHAT is stored** (an address where a value belongs); this is about **WHAT HAPPENS TO THE SOURCE** afterwards (dropped instead of moved-from). They are independent — either alone still double-frees — and **both must land for `newtype N(Box[T])` to be sound.**

  **INTENDED:** `newtype NX(Box[int])` builds, runs and is ASan-clean on C and LLVM.
