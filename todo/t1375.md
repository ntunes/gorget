- **🆕🚨 [HIGH — A SECOND, INDEPENDENT DEFECT AT THE NEWTYPE CONSTRUCTOR, AND IT IS WHY FIXING ITS SIBLING ALONE DOES NOT WORK. Found 2026-09-05 by R50 Track A2's brief-review pass 1, which read the emitted C rather than reasoning about it.]**

  Under Track A2's registration fix, `newtype NX(Box[int])` emits **two** defects, not one:

  ```c
  __v2  = &__s2;   __v3 = (__gg_NX){ ._0 = __v2 };   /* t1374: slot address into a by-value field */
  __v8  = __s2;    __gorget_box_free_int64_t(__v8);  /* THIS ITEM: the SOURCE temp is dropped -- no MoveZero */
  __v10 = &__s1;   NX__drop(__v10);                  /* ...and NX__drop frees _0 again */
  ```

  ⛔⛔ **FIXING `t1374` ALONE STILL DOUBLE-FREES, BY CONSTRUCTION.** Store the payload by value (`._0 = __s2`) and `__s2` and `__s1._0` hold **the same pointer**, and **both are freed**. `t1374` as filed describes only the address store, so *"gate the registration fix behind `t1374`"* gives **false confidence**.

  ⭐ **THE RULE IS EXPLICIT AND THE MOVE IS OWED.** `AGENTS.md`'s *Ownership at Consuming Positions* names **constructors** as a consuming position, and lists *"expression temp (last-use + owning by construction)"* as one of the three move-eligible shapes. **The source here is exactly that shape.** ⇒ **Core #3: the ownership tag is missing at the producer**, and the read-side symptom is a double free.

  ⚠ **DISCRIMINATOR vs `t1374`:** that item is about **WHAT is stored** (an address where a value belongs); this is about **WHAT HAPPENS TO THE SOURCE** afterwards (dropped instead of moved-from). They are independent — either alone still double-frees — and **both must land for `newtype N(Box[T])` to be sound.**

  **INTENDED:** `newtype NX(Box[int])` builds, runs and is ASan-clean on C and LLVM.

  ---
  ## ⛔⛔ ROOT CAUSE CORRECTED 2026-09-05 (R50 Track A2's brief-review pass 2 — it traced one layer UP)

  **This item was filed as an ownership defect (*"the move is owed and absent"*, `areas = ["cow"]`). THAT SENDS THE EXECUTOR TO THE WRONG LAYER.** The GIR settles it:

  ```
  newtype:  _3 = call @NX(copy _2)              <- a CALL. no move_zero. and: drop_if_alive _2
  struct:   _3 = struct_init S { copy _2 }
            move_zero _2                         <- the move IS emitted
  enum:     _3 = enum_init E::V { copy _2 }      <- source correctly not dropped
  ```

  ⭐ **THE OWNERSHIP MACHINERY IS CORRECT.** `move_zero_consumed_args` fires after `StructInit`/`EnumInit`, and **the struct sibling proves it works.** **The newtype path simply never reaches it** — it stays a `Call` to a synthesized `extern fn`.

  ⛔⛔ **AND BOTH BACKENDS RE-DERIVE THE CONSTRUCTION BY NAME-MATCHING** — `is_newtype_ctor` (C) and `newtype_sid` (LLVM), both spelled `s.name == *name && s.fields.len() == 1`. **That is Core #2 / Layering rule 2 — *"no name-matching to decide MEANING"* — sitting directly under the defect.**

  ⇒ ⭐ **`t1374` IS THE SAME ROOT CAUSE, NOT A SIBLING.** The C arm writes `._0 = {arg}` with **no pointer/value adaptation**; the LLVM arm **has one** — **and that asymmetry IS the measured C/LLVM divergence.**

  ⇒ ⛔ **THE FIX IS UPSTREAM AND SINGULAR: lower newtype construction to `StructInit` through the SAME path the struct literal uses — which also DELETES BOTH backend name-matching arms.** Splitting `t1374` and `t1375` across two tracks would split **one write-site fix** across two worktrees.

  ⊕ **SIX-Q #2 — THE EXISTING VALIDATOR IS STRUCTURALLY BLIND:** `Call` → `fn_param_abis.get("NX")` → `None => false, // unknown ABI -- skip`. Measured: `GG_VALIDATE_CONSUME_SITES` emits **nothing** for a program that double-frees.

  ⊕ **Core #4's SIBLING SET IS THE TWO BACKEND NAME-MATCHING ARMS — not other consuming positions.** Struct literals and enum variants were **measured correct on both backends, PRE and POST**. **Newtype is the ONLY constructor form that never becomes an init instruction.**
