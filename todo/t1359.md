- **🆕🔥 [CRITICAL -- DOUBLE-FREE REACHABLE FROM ORDINARY SAFE SYNTAX, `gg check` clean; found 2026-09-05 by the R50 CoW design scout while measuring the `SetIter` clone path]** `gorget_set_clone` propagates the *destructor* for resource-typed keys but neither of the two *copy* hooks.

  **Regenerate the field drift** (Core #15(a) -- this is the grep, not a line number):

  ```bash
  awk '/static inline GorgetMap gorget_map_clone\(/,/^}/' src/backend/c/runtime/runtime_map.c \
    | grep -oE 'dst\.[a-z_]+ = src->' | sort -u > /tmp/mapclone.txt
  awk '/static inline GorgetSet gorget_set_clone\(/,/^}/' src/backend/c/runtime/runtime_set.c \
    | grep -oE 'dst\.[a-z_]+ = src->' | sort -u > /tmp/setclone.txt
  comm -23 /tmp/mapclone.txt /tmp/setclone.txt
  ```

  Today that prints six rows. **Four are legitimate** -- a Set has no values, and `gorget_set_clone`
  sets `dst.val_size = 0` explicitly, so the `val_*` omissions are by design. **Two are the defect:**
  `key_clone` and `key_materialize`.

  **Why that is a double-free and not merely a missing optimisation.** The clone keeps `key_drop`,
  so the copy genuinely owns its keys and will free them. It loses `key_clone`, so when the *copy*
  is itself cloned the keys are `memcpy`'d rather than deep-copied, and the two sets now hold the
  same pointers with a live destructor each.

  **The independent witness for the field enumeration is the struct declaration, not either
  clone function's own list** (Readiness row 2 / SIX-QUESTIONS #3 -- a clone function cannot show
  you the field it forgot):

  ```bash
  sed -n '/^typedef struct {/,/} GorgetMap;/p' src/backend/c/runtime/runtime_preamble.c \
    | grep -nE '__gorget_drop_fn'
  ```

  **This is Core #4 sibling-site drift in the runtime**, so the fix is the class, not the line:
  the two clone routines are one enumerated set with a shared field list, and nothing today forces
  the next field added to `GorgetMap` through both. **Ship the arm-count-style guard with the fix** --
  a lint that diffs the two field lists and fails on any asymmetry not on a declared `val_*`
  allowlist, per Core #6.

  **Fixture (Core #11/#12): must be RED-verified against the pre-fix compiler**, must use a
  *heap-forced* key type (`Set[String]`, not `Set[int]` -- a trivial key has no `key_drop` and the
  bug cannot fire), and must exercise the second clone, since one clone alone does not double-free.
  ASan adjudicates this, **not ggdef** -- Core #13: ggdef is structurally blind to memory
  invalidation.
