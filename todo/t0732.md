- **[MED — `shared(atomic) int` LEAKS 8 BYTES ON BOTH BACKENDS, and no gate in this tree can see it. Adjudicated 2026-08-29 by R47 Track C, which was asked to confirm a suspected LLVM lane divergence and found something different underneath.]**
  - **MEASURED AT HEAD, deterministically, both lanes.** `gg build --sanitize [--backend=llvm]` on the two-task repro, run under `ASAN_OPTIONS=detect_leaks=1:exitcode=99`: **10/10 runs exit 99 on each lane**, reporting
    ```
    Direct leak of 8 byte(s) in 1 object(s) allocated from:
      #0 __interceptor_malloc   #1 gorget_atomic_int_new   #2 main
    ```
    Repro: `tests/fixtures/known_gaps/shared_atomic_int_never_dropped_leak.gg`, wired `#[ignore]`d as `shared_atomic_int_is_dropped` (`tests/integration.rs`).
  - **THE SHIPPED FIXTURE ALREADY EXERCISES IT.** `tests/fixtures/security/attack_87_atomic_counter_race.gg` leaks the same 8 bytes. Nothing reports it, for three independent reasons: it is wired as `security_safe`, which runs under `ASAN_OPTS_NO_LEAK` = `detect_leaks=0`; `scripts/sanitize_sweep.sh` does run `detect_leaks=1` but enumerates `find tests/fixtures -maxdepth 1`, so it never descends into `tests/fixtures/security/` (t0731); and the robustness map's `asan` lane covers a different corpus. **A leak sitting inside a memory-safety fixture, inside the security suite, invisible to all of it.**
  - **⚠ THE "LANE DIVERGENCE" IT WAS FILED AS DOES NOT EXIST — do not go hunting one.** Measured on `attack_87`'s own 4-task shape, C reports 10/10 and LLVM reports 0/10, which is what the R47 scout saw and reasonably read as an LLVM divergence. It is a measurement artifact. Reduced to two tasks, **both** lanes report 10/10; and an extern-`malloc` leak injected into the 4-task LLVM binary IS reported, so LeakSanitizer is present and looking on that lane. The 4-task silence is a stop-the-world REACHABILITY effect under contention — a live worker stack or pool structure still referencing the block — not different codegen. **Keep the task count low in any repro, or the instrument stops reporting the thing being measured.**
  - **PROCESS NOTE worth keeping.** Two review passes reasoned about this row from the fixture's wiring alone and reached opposite conclusions ("cannot redden the gate", therefore "not a defect"). The first was right and the second did not follow. One 10-run execution on each lane settled it, and turned a suspected lane divergence into a real cross-lane leak.
  - **ON FIXING IT.** Graduate the repro to a live `security_safe_no_leak` fixture, and consider re-wiring `attack_87_atomic_counter_race` as `security_safe_no_leak` at the same time — it is a `shared(atomic)` fixture whose bug class is stdout-invisible, which is exactly that helper's stated subject.
