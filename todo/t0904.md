- **🆕🧹 [MED — layering; no user-visible defect, `AGENTS.md` § No name matching violation; filed 2026-08-31 by R48 Track D2] The Shared / Weak / Mutex method-dispatch blocks in `src/ir/lowering/exprs/methods.rs` still route by name prefix, and only the CONVENTION half of that was retired.** R48 Track D2 moved the calling-convention decision out of those blocks and onto the typed channel that already carried it — the receiver is coerced once, upstream of all dispatch, from `SelfConvention::ByValue` (`deref_by_value_handle_receiver`), and the clone convention from `is_refcount_clone_type`. The blocks no longer DECIDE anything semantic about how `self` is passed. What they still do is select a method surface by `stn.starts_with("Shared__")` / `"Weak__"` / `"Mutex__"`.
- **WHY THEY COULD NOT SIMPLY BE DELETED, measured 2026-08-31:** each block carries type-registration and ownership side effects the generic `BuiltinTypeProtocol` path does not reproduce. `Shared.clone`/`downgrade` call `ctx.set_owned_fresh` (without it a consuming position re-clones the fresh handle and the strong count is one too high); `Shared.downgrade` and `Weak.upgrade` call `get_or_register_type(… ensure_weak_type_def / ensure_option_type_registered …)` FIRST, while the protocol's own return-type closures fall back to `self_type` / `I64_TYPE` when those types are not yet registered; `Mutex.lock` calls `ctx.drops.register_local` for the fresh `Guard` (without it the pthread mutex is never released). Deleting the blocks without moving those effects into type registration turns a layering cleanup into a leak/deadlock class.
- **THE SHAPE OF THE FIX:** move the registration side effects to where the type is minted (`ensure_shared_type_def` / `ensure_weak_type_def` / `ensure_mutex_type_def` already exist and are the single writers for their metadata), and give `BuiltinMethodDecl` honest `returns_fresh` values for the refcount `clone`/`downgrade` arms so the generic path's existing consumer tags them. Then the three blocks delete, `Channel`'s precedent comment at `methods.rs` (*"handled by generic dispatch via BuiltinTypeProtocol"*) becomes true of the whole family, and `no_growth_in_name_prefix_routing`'s constant drops by the retired count in the same commit.
- **THE GUARD IS ALREADY EXACT:** that ratchet asserts EQUALITY in both directions as of R48 Track D2, so a retirement that forgets to lower the constant now FAILS rather than being silently absorbed.
