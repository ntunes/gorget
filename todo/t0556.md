- **[HIGH — SH lane, Core #10 lower-or-reject. A SILENT-TRUNCATION MISCOMPILE, not a missing feature.]** The self-host **silently swallows** the statements that FOLLOW a construct it does not implement, and emits a program that runs to exit 0 with the tail missing. Measured on the self-host lowerer driver: `print("a") / where: print("b") / print("c") / print("d")` prints **`a` `b` and stops** — the block body runs, `c` and `d` vanish. Rust gg rejects the same program with 10 parse errors, so the lanes disagree on whether the program exists. Lower-or-reject: the SH must `lower_fail` LOUDLY on a construct it does not implement, never emit silently-wrong code.
  - **THE MECHANISM IS A CLASS, and it is one line.** `self_host_typechecker/parser.gg` gates the named-scope path on `if self.check_tok(TOK_IDENT)`. A word that lexes as a KEYWORD is never `TOK_IDENT`, so if no parse rule claims it, control falls past the named-scope path into `parse_expr()`, which consumes the word, the colon, the indented body and the remainder of the block. **Any keyword in the lexer without a parse rule reopens this**, so the fix belongs at the parser's dispatch — an explicit reject for an unclaimed keyword in statement position — not in a per-keyword arm.
  - **THE SURVIVING COSTUME IS `where:`** — a keyword on BOTH lanes with **zero consumers outside the lexer** (`grep -rn "Keyword::Where" src/` → 2 hits, both `src/lexer/token.rs`), so no parse rule claims it. Repro: `known_gaps/sh_keyword_no_parse_rule_swallows_block_where.gg`, pinned `#[ignore]`d as `sh_keyword_no_parse_rule_swallows_block_where`.
  - **⚠ THE PIN MUST RUN ON THE SELF-HOST DRIVER (`sh_known_gap_expect`), NOT `check_gg_fails`.** The Rust lane already rejects `where:` with a parse error, so a `gg check` pin is **green on arrival and asserts nothing about this gap**. The committed pin uses the self-host lowerer driver — the same driver behind `self_host_runtime_diff` and `self_host_bootstrap_fixed_point`.
  - **THE `unsafe:` COSTUME IS GONE, AND THAT CLOSED THE INSTANCE, NOT THE CLASS.** D50 (2026-08-28) removed the `unsafe` keyword from the language, so `unsafe:` now lexes as an identifier and lands on the fully-implemented named-scope path. That retired one costume of this mechanism by deleting its keyword. The dispatch hole is untouched.
  - **`select` REMAINS a costume of the same shape** and `with Arena` diverges for separate allocator reasons; both documented in `known_gaps/cow_scope_bare_param_{select,with}.gg`.
