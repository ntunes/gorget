- **🆕🐛 [HIGH — a closure that CAPTURES a `Callable[T]` parameter cannot be compiled AT ALL, on either backend; found R48 Track A while fixing `t0770`'s reader 5]** `void go(Callable[String(String)] f): Callable[String()] g = (): f("hel")` fails at cc/llc.
  - **MECHANISM, read at HEAD.** A `Callable[T]` parameter's GIR local type is ERASED to unit. `ClosureLowering::lower_closure` (`src/ir/lowering/closures.rs`) builds each env-struct field type from the capture's own `type_id` (`ctx.pointee_type(cap.type_id).unwrap_or(cap.type_id)`), so the field for `f` is `unit`, and loading it emits `__v5 = *(void *)(__v4);` → `error: void value not ignored as it ought to be` on C, `void type only allowed for function results` from llc on LLVM.
  - **A SECOND FAULT ONE LINE DOWN.** The indirect call inside the closure body is cast `((int64_t(*)(void*, void*))…)` even for a `String`-returning callable: inside the lifted closure, `f` is an env FIELD, not the outer local the `callable_return_types` / `callable_param_types` sidecars are keyed on, and those sidecars are cleared per function. Both faults must be closed for the shape to work.
  - **⚠ DISCRIMINATE FROM `t0770` (fixed this round).** That class is the READERS of an erased callable's declared return type, and its reader 5 — `infer_closure_return_type` in `closures.rs` — IS fixed and DOES fire on this program (verified by instrumenting the arm: one FIRE per program, returning the `GorgetString` tid). It is not sufficient: the closure's registered return type is re-pinned from the emitted body (`closures.rs`, the `actual_ret != func.return_type` re-pin), and the body cannot be emitted at all while the env field is `void`. So reader 5 is correct and stays; this is a CAPTURE-TYPING + sidecar-propagation gap at the closure boundary.
  - **DISCRIMINATE FROM THE FAMILY:** `t0526` is the closure-env `TypeDef` built with no drop strategy — that is about the env's DROP, this about a field's TYPE. `t0026` is capture of a collection-element borrow returning the address — that capture has a real type and compiles. `t0530` is a struct capture not persisting across invocations — also compiles.
  - **⚠ THE DESIGN QUESTION THE FIX OWES AN ANSWER TO.** A callable value is a fat pointer (code pointer + environment pointer). Capturing one BY VALUE copies the pair, which ALIASES the captured environment — so the fix must say whether a captured `Callable` is a borrow of the outer callable (lifetime tied to it, per the CoW-default-borrow rule) or an owned copy (which would need the single-owner `^`/`.clone()` treatment `Callable` already gets at init boundaries). That is why this is filed rather than patched inside another track.
  - **NEGATIVE CONTROL:** the identical program with a TOP-LEVEL FUNCTION in place of the captured parameter builds and prints `hello!` on both backends.
  - **INTENDED:** prints `hello!`, rc 0, on C and LLVM. Repro `tests/fixtures/known_gaps/closure_captures_callable_param_void_env_field.gg`, wired `#[ignore]`d as `known_gap_closure_captures_callable_param_void_env_field`.
