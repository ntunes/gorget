- **🆕 CI/TOOLING FOLLOW-UPS (filed 2026-06-30, from the `test_result_advanced` CI-red fix — see DONE):**
  - **🔧 macOS dev machine CANNOT run the self-host runtime net / bootstrap locally without a `cc` shim — this is WHY the `Result.map` drop-corruption shipped (4 days red on CI, invisible locally).** The self-host's emitted C contains constructs that Linux/gcc accepts as WARNINGS but Apple clang (the dev toolchain) rejects as ERRORS, so `self_host_runtime` + `self_host_bootstrap_fixed_point` CC-FAIL on ~925/~36/8 fixtures locally for reasons UNRELATED to any given change → the dev never sees real runtime regressions; CI (Linux/gcc) is the only place these fixtures execute. **Workaround proven this round:** a PATH-shimmed `cc` wrapping `/usr/bin/cc -Wno-int-conversion -Wno-implicit-function-declaration -Wno-incompatible-pointer-types -Wno-return-mismatch -Wno-return-type` makes the net regress down to 8 genuinely-platform-specific fixtures (the `send`/`clone_inplace`/`RxNode` macOS-header/fwd-decl clashes + `meta_platform_guard` OS-detection). **Fix options (own decision):** (a) make the test harness append these `-Wno-*` flags to its `cc` invocations on macOS (`tests/integration.rs` `self_host_emit_cc_run` :18426 + `self_host_bootstrap_fixed_point` :18633) so local validation is faithful; OR (b) document the shim in CLAUDE.md Build&Test as the macOS prerequisite for self-host gates. Without one of these, every self-host codegen change is un-validatable on the dev box and ships blind to CI.
  - **🐛 CLEAN UP the gcc-tolerated-but-clang-rejected self-host EMIT classes (latent UB, benign on the gcc/x86_64 production target but real codegen sloppiness).** Surfaced as the ~36 CC-FAIL classes when the net runs under strict clang: (i) **int↔pointer untyped-local stores** — the self-host emits `void* local = (int32_t)0` for some unresolved-type locals (dead stores in `test_result_advanced`, but the class is real: a local whose type the lowerer couldn't resolve defaults to `void*` + an int-0 init); (ii) **non-void functions that fall off the end without a `return`** (`-Wreturn-mismatch`: `Column__col_len`, `IoError__display`, `MapIter__…__next`, `Color__eq`, etc. — the self-host emits a non-void signature but no terminal return on some path); (iii) **conflicting forward-decl vs definition types** (`X__clone_inplace`, `RxNode`) and the **`send` libc-symbol collision** (the self-host emits a function named `send`, clashing with macOS `<sys/socket.h>`; rename-mangle runtime-colliding symbols). All round-trip harmlessly on 64-bit gcc but are principled bugs; (i) is also the reason the `map` crash was a SEGFAULT rather than a clean error on x86_64. Own scout per class; lower priority than parity work but they erode the "reference-grade emit" bar.
