- **🆕🚨 [HIGH — Layering rule 2 class retirement: NAME MATCHING DECIDES TYPE SEMANTICS, and the typed replacement already exists in-tree] Retire literal-name type decisions in `typecheck.rs`.** Semantic questions are answered by comparing `self.scopes.get_def(def_id).name` against string literals. Because the answer is keyed on a *name* rather than a `DefId`, **an import — which changes what the name resolves to — changes the semantics**. That is the mechanism behind `todo/t0710` (an import flips `Box[Concrete]` → `Box[Trait]` from ACCEPT to `E_TypeMismatch`), ratified as **D51**.
  - **CENSUS (verified at `ddc21aaa`).** `src/semantic/typecheck.rs` makes literal-name decisions for at least: `Result`, `String`, `Box`, `Task`, `Future`, `Mutex`, `Shared`, `RWLock`, `ReadGuard`, `AtomicInt`, `AtomicBool`. The shared-wrapper coercion arms are at `:1292-1327`; a **second, structurally identical name match for the atomics sits immediately below them**, which is the tell that this is a class and not a site. Re-run the census:
    ```

    grep -rn 'name == "' src/semantic/typecheck.rs
    ```
    (Hits in `src/semantic/safety/tests.rs` are test data — variable names like `"x"` — not decisions. Do not count them.)
  - **THE TYPED MECHANISM ALREADY EXISTS; THIS IS AN UNMIGRATED SIBLING SET (Core #4), NOT A MISSING FEATURE.** `DefInfo.deref_wrapper_kind: Option<DerefWrapperKind>` (`src/semantic/scope.rs`) is seeded ONCE at registration by `DerefWrapperKind::for_builtin_name`, documented there as *"The ONE allowed registration-time name-match"* — the sanctioned exception, where the name genuinely is the contract. It already classifies `Box` → `DerefTarget`, `Shared`/`Weak`/`Mutex`/`RWLock` → `NonDerefContainer`, `Guard`/`ReadGuard`/`WriteGuard` → `GuardAccept`. The RV-A fix retired this class **for field access** and left the coercion path comparing strings.
  - **The prior fix's own doc comment describes this bug as the thing it fixed:** *"a USER struct that shadows the name gets a distinct DefId with `None`, so it no longer escapes `E_NoFieldFound` (the garbage-0 miscompile)"*. Resolution-dependent behaviour — fixed on the field-access axis, still live on the coercion axis.
  - ⚠ **DO NOT SIMPLY REUSE `DerefWrapperKind` FOR COERCION.** It answers *field-access disposition*. Coercion is a different axis, and overloading one flag across two axes swaps a Layering rule 2 violation for a rule 3 one (**one source of truth per AXIS**). Reference-grade shape: one registration producing a builtin-wrapper **identity**, with separate per-axis accessors — `unify` asks "transparent for coercion?", the field path asks its own question, both reading the same seeded fact.
  - **THE GUARD IS THE DELIVERABLE, NOT JUST THE FIX (Core #6).** A `tests/lints.rs` ratchet that counts literal-name comparisons on resolved definitions in `src/semantic/`, allowlisting **only** the registration-time seeding site, so site N+1 cannot reappear. Env-gate → burn down → fatal. ⚠ The guard must be able to catch its OWN class (Core #15e Q2): counting sites that *already* use the typed accessor would green-light a new name match — it must count the **name comparisons**, and the count must go DOWN, never up.
  - **RELATIONSHIP TO OTHER ITEMS.** `t0710`/D51 force the `Box` wrapper half (an import must never change whether a program typechecks) — that is the first slice. `t0717` is the same rule-2 disease in the CoW materialize gate (`is_mutating_method_name`, `src/ir/lowering/functions.rs:999`) and stays separate: different subsystem, different fix, same invariant.   - **NO SEPARATE REPRO NEEDED** — `t0710` carries the durable RED-verified reproducer (`known_gap_box_trait_import_flips_accept_reject`) for the Box slice; the remaining cells need their own once the fix shape is chosen.
