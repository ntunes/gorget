- **🆕🚨 [HIGH — A RATCHET THAT CANNOT SEE ITS OWN CLASS. Found 2026-09-06 by R51 Track F's brief-review pass 1.]**

  `auto_clone_if_ptr` is one of six chokepoints RATCHET C (`tests/lints.rs`) names, and that ratchet documents this exact shape as the bug class it exists to retire:

  > *"a lowering arm that ... emits the clone ITSELF instead of delegating the decision to a chokepoint ... the return-borrow double-free family existed because `return` had its OWN hand-rolled `GirType::Ptr`-only clone."*

  **Measured: the guard is inlined at 1 of 4 callers** (regenerate: `grep -rn 'ctx.auto_clone_if_ptr(' src/`), and **no arm-count lint** forces the next one through the shared path — while the repo already has that idiom twice (`container_literal_arms_count`, `compound_assign_root_materialize_arms_count`).

  ⛔⛔ **AND THE RATCHET IS BLIND TO IT BY CONSTRUCTION — SIX-Q #2.** Its predicate counts `emit_clone(` / `call_clone(` occurrences. A clone-**suppression** adds neither, so an inlined suppression at a non-chokepoint site scores **zero** and the ratchet stays green. *A guard that green-lights the class it was written to retire is worse than none.*

  ⚠ **HISTORY SAYS THIS RECURS.** `5d9a644a9` (2026-06-15) hit the same root cause and fixed it at the ABI consumer — *"the live ExternBlock site + 2 defensive siblings"*. Those three `is_borrow_named` blocks are still in the tree; patching inline adds a fourth and a fifth.

  **INTENDED:** the decision is threaded INTO `auto_clone_if_ptr` so all four callers inherit it (Core #1: fix at the write site); an arm-count lint pins the caller set; and RATCHET C's predicate is widened to see suppressions, or a companion instrument is added that can — Core #6, a guard needs BOTH directions.
